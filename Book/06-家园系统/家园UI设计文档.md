# 家园UI设计文档

**创建时间**：2026-04-10  
**最后更新**：2026-04-13  
**状态**：开发中  
**关联任务**：M0.2-W3 #17  
**涉及包**：`cn.etetet.statesync`、`cn.etetet.home`、`cn.etetet.map`

## 文档目标

本文档负责定义家园系统正式版 demo 的 UI 信息架构、页面职责、交互流程和 YIUI 资源边界。

本文不再以“工坊页/合同页/恢复页/出击页”作为当前正式版 demo 的页面主结构，而是改为“场景建筑 + 建筑详情页”的建筑驱动结构。

`Home` 场景本身默认只提供家园地块和槽位锚点，主城、建筑和展示物都按家园数据动态加载。

系统规则与建筑功能定义见 [家园系统需求文档.md](家园系统需求文档.md)。

## 设计原则

### 1. 场景建筑是入口，页面是承接层

1. 玩家先在场景里看见建筑和空地。
2. 点击建筑或槽位后，UI 再承接详情和管理动作。
3. 不允许把建筑先做成纯 UI 标签页，再反过来给场景找存在感。

### 2. 一个页面只负责一个明确建筑或一个明确管理动作

1. `主城详情` 单独一页。
2. `主城任务` 单独一页。
3. `大红收藏馆`、`物品回收间`、`农场`、`仓库` 各自有独立详情页。
4. `建造选择` 单独一页，不把建造选择塞进首页角落。

### 3. 当前工程的场景交互不复活旧直点单位链路

1. 当前工程里旧 `click-unit` 直点链路已废弃。
2. 家园正式版不复活旧单位点击方案。
3. 家园正式版默认使用轻量场景建筑交互层，以 `BuildingId/SlotId` 打开对应 UI。
4. `ECA` 只作为未来特定场景点位能力的可选复用，不是家园默认交互框架。

### 4. 场景内容按数据加载

1. `Home` 场景默认只有地块/底座，不预摆固定家园内容。
2. 主城、已建建筑、收藏展示物都根据玩家家园数据动态加载。
3. 没有数据的槽位保持空地状态。

### 5. 仓库优先

1. 当前这轮 UI 设计里，`仓库页` 需要写得最细。
2. 仓库首版先做“存储闭环”，不做复杂背包拖拽整理。
3. 页面结构必须支持后续再扩跨容器流转，而不是现在就把页面做死。

### 6. 首页只做总控，不吞掉所有详情

1. 首页负责总览、待办和快捷入口。
2. 首页不承担每个建筑的完整操作细节。
3. 详细操作全部落在建筑详情页。

## UI 总体结构

正式版家园 UI 建议采用以下结构：

1. `HomePanel`：家园主 Panel。
2. `HomeMainView`：基地首页总览。
3. `HomeBuildingDetailPanel`：通用建筑详情页壳。
4. `HomeMainCityTaskPanel`：主城任务页。
5. `HomeBuildSelectPanel`：空槽位建造选择页。
6. `HomeMuseumPanel`：大红收藏馆详情页。
7. `HomeRecyclePanel`：物品回收间详情页。
8. `HomeFarmPanel`：农场详情页。
9. `HomeWarehousePanel`：仓库详情页。

### 当前实现基线（2026-04-13）

本轮代码已经把正式版主链路从旧 `LobbyPanel.BuildPanel` 切到独立 `HomePanel`：

1. `HomePanel` 已作为独立 YIUI Panel 接入，不再继续沿 `BuildPanel` 扩正式家园主流程。
2. `HomeBuildingDetailCard` 已作为正式详情卡 prefab 生成并接入 `HomePanel`。
3. `HomePanel` 当前采用“顶部状态条 + 左侧导航/槽位列表 + 中间场景操作区 + 右侧正式页浮层”的结构。
4. 右侧正式页当前已落地 `总览/建造`、`主城任务`、`收藏馆网格页`、`独立回收间页`、`农场页`、`Home 专属仓库页`。
5. `LobbyPanel` 在 `Home` 场景内的 `Build` 入口已改为打开独立 `HomePanel`，旧 `BuildPanel` 只保留历史样机意义，不再是正式主链路。
6. `HomeSceneRuntimeComponent` 当前会把场景点击直接同步到 `HomePanel` 选中态，并在进入/离开 `Home` 场景时自动开关 `HomePanel`。
7. `HomePanel.Background` 当前必须保持低透明且 `raycastTarget = false`，禁止再用整屏深色底板遮住场景点击。

## 信息架构

### 顶层结构

`HomePanel` 顶层建议固定为以下五个区域：

1. 顶部全局状态条。
2. 左侧导航与槽位摘要区。
3. 中间场景交互承接区。
4. 当前建筑详情浮层。
5. 全局提示与确认弹窗层。

### 场景点击可达性约束

1. 中间场景区必须始终保留一块连续可见、可点击的 3D 操作窗口。
2. 左侧导航和右侧详情都只能占各自固定边栏，不能再吃满中间区域。
3. 顶部状态条只允许占顶部一条安全高度，不能向下压到主场景点击区。
4. 任何全屏 `Image` 背板都必须默认 `raycastTarget = false`，否则会直接拦截 `HomeSceneRuntimeComponent` 的场景点击。
5. 顶部文案必须明确提示“点击中间场景中的主城、建筑或空地”，避免把玩家引导到不可点的 UI 区域。

### 顶部全局状态条

建议展示：

1. 家园标题或主城名。
2. 当前金币。
3. 主城等级。
4. 仓库占用概览。
5. 当前待办提示数量。

`HomeTopNoticeBar` 的职责就是承接这一层顶部状态条资源，并在家园快照变化后统一刷新金币、主城等级、仓库占用和待办提醒，不承接具体建筑详情操作。

### 首页快捷入口

首页中保留以下快捷入口，但这些入口都应回到“建筑驱动”语义：

1. 主城任务。
2. 去主城。
3. 去仓库。
4. 去回收间。
5. 去农场。
6. 去收藏馆。

说明：

1. 这里的“去某建筑”不是替代场景点击。
2. 它只是作为首页快捷跳转，最终仍然要打开对应建筑详情页。

## 场景交互设计

### 场景元素

场景里至少存在以下可视元素：

1. 默认存在的家园地块或底座。
2. 若干固定位置的槽位锚点。
3. 根据家园数据加载出的 `主城`、`大红收藏馆`、`物品回收间`、`农场`、`仓库` 模型。
4. 已锁定槽位的占位表现。

### 交互方式

1. 场景加载完成后，先根据家园数据生成主城和其他已建内容。
2. 点击主城，打开主城详情。
3. 点击空地槽位，打开建造选择页。
4. 点击已建建筑，打开对应建筑详情页。
5. 点击关闭或空白区，收起当前详情层但不打断场景身份。

### 选中反馈

1. 当前选中建筑需要有明显描边、光圈或浮牌提示。
2. 未解锁槽位需要表现为锁定态。
3. 可建空槽位需要有清晰的“+ 建造”语义。

## 首页设计

### 页面定位

首页是“基地总控台”，负责让玩家在 3 秒内知道：

1. 当前主城几级。
2. 哪些建筑有待处理事项。
3. 仓库是否快满。
4. 现在最值得点哪一个建筑。

### 页面结构

首页建议由六个区块组成：

1. 头部总览区。
2. 主城进度区。
3. 待处理事项区。
4. 建筑速览区。
5. 仓库快照区。
6. 快捷操作区。

### 头部总览区

展示内容：

1. 页面标题：家园 / 基地。
2. 副标题：当前主城等级和基地状态说明。
3. 当前金币。
4. 当前已解锁槽位数和已建建筑数。

### 主城进度区

展示内容：

1. 当前主城等级。
2. 当前主城任务组完成度。
3. 下一主城等级将解锁的槽位或建筑等级提示。
4. 主 CTA：查看主城任务。

### 待处理事项区

待办卡片建议收束为：

1. 农场可收取金币。
2. 回收间有已完成待收取结果。
3. 仓库空间紧张。
4. 收藏馆有可摆放的大红单位。
5. 主城任务可提交或主城可升级。

### 建筑速览区

展示内容：

1. 已建建筑摘要卡片。
2. 空槽位数量。
3. 点击卡片后，联动场景选中并打开详情页。

### 仓库快照区

这是首页必须单独强调的区块，展示：

1. 当前总格子数。
2. 当前已占用格子数。
3. 仓库是否已满或即将满。
4. 最近一次入库来源摘要，例如“回收间产物已入库”。

### 快捷操作区

建议只保留两个高优先级 CTA：

1. 查看主城任务。
2. 打开仓库。

## 主城详情页设计

### 页面职责

1. 展示主城等级、升级条件和解锁效果。
2. 承接跳转到主城任务页。
3. 承接主城升级动作。

### 页面分区

1. 顶部主城信息区。
2. 当前等级效果区。
3. 下一等级解锁预览区。
4. 升级条件区。
5. 底部操作区。

### 关键状态

1. 任务未完成。
2. 任务已完成但金币不足。
3. 可升级。
4. 已达当前 demo 最高等级。

## 主城任务页设计

### 页面职责

1. 展示当前主城等级对应的任务组。
2. 清楚表达“升级主城还差什么”。
3. 在任务完成后给出返回主城升级的明确引导。

### 页面分区

1. 顶部任务组标题与当前主城等级。
2. 任务列表区。
3. 任务进度摘要区。
4. 底部返回主城按钮。

### 任务状态

1. 未开始。
2. 进行中。
3. 已完成未提交。
4. 已完成可升级主城。

## 建造选择页设计

### 页面职责

1. 当玩家点击空槽位时，展示当前可建建筑列表。
2. 告知玩家每个建筑的作用、当前数量、数量上限和金币消耗。

### 页面分区

1. 当前槽位信息区。
2. 可建建筑卡片列表。
3. 被锁建筑说明区。
4. 底部确认建造区。

### 关键状态

1. 可建。
2. 数量上限已满。
3. 主城等级不足。
4. 金币不足。

## 大红收藏馆页设计

### 页面职责

1. 管理大红展示单位的摆放和取下。
2. 让玩家清楚看到展示容量和每个独立展示位。

### 页面分区

1. 当前容量区：已摆放数 / 当前容量上限。
2. 展示位网格区。
3. 可摆放单位列表区。
4. 当前选中单位详情区。

### 关键交互

1. 点击空展示位，选择一个可摆放单位。
2. 点击已摆放单位，执行取下。
3. 取下后立即释放展示位。

### 关键状态

1. 展示位为空。
2. 展示位已占用。
3. 没有可摆放单位。
4. 容量已满。

## 物品回收间页设计

### 页面职责

1. 管理回收队列。
2. 承接放入、等待和收取进仓库的动作。

### 页面分区

1. 建筑等级与处理位数量区。
2. 回收槽位列表区。
3. 可放入物品列表区。
4. 结果收取区。

### 关键交互

1. 选中空处理位，放入任意待回收物品。
2. 查看处理中物品的剩余时间。
3. 处理完成后点击收取，结果进入仓库。

### 关键状态

1. 空槽位。
2. 处理中。
3. 已完成待收取。
4. 仓库容量不足无法收取。

## 农场详情页设计

### 页面职责

1. 展示当前农场等级和金币产出节奏。
2. 承接金币收取动作。

### 页面分区

1. 建筑信息区。
2. 当前待收金币区。
3. 收取倒计时或下一次产出说明区。
4. 底部收取按钮区。

### 关键状态

1. 产出中。
2. 可收取。
3. 已达暂存上限。

## 仓库页设计

### 页面职责

1. 作为当前正式版 demo 的优先页面。
2. 清楚表达仓库容量、占用和当前库存。
3. 承接家园内物品的“查看”和“结果确认”，而不是首版就做复杂整理器。
4. 当前已在 `HomePanel` 内落 Home 专属仓库页，不再直接依赖 `EquipPanel / Warehouse` 作为正式目标结构。

### 当前范围

1. 首版先做家园存储闭环。
2. 先不做复杂跨容器拖拽。
3. 先不做大型整理算法或高级筛选器。
4. 先把“容量可见、库存可见、来源可见、满仓可感知”做好。

### 页面分区

1. 顶部容量摘要区。
2. 分类筛选区。
3. 仓库格子区。
4. 当前物品详情区。
5. 来源说明区。

### 顶部容量摘要区

必须展示：

1. 当前仓库等级。
2. 总格子数。
3. 已占用格子数。
4. 剩余格子数。

### 分类筛选区

首版建议保留轻量分类：

1. 全部。
2. 回收产物。
3. 收藏相关。
4. 其他家园物品。

### 仓库格子区

1. 使用规则网格表达“总格子数”。
2. 空格子和占用格子必须一眼可辨。
3. 支持点击物品格查看详情。

### 当前物品详情区

展示内容：

1. 物品图标和名称。
2. 来源说明。
3. 当前数量或占用说明。
4. 当前首版仅展示，不强制提供复杂转出操作。

### 来源说明区

必须清楚告诉玩家：

1. 该物品是否来自回收间。
2. 它为什么进入了仓库。
3. 仓库已满时，为什么新的收取动作会被阻塞。

### 关键状态

1. 有空位。
2. 快满。
3. 已满。
4. 无物品空态。
5. 新产物待入库但容量不足。

## 全局交互流

### 流程1：进入 Home

1. 玩家进入 `Home`。
2. 打开 `HomePanel` 并进入首页。
3. 场景先呈现默认家园地块与槽位锚点。
4. 客户端根据家园数据加载主城、已建建筑和展示物。
5. 首页显示主城进度、仓库概览和待办卡片。

### 流程2：点击空槽位建仓库

1. 玩家点击已解锁空槽位。
2. 打开 `HomeBuildSelectPanel`。
3. 选择 `仓库` 并确认。
4. 场景生成仓库建筑并自动选中。
5. 打开仓库详情页查看当前容量。

### 流程3：回收间产物入仓

1. 玩家在回收间放入物品。
2. 等待处理完成。
3. 点击收取。
4. 若仓库容量足够，则结果进入仓库并刷新首页仓库快照。
5. 若仓库容量不足，则停留在回收间页并给出明确阻塞提示。

### 流程4：农场收金币

1. 首页或农场详情提示“可收取”。
2. 玩家点击农场。
3. 打开农场详情页并收取金币。
4. 顶部金币数即时刷新。

### 流程5：主城升级

1. 玩家点击主城。
2. 在主城详情页查看任务完成度。
3. 跳转主城任务页确认全部完成。
4. 返回主城详情页点击升级。
5. 主城等级、槽位解锁和建筑等级上限即时刷新。

### 流程6：收藏馆摆放大红

1. 玩家点击收藏馆。
2. 打开收藏馆详情页。
3. 在空展示位中选择一个大红单位摆放。
4. 或点击已摆放单位执行取下。

## 页面状态与红点

全局红点来源建议收束为：

1. 主城任务已全部完成，可升级主城。
2. 农场可收取金币。
3. 回收间有已完成待收取结果。
4. 仓库已满或接近满仓。
5. 收藏馆有可摆放单位。
6. 有已解锁但未建造的空槽位。

页面至少要支持：

1. 正常态。
2. 空态。
3. 锁定态。
4. 加载态。
5. 错误态。
6. 容量不足阻塞态。

2. 场景点击后的详情壳也要在资源层明确存在，不用运行时代码拼整个页面。
3. 运行时只负责数据赋值、显隐、事件绑定和不定长列表实例化。
4. `HomePanel` 运行时禁止“快照一变就把所有正式页一起重建”；正式页只允许刷新当前可见页，农场/回收类时间推进也必须按秒节流，不能再做按帧全页重建。

## 文案与视觉要求

1. 全站家园文案保留中文口径。
2. 正式版统一使用可正常显示中文的 TMP 字体资产。
3. 家园整体视觉强调“基地、建造、收纳、经营”，不走大厅娱乐化语义。
4. 仓库页要有明显的“容量压力”和“管理感”，不能做成普通背包页换皮。

## UI 验收标准

- [ ] 玩家进入家园后能一眼分辨这是“有主城、有空地、有建筑”的基地场景。
- [ ] 点击主城、空槽位、已建建筑都能进入正确 UI，而不是只留在首页。
- [ ] 首页能把主城进度、仓库状态和待处理事项讲清楚。
- [ ] `主城详情`、`主城任务`、`收藏馆`、`回收间`、`农场`、`仓库` 都有独立页面承接。
- [ ] `仓库页` 能明确表达总格子、已占用、剩余空间和满仓阻塞。
- [ ] 页面空态、锁定态和错误态不丢失建筑身份。
- [ ] UI 结构支持后续继续加建筑，而不是回到抽象模块标签页。
- [ ] `HomePanel` 与场景点选、进入/离开 `Home` 场景、`Lobby Build` 入口已形成独立正式链路。
