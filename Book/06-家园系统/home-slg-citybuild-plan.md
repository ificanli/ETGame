# Home 搜打撤基地建设系统需求与开发计划

## 1. 文档目标

本文档用于对齐 `Home` 场景下的基地建设系统一期目标、系统边界、包设计、数据模型、建筑功能、开发阶段与验收标准。

本系统不是独立 SLG，而是服务于搜打撤主循环的局外基地系统。基地的价值在于承接“局内带出 -> 局外处理 -> 下局准备”。

---

## 2. 当前项目基础

结合当前仓库代码，`Home` 已具备以下基础能力：

1. `Home` 已按玩家私有副本进入。
2. `Home` 副本 `mapId` 已绑定为 `player.Id`。
3. `MapManager` 已支持按指定副本 Id 创建 `Home` 副本。
4. 已存在自动化测试验证 `Home` 私有隔离与 `mapId == player.Id`。
5. 客户端切入 `Home` 时已有专门分支，不走常规战斗地图展示逻辑。

当前关键代码位置：

1. `Packages/cn.etetet.map/Scripts/Hotfix/Server/C2G_EnterMapHandler.cs`
2. `Packages/cn.etetet.mapmanager/Scripts/Hotfix/Server/MapManagerComponentSystem.cs`
3. `Packages/cn.etetet.test/Scripts/Hotfix/Test/Test_Home_MapIdEqualsPlayerId_Test.cs`
4. `Packages/cn.etetet.test/Scripts/Hotfix/Test/Test_Home_TwoPlayers_Isolated_Test.cs`
5. `Packages/cn.etetet.map/Scripts/Hotfix/Client/SceneChangeHelper.cs`

结论：

`Home` 的“玩家私有场景”基础已经具备，基地系统应直接建立在这一基础上，不需要重复改造私有副本方案。

## 3. 一期产品目标

一期目标聚焦在“单人 Home 基地闭环”，服务搜打撤主循环，不追求完整 SLG 大世界玩法。

一期建议范围：

1. 玩家进入 `Home` 后加载自己的建筑数据。
2. 建筑直接做在 `Home` 场景内，不做纯 UI 城建。
3. 支持点击场景槽位创建建筑。
4. 支持点击场景中的建筑，选择升级或拆除。
5. 支持基地生产，鼓励玩家每天上线收菜。
6. 支持“局内带出资源 -> 基地加工 -> 下局准备”的外围循环。
7. 支持离线后重登恢复。
8. 所有核心状态由服务端权威维护。

一期明确不做：

1. 好友拜访。
2. 联盟协作。
3. 掠夺与防守战斗。
4. 多建造队列。
5. 复杂付费加速链路。
6. 跨玩家 Home 交互。
7. 医疗收容站（推迟至二期）。

一期核心定位补充：

1. 基地是搜打撤的外围养成，不是独立资源经营游戏。
2. 建筑效果优先服务局前准备、局后恢复、物资处理、情报获取和长期解锁。
3. 基地允许存在每日可收的被动产出，但不能替代局内搜集和撤离带出。

一期交互形态补充：

1. 玩家登录后直接进入 `Home` 场景。
2. `LobbyPanel` 包含多个子页签，其中”基地”页签可直接与 Home 场景交互。
3. 基地页签下，场景中的建筑槽位可点击，已有建筑可点击。
4. 其他页签下场景不可交互（被 UI 遮挡）。

## 4. 核心设计原则

### 4.1 架构原则

遵循 `et-arch` 要求：

1. Entity 只存数据，不写业务逻辑。
2. 业务逻辑放在 System/Helper。
3. 不在 `map` 包中堆积基地业务。
4. 进入 `Home` 的链路仍由 `map` 负责，基地玩法由独立包承接。

### 4.2 权威原则

1. 客户端只发送建造、升级、收取、生产意图，不发送最终结果。
2. 服务端校验资源、槽位、前置条件、升级条件和生产条件。
3. 服务端写入成功后，再同步给客户端。
4. 异常或不同步时，以服务端状态为准。

### 4.3 主循环结合原则

1. 基地产出必须服务下一局，而不是脱离单局体验自循环。
2. 高价值产物应主要依赖局内带出材料加工，而不是纯挂机生成。
3. 建筑效果优先做准备能力、恢复能力、信息能力、制作能力。
4. 应避免大量直接提升局内硬数值的建筑效果。

### 4.4 表现原则

1. 建筑是 `Home` 场景内对象，不是列表式 UI 格子。
2. UI 只负责模式切换、弹窗确认、状态展示和操作按钮承载。
3. 槽位点击、建筑点击、选中态、高亮态由场景交互层负责。

### 4.5 生产原则

1. 基地生产分为“被动产出”和“加工产出”两类。
2. 被动产出用于拉起每日上线动机，但价值不能过高。
3. 加工产出需要消耗局内带出的材料，体现搜打撤回收价值。
4. 收菜上限应受建筑等级和仓储上限约束。

## 5. 包设计建议

建议新增高层玩法包：`cn.etetet.home`

包层级：第5层（与 `map`、`login` 同层），设置 `AllowSameLevelAccess: true`。

依赖关系：依赖 `unit`（第2层）、`item`（第3层）。

原因：

1. `map` 包应聚焦地图切换、副本、场景管理。
2. `home` 属于具体玩法系统，不应长期耦合在 `map`。
3. 后续基地若接任务、数值、背包、活动，独立包更容易维护依赖关系。
4. `home` 放第5层，`map` 可通过 `AllowSameLevelAccess` 在进入时调用 `home` 的 Helper。

建议包内结构：

### 5.1 Model

路径建议：

`Packages/cn.etetet.home/Scripts/Model/`

职责：

1. 基地持久化组件定义。
2. 建筑 Entity 与组件定义。
3. 解锁状态、生产状态。

### 5.2 Hotfix

路径建议：

`Packages/cn.etetet.home/Scripts/Hotfix/`

职责：

1. 基地进入加载逻辑。
2. 建造/升级/拆除/收取的服务端校验。
3. 生产订单与被动产出处理。
4. 协议处理与同步。
5. 离线收益结算与存档保存。

### 5.3 HotfixView

路径建议：

`Packages/cn.etetet.home/Scripts/HotfixView/`

职责：

1. Home 基地页签交互。
2. 槽位点击、建筑点击、选中高亮和操作菜单。
3. 建筑状态展示、生产进度、红点和操作反馈。

### 5.4 Proto

路径建议：

`Packages/cn.etetet.home/Proto/`

职责：

1. 基地相关消息定义。
2. 客户端意图消息与服务端回推消息。

## 6. 数据模型设计

### 6.1 组件拆分原则

为符合 ET ECS “小而聚焦”的组件设计原则，基地数据按职责拆分为多个独立持久化组件，避免单一组件过于臃肿导致任何字段变更触发整体序列化。

基地资源不另建独立存储，直接复用现有 `cn.etetet.item`（道具背包系统），避免两套资源管理并存。

### 6.2 PlayerHomeComponent

挂载位置：挂在 `Player` 下。

职责：基地元信息。

建议字段：

1. `long HomeVersion` — 用于后续数据迁移与兼容。
2. `long LastSettleTime` — 用于离线收益结算（登录即结算，不依赖进入 Home）。
3. `HashSet<int> UnlockedBuildingConfigIds` — 保存解锁状态，避免硬编码。

### 6.3 建筑采用 Child Entity 方案

建筑采用 ET “一切皆 Entity”的设计理念，每个建筑实例作为 `Player` 的子 Entity 存在，而非存储在 Dictionary 中的数据结构。

#### HomeBuildingComponent

挂载位置：挂在建筑子 Entity 上。

建议字段：

1. `int ConfigId` — 对应建筑配置。
2. `int Level` — 当前等级。
3. `int State` — 空闲、待收取等状态（一期无建造中/升级中状态，因为建造和升级即时完成）。
4. `int SlotId` — 固定槽位 Id（一期采用固定槽位方案，避免服务端做复杂空间校验）。
5. `long LastCollectTime` — 上次收取时间。
6. `long LastProductionTime` — 上次被动产出结算时间，用于离线结算。

说明：

1. 建筑 Entity 的 `Id` 即为建筑实例 Id，无需额外 `BuildingId` 字段。
2. 一期建造和升级均为即时完成，无需 `BuildStartTime`/`BuildFinishTime`。
3. 固定槽位方案下，`SlotId` 对应 `HomeSlotConfig` 中的槽位定义，无需坐标字段。

### 6.4 HomeProductionComponent

挂载位置：挂在 `Player` 下。

职责：管理加工订单。

建议字段：

1. `Dictionary<long, HomeProductionOrderData> ProductionOrders` — 加工队列。

#### HomeProductionOrderData

建议字段：

1. `long OrderId`
2. `long BuildingEntityId` — 关联的建筑 Entity Id。
3. `int RecipeId` — 对应 HomeProductionConfig 中的配方 Id。
4. `int State` — 进行中、已完成、已收取。
5. `long StartTime`
6. `long FinishTime`

说明：

1. 消耗和产出从 `RecipeId` 对应的配置表实时读取，不在订单中冗余存储，避免配置热更后数据不一致。
2. 一期使用单生产队列。

### 6.5 HomeContractComponent

挂载位置：挂在 `Player` 下。

职责：管理情报站悬赏合同。

建议字段：

1. `long LastRefreshTime` — 上次合同刷新时间。
2. `List<HomeContractData> AvailableContracts` — 当前可接取的合同列表。
3. `List<HomeContractData> ActiveContracts` — 已接取的进行中合同。

#### HomeContractData

建议字段：

1. `long ContractId`
2. `int ConfigId` — 对应 HomeContractConfig 中的合同配置。
3. `int State` — 可接取、进行中、已完成、已领取、已过期。
4. `long AcceptTime` — 接取时间。
5. `long ExpireTime` — 过期时间。
6. `int Progress` — 当前进度（如需要收集3个物品，当前已收集2个）。
7. `int Target` — 目标数量。

说明：

1. 合同每日由服务端根据情报站等级刷新，等级越高可选合同数量和品质越高。
2. 合同目标在局内撤离成功后由服务端自动判定并结算。
3. 死亡未撤离则进行中合同进度不变，合同不会因死亡失败（但也不会推进）。

### 6.6 运行时数据

运行时态独立为非持久化组件：

1. `HomeSelectionComponent` — 当前选中的槽位或建筑（客户端）。

职责：

1. 当前选中的槽位或建筑。
2. 不直接替代持久化数据。

用途：

4. `TargetId` — 目标配置 Id（物品 Id、区域 Id、目标类型 Id 等）。
5. `TargetCount` — 需要完成的数量。
6. `RewardItemIds` — 奖励物品 Id 列表。
7. `RewardItemCounts` — 奖励数量列表。
8. `RequireIntelLevel` — 需要的情报站最低等级。
9. `Duration` — 合同有效时长（秒）。
10. `Weight` — 刷新权重，用于服务端每日随机选取合同。

说明：

服务端每日根据情报站等级和权重随机选取合同。高等级情报站可刷出更高品质的合同，合同数量也随等级增加。

### 7.6 HomeWeaponModConfig

用途：

定义工坊武器改装配方。

建议字段：

1. `Id`
2. `ModType` — 改装类型（瞄准镜、消音器、握把、弹匣等）。
3. `WeaponType` — 适用武器类型。
4. `InputItemIds` — 消耗材料 Id 列表。
5. `InputItemCounts` — 消耗数量列表。
6. `OutputItemId` — 产出改装件 Id。
7. `Duration` — 制作时间。
8. `RequireWorkshopLevel` — 需要的工坊最低等级。
9. `EffectType` — 改装效果类型（精准度、稳定性、射速等）。
10. `EffectValue` — 改装效果数值。

## 8. 一期推荐建筑规划

一期推荐建筑不走传统 SLG 的木石粮路线，而是围绕搜打撤的外围养成来设计。

### 8.1 指挥中心

定位：

基地主建筑，决定其它建筑解锁、等级上限和可开放槽位。

一期功能：

1. 解锁新建筑。
2. 提升全基地功能上限。
3. 决定可用生产队列上限。

### 8.2 补给站

定位：

每日可收的基础被动产出建筑。

一期功能：

1. 被动产出基础补给品、通用零件或低级耗材。
2. 产出有缓存上限，鼓励玩家每日上线收取。
3. 高等级提升产出速度和缓存上限。

### 8.3 工坊

定位：

消耗局内带出材料进行加工的核心建筑，同时是装备个性化和战术准备的中枢。

一期功能：

1. 消耗局内带出资源生产弹药、药品、维修件。
2. 支持订单队列和加工时间。
3. 高等级解锁更高级配方。
4. **武器改装**：消耗局内带出的稀有零件，给武器加装配件（瞄准镜、消音器、握把等）。改装件只能在工坊制作，不可直接购买。
5. **弹药特化**：不同配方生产不同弹药类型（穿甲弹、燃烧弹、标记弹等），影响局内战术选择。
6. **装备修复**：撤离带回的装备存在耐久磨损，工坊可消耗材料修复。不修复也能使用但性能下降。
7. **一次性战术道具**：工坊制作仅局内使用的消耗品（干扰器、诱饵、信号弹等），增加战术深度。

说明：

工坊的核心价值是让局内带出的材料转化为"局内战术优势"，而不只是补充消耗品。武器改装和弹药特化让每次出局都有不同的装备配置可能性。

### 8.4 情报站

定位：

局前信息优势与出局目标驱动建筑。情报站不只是被动产出，而是直接影响下一局的游戏体验和目标感。

一期功能：

1. 被动产出情报点。
2. **悬赏合同**：情报站每日生成悬赏任务（带回指定物资、到达指定区域、击杀指定目标等），完成后获得额外奖励。悬赏合同由服务端每日刷新，合同数量和品质随建筑等级提升。
3. **地图预览**：情报站等级越高，进入局内前可预览的地图信息越多（资源热点区域、高危区域标记、撤离点分布提示）。
4. **情报消耗品**：情报站产出可消耗的"情报道具"，局内使用后临时显示附近物资分布或敌人位置。

说明：

悬赏合同是一期核心亮点。它给每局出局提供明确目标，提升重复游玩动力。服务端只需每日根据配置表刷新合同列表，客户端在情报站界面展示可接取的合同。玩家出局前选择接取哪些合同，撤离后自动判定是否完成。

### 8.5 仓储站

定位：

基地容量与缓存上限建筑。

一期功能：

1. 提升资源和产物缓存上限。
2. 提升生产订单缓存或特殊物资保留位。
3. 与补给站、工坊的收菜上限联动。

## 9. 基地资源与生产设计

### 9.1 资源来源划分

基地资源建议分为两类：

1. 基地自产资源
2. 局内带出资源

### 9.2 基地自产资源

推荐一期类型：

1. 基础补给
2. 情报点
3. 通用零件

用途：

1. 拉起每日上线收菜动机。
2. 用于基础制作和信息刷新。

### 9.3 局内带出资源

推荐一期类型：

1. 电子元件
2. 药剂原料
3. 稀有金属
4. 样本
5. 加密数据

用途：

1. 工坊加工。
2. 高级建筑升级和功能解锁。

### 9.4 生产模型

基地生产建议分两类：

1. 被动产出
2. 加工产出

被动产出：

1. 随时间累积。
2. 上线即可收取。
3. 受建筑等级和仓储上限限制。

加工产出：

1. 需要消耗局内带出材料。
2. 需要排队和等待完成。
3. 用于制作更有价值的下局物资。

### 9.5 装备获取与购买

玩家在出局前需要配置装备（枪械、防具等）。装备获取方式：

1. 仓库中已有的装备可直接装备使用。
2. 仓库中没有对应装备时，需要花费货币购买。
3. 装备购买消耗的是通用货币（通过 item 系统管理）。
4. 局内撤离带出的装备会自动进入仓库，下次可直接使用。

说明：

装备系统复用现有 `cn.etetet.item` 背包系统。装备购买属于商店行为，一期可直接在出局配装界面中内嵌购买功能，不需要独立商店建筑。

### 9.6 战损与恢复系统

局内表现直接影响基地状态，建立真正的"局内 → 基地 → 局内"循环感。

#### 角色伤势

1. 角色在局内受伤后回到基地，进入"受伤"状态。
2. 受伤状态下再次出局，角色属性会有一定程度下降（移速、负重、精准度等）。
3. 伤势会随时间自然恢复，但速度较慢。
4. 使用补给站产出的医疗物资可以加速恢复，或在工坊制作高级医疗品即时恢复。
5. 伤势严重程度与局内受到的伤害量挂钩，鼓励玩家在局内谨慎行动。

#### 装备磨损

1. 撤离带回的装备存在耐久度，每次出局使用都会磨损。
2. 耐久度下降后，装备性能随之下降（武器精准度降低、防具减伤降低等）。
3. 工坊可消耗材料修复装备耐久度。
4. 耐久度为 0 时装备不会消失，但性能大幅下降，鼓励及时修复。
5. 新购买的装备为满耐久。

#### 死亡惩罚缓冲

1. 角色死亡未能撤离时，携带的装备和物资默认全部丢失。
2. 仓储站的"保险位"可保护部分装备，放入保险位的装备不受死亡影响。
3. 指挥中心高等级可解锁"遗物回收"概率，死亡后有一定概率回收部分物资。

说明：

战损系统的数值层面通过 `cn.etetet.numeric`（数值系统）实现。伤势和耐久度作为角色/装备属性存储在 item 系统中。服务端在撤离结算时计算伤势程度和装备磨损，写入玩家存档。

### 9.7 搜打撤主循环绑定

推荐主循环：

1. 玩家在情报站查看悬赏合同，选择接取目标。
2. 在工坊改装武器、制作弹药和战术道具，准备出局装备。
3. 检查角色伤势状态，必要时使用医疗物资恢复。
4. 进入单局，完成搜集、战斗、撤离。
5. 撤离成功后，带出材料和装备进入仓库，结算悬赏合同奖励。
6. 回到 `Home`，处理基地收菜，修复磨损装备。
7. 在工坊消耗带出材料加工高价值物资。
8. 重复循环。

## 10. 服务端主流程设计

### 10.1 进入 Home

接入位置建议：

`Packages/cn.etetet.map/Scripts/Hotfix/Server/Map/M2M_UnitTransferRequestHandler.cs`

触发条件：

1. `mapName == "Home"`
2. `unit.UnitType == Player`

处理流程：

1. 玩家切入 `Home`。
2. `map` 层负责完成场景切换和玩家 Unit 初始化。
3. `home` 层通过 `HomeEnterHelper` 读取 `PlayerHomeComponent` 和建筑子 Entity。
4. 执行一次离线收益惰性结算（根据 `LastSettleTime` 计算离线期间的被动产出）。
5. 构建进入时需要下发的基地快照（建筑列表、槽位状态、生产订单）。
6. 同步给客户端加载场景内建筑与资源状态。
7. 客户端打开 `LobbyPanel`，默认展示基地页签。

说明：

1. 离线收益在登录时即结算（不依赖进入 Home），结算结果缓存，进入 Home 时下发给客户端展示。
2. 采用惰性结算方式（访问时根据时间差计算），不使用 Timer 主动触发，天然支持离线场景。

说明：

不要在 `M2M_UnitTransferRequestHandler` 中直接堆积基地业务逻辑，应转调 `HomeEnterHelper`。

### 10.2 建造流程

建议协议：

1. `C2M_HomeBuildRequest`
2. `M2C_HomeBuildResponse`
3. `M2C_HomeBuildingChanged`

服务端流程：

1. 客户端在基地页签下点击场景中的空槽位。
2. 弹出可建造建筑列表，玩家选择后发送建造请求。
3. 服务端校验当前场景是否为 `Home`。
4. 校验建筑配置是否合法。
5. 校验槽位是否合法、是否已占用、是否满足前置条件、资源是否足够。
6. 扣除资源（通过 item 系统）。
7. 创建建筑子 Entity，挂载 `HomeBuildingComponent`，即时完成建造。
8. 写入玩家存档。
9. 下发最新建筑状态。

### 10.3 升级流程

建议协议：

1. `C2M_HomeUpgradeRequest`
2. `M2C_HomeUpgradeResponse`
3. `M2C_HomeBuildingChanged`

服务端流程：

1. 校验建筑子 Entity 存在。
2. 校验是否达到最大等级。
3. 校验前置建筑与资源。
4. 扣除资源（通过 item 系统），即时完成升级，更新 `HomeBuildingComponent.Level`。
5. 落库并回推。

### 10.4 收取流程

建议协议：

1. `C2M_HomeCollectRequest`
2. `M2C_HomeCollectResponse`
3. `M2C_HomeResourceChanged`

服务端流程：

1. 结算当前建筑可收取资源。
2. 增加资源。
3. 更新建筑最后收取时间。
4. 落库并回推。

### 10.5 拆除流程

建议协议：

1. `C2M_HomeDemolishRequest`
2. `M2C_HomeDemolishResponse`
3. `M2C_HomeBuildingChanged`

服务端流程：

1. 客户端点击场景中的建筑。
2. 客户端弹出建筑操作菜单，选择拆除。
3. 服务端校验建筑实例存在且允许拆除。
4. 校验是否存在不可拆前置依赖。
5. 删除建筑子 Entity。
6. 写入存档并回推场景刷新。

### 10.6 生产流程

建议协议：

1. `C2M_HomeStartProductionRequest`
2. `M2C_HomeStartProductionResponse`
3. `C2M_HomeCollectProductionRequest`
4. `M2C_HomeProductionChanged`

服务端流程：

1. 客户端点击工坊或其它可生产建筑。
2. 服务端校验建筑功能、配方、材料与队列。
3. 创建 `HomeProductionOrderData`。
4. 进入进行中状态。
5. 到时完成并允许收取。
6. 玩家上线或点击建筑时收取产物。

### 10.7 悬赏合同流程

建议协议：

1. `C2M_HomeRefreshContractsRequest` — 手动刷新合同（可选）。
2. `M2C_HomeContractsChanged` — 合同列表变更推送。
3. `C2M_HomeAcceptContractRequest` — 接取合同。
4. `M2C_HomeAcceptContractResponse`
5. `C2M_HomeCollectContractRewardRequest` — 领取已完成合同奖励。
6. `M2C_HomeContractRewardResponse`

服务端流程：

1. 玩家进入 Home 时，服务端检查 `HomeContractComponent.LastRefreshTime`，如果跨天则自动刷新合同列表。
2. 刷新逻辑：根据情报站等级，从 `HomeContractConfig` 中按权重随机选取合同，写入 `AvailableContracts`。
3. 玩家在情报站界面选择接取合同，服务端校验合同存在且未过期，移入 `ActiveContracts`。
4. 玩家完成局内撤离后，服务端遍历 `ActiveContracts`，根据撤离结果判定合同进度（带回了指定物品、到达了指定区域等）。
5. 合同完成后状态变为已完成，玩家手动领取奖励。

### 10.8 撤离结算与战损流程

触发条件：玩家从局内撤离（成功或死亡）返回 Home。

服务端流程（撤离成功）：

1. 结算撤离带出的物资和装备，写入 item 系统。
2. 计算角色伤势程度（根据局内受伤量），写入角色伤势状态。
3. 计算携带装备的耐久磨损，更新装备耐久度。
4. 结算悬赏合同进度。
5. 同步基地状态给客户端。

服务端流程（死亡未撤离）：

1. 未放入保险位的携带物资和装备全部丢失。
2. 保险位内的物资和装备保留。
3. 角色进入重伤状态，恢复时间更长。
4. 悬赏合同进度不变，不因死亡失败。
5. 指挥中心高等级时触发"遗物回收"概率判定，可能回收部分物资。

## 11. 客户端表现建议

### 11.1 面板策略

当前客户端在进入 `Home` 后打开的是 `LobbyPanel`，玩家已身处 `Home` 场景。

决策：

`LobbyPanel` 包含多个子页签（子 Panel），其中”基地”页签可直接与 Home 场景交互（场景可见、可点击），其他页签下场景被 UI 遮挡，不可交互。基地页签负责承载槽位点击、建筑操作菜单、资源展示等功能。

### 11.2 客户端职责

客户端只负责：

1. 展示场景内建筑。
2. 管理页签切换与场景交互开关。
3. 处理槽位点击与建筑点击。
4. 发送建造、升级、拆除、收取、生产意图。
5. 展示资源变更和生产进度。
6. 根据服务端推送刷新状态。

客户端不负责：

1. 最终资源计算。
2. 建筑是否合法。
3. 离线收益结算。

### 11.3 场景交互建议

建议增加以下客户端运行时能力：

1. 槽位点击检测。
2. 建筑点击检测。
3. 基地页签下的槽位高亮。
4. 建筑选中后的操作菜单。
5. 非基地页签下屏蔽场景交互。
6. 不同建筑展示各自的生产、升级和收取状态。

## 16. 推荐结论

推荐的一期落地方向如下：

1. `Home` 保持个人私有副本。

3. 一期只做单人基地闭环，且交互发生在 `Home` 场景内。

9. 建筑采用 Child Entity 方案，固定槽位放置。
10. 基地资源复用 item 系统。
11. 离线收益惰性结算。
12. **情报站悬赏合同**：每日刷新出局任务，给玩家明确目标，提升重复游玩动力。
13. **工坊武器改装与弹药特化**：局内带出的材料转化为战术优势，让装备配置更有深度。
14. **角色伤势与装备磨损**：局内表现直接影响基地状态，形成真正的"局内 → 基地 → 局内"循环。
15. 先实现建筑加载、槽位建造、建筑升级、建筑拆除、收取、生产、悬赏合同、战损恢复、重登恢复。
16. 医疗收容站、拜访、联盟、掠夺等内容放到二期以后。

这样可以在不破坏当前 `map` 结构的前提下，形成一套真正服务搜打撤单局循环的局外基地系统。基地不是一个脱节的 SLG 空壳，而是通过悬赏合同驱动出局目标、通过改装系统影响局内战术、通过战损系统建立局后反馈，让每一局的"搜-打-撤"都和基地产生双向联动。
