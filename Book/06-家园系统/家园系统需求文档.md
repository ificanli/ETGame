# 家园系统需求文档

**创建时间**：2026-04-10  
**最后更新**：2026-04-13  
**状态**：开发中  
**关联任务**：M0.2-W3 #17  
**涉及包**：`cn.etetet.home`、`cn.etetet.statesync`、`cn.etetet.map`、`cn.etetet.item`、`cn.etetet.excel`

## 需求概述

当前 `Home` 已经具备私有副本、服务端建筑样机、快照同步和首页首段闭环，但新文档仍保留了“工坊/合同/恢复/出击准备”那套抽象模块主结构，和现在确认的正式版方向不一致。

用户已经明确正式版 demo 的主口径：

1. 家园必须是“建筑驱动”，不是抽象功能页驱动。
2. 与资源循环相关、能升级的能力都落在场景建筑上。
3. 其他管理动作由界面 UI 承接，而不是把建筑做成纯 UI 按钮。
4. 当前正式版 demo 先围绕 `主城` + `4 个可建建筑` 跑通真实闭环。
5. 这轮文档里优先把 `仓库` 写深，作为后续正式版实现的优先模块。
6. `Home` 场景默认只有一块家园地块，地块上的主城、建筑和展示物都根据家园数据动态加载，不做固定死预摆。

本文档是家园系统的正式需求基线，不替代旧稿 [Home主界面需求文档.md](Home主界面需求文档.md)。旧稿继续保留，用于记录 `Home` 首页首轮样机的历史背景与实现追踪。

## 文档定位

本文档只定义系统级需求、共通规则和正式版 demo 范围，不展开具体 prefab、页面树和 YIUI 资源结构。

本文重点回答：

1. 家园系统在搜打撤主循环里承担什么职责。
2. 当前正式版 demo 要做哪些建筑，规则是什么。
3. 场景建筑和界面 UI 如何分层。
4. 哪些规则需要走配置，哪些链路必须形成真实闭环。
5. 当前实现优先级为什么先落在 `仓库`。

具体页面结构、交互流和 YIUI 分层见 [家园UI设计文档.md](家园UI设计文档.md)。

## 系统定位

家园系统不是独立 SLG，也不是大厅里堆几块经营卡片。

它是搜打撤主循环的局外承接层，负责把“局内带出”转成“局外经营和下局准备”。当前正式版 demo 的核心不是把所有外围系统一次补完，而是先把以下链路成立：

1. 玩家进入 `Home` 后，看到的是一个有主城、有建筑槽位、有可点击建筑的基地。
2. 玩家通过场景建筑完成建造、升级、收取、展示、回收、存储等动作。
3. 玩家能感知主城等级、建筑等级、仓库容量和当前待处理事项之间的关系。
4. 玩家在家园里做的事情能够服务下一步资源积累和后续系统扩展。

## 正式版 Demo 范围

当前正式版 demo 只定义以下 5 类核心建筑：

1. `主城`
2. `大红收藏馆`
3. `物品回收间`
4. `农场`
5. `仓库`

说明：

1. `主城` 为系统默认拥有建筑，其场景表现按家园数据加载，不参与建造选择。
2. 其余 4 类建筑属于当前首批可建建筑。
3. 后续还会继续扩建筑，但本文档和当前 demo 先围绕这 4 类可建建筑写清楚。

## 当前工程基线

### 已有基础

当前工程已经具备以下承载条件：

1. `Home` 私有副本进入链路已打通。
2. 服务端已有家园建筑实例、基础建造/升级/拆除/收取样机能力。
3. 客户端已有 `Home` 快照缓存和首页首段闭环。
4. 当前首页样机已能承接 `Home` 主界面的第一轮视觉与交互。
5. 主城任务配置、快照、升级前置校验和主城任务完成度摘要已接入。
6. `大红收藏馆` 已接通“按仓库真实物品摆放 / 取下回仓”的最小真实闭环。
7. `物品回收间` 已接通“仓库取材 -> 开始回收 -> 完成后入仓”的最小真实闭环。
8. 独立 `HomePanel` 与正式 `HomeBuildingDetailCard` 已接入，`Home` 主流程不再继续依赖旧 `LobbyPanel.BuildPanel`。
9. `HomePanel` 已落地 `总览/主城任务/收藏馆网格/独立回收间/农场/Home 专属仓库` 六类正式承接页。
10. `Home` 场景点击、`Lobby Build` 入口、进入/离开 `Home` 场景时的 UI 开关已接通到独立 `HomePanel`。

### 当前缺口

当前距离正式版 demo 仍有以下缺口：

1. `Home` 场景虽然已按快照动态生成主城/建筑/空地块/锁定位，但正式场景模型和资源表现仍未替换。
2. 收藏馆、回收间、仓库当前已经进入独立正式页，但更细的筛选、排序和物品操作体验仍未补全。
3. 当前主城任务、收藏馆、回收间、农场和仓库闭环已经可体验，但正式美术资源、动效和更丰富的详情页表现仍待细化。

## 核心设计原则

### 1. 建筑驱动

1. 家园的主语是建筑，不是抽象功能标签。
2. 与资源循环、升级和容量有关的能力，必须落到可点击建筑上。
3. 其他说明、筛选、详情和批量管理动作由 UI 页面承接。

### 2. 场景优先，UI 承接

1. 建造发生在场景槽位上，而不是先开一个纯列表页。
2. 建筑交互先来自场景点击，再进入对应详情页。
3. 页面空态必须保留页面身份，不能靠跳到别的页面代替。

### 3. 服务端权威

1. 客户端只发建造、升级、拆除、摆放、放入、收取等意图。
2. 服务端负责校验金币、容量、任务前置、等级限制和结果写回。
3. 任何状态不一致时，以服务端快照和响应为准。

### 4. 配置驱动

1. 建筑可否重复、同类建筑数量上限、槽位解锁数量都走表配置。
2. 主城等级对建筑等级上限、槽位解锁和任务组切换的影响都走表配置。
3. 文档可以写“常见上限倾向为 2”，但最终实现不允许写死在代码里。

### 5. 正式版 demo 可真实体验

1. 不允许只做纯展示假页面。
2. 当前首版可以收敛范围，但每个保留模块都必须有真实闭环。
3. 当前优先把 `仓库` 做成真实承接层，而不是把它留成概念词。

### 6. 数据驱动加载

1. `Home` 场景默认只提供家园地块、槽位锚点和基础环境。
2. 主城、已建建筑、大红展示物等可见内容都根据玩家家园数据动态加载。
3. 系统语义上的“默认拥有主城”不等于把主城模型死写在场景里。

## 场景与 UI 分层

当前正式版 demo 的分层原则如下：

### 场景承担

1. 家园地块、槽位锚点和基础空间感。
2. 根据家园数据加载主城、建筑模型和展示物。
3. 空地槽位的解锁、锁定、可建提示。
4. 点击建筑或槽位进入后续操作。
5. 建筑存在感、空间关系和“基地感”。

### UI 承担

1. 首页总览和全局资源摘要。
2. 建筑详情、升级说明、拆除确认、主城任务查看。
3. 大红摆放/取下、回收队列管理、仓库查看等管理动作。
4. 各建筑的状态说明、空态、错误态和红点。

### 交互技术约束

1. 当前工程里“场景直点单位交互”已经被废弃。
2. 家园建筑的正式交互不复活旧 `click-unit` 链路。
3. 家园默认使用轻量场景建筑交互层，以 `BuildingId/SlotId` 打开对应详情页。
4. `ECA` 只作为未来特定点位能力的可选复用方案，不是家园默认交互框架。

## 玩家主循环

当前正式版 demo 推荐主循环如下：

1. 玩家进入 `Home`，默认看到基地首页和场景建筑。
2. 查看主城等级、当前主城任务和已解锁槽位。
3. 在空槽位上建造 `大红收藏馆`、`物品回收间`、`农场` 或 `仓库`。
4. 定期进入 `农场` 收金币。
5. 把垃圾物品放入 `物品回收间`，等待随机变成另一件物品。
6. 将回收产物收进 `仓库`，并在 `仓库` 中查看容量变化。
7. 把大红展示单位摆到 `大红收藏馆`，或者取下来。
8. 完成当前主城等级对应的任务组。
9. 满足任务组完成条件后消耗金币升级 `主城`，解锁更多槽位和更高建筑等级。

## 系统结构

家园正式版 demo 当前按以下结构组织：

1. `Home` 场景空间层
2. `主城` 与主城任务系统
3. `建筑槽位` 与通用建造/升级/拆除规则
4. `大红收藏馆`
5. `物品回收间`
6. `农场`
7. `仓库`

### 1. Home 场景空间层

职责：

1. 提供基地空间感、家园地块和固定建筑点位。
2. 让玩家通过场景点击进入建造或管理。
3. 按玩家家园数据动态加载主城、空槽位、已建建筑和展示物。

正式版要求：

1. `Home` 场景默认只有一块家园地块或底座，不预摆固定建筑内容。
2. 主城虽然在系统语义上默认拥有，但其场景表现对象也必须由家园数据动态加载。
3. 其他建筑建在固定空地槽位上，不做自由拖拽摆放。
4. 已解锁和未解锁槽位在场景中要可区分。

### 2. 主城

职责：

1. 作为基地的核心建筑。
2. 限制其他建筑的可升级上限。
3. 决定当前主城任务组。
4. 解锁更多建筑槽位和后续建筑能力。

核心规则：

1. 主城为系统默认拥有建筑。
2. 主城不可拆除，不可替换。
3. 主城的场景表现对象由家园数据动态加载，不在场景里写死预摆。
4. 点击主城后可进入主城详情，并从详情页跳转主城任务页。
5. 主城升级前，当前主城等级对应任务组必须全部完成。
6. 主城升级需要支付金币。
7. 主城升级后才允许其他建筑继续突破等级上限。

### 3. 大红收藏馆

职责：

1. 提供“大红”展示能力。
2. 让玩家对已拥有的大红进行摆放和取下管理。

核心规则：

1. `大红收藏馆` 只做展示，不提供属性。
2. 大红按“独立展示单位”处理，不是抽象数字。
3. 收藏馆有等级。
4. 当前 demo 建议默认展示容量为 `20`，正式实现走配置。
5. 玩家可以把大红摆上去，也可以取下来。
6. 展示状态需要能在详情页中明确看到当前已摆放单位。

### 4. 物品回收间

职责：

1. 吃掉垃圾物品。
2. 经过时间后随机产出另一件物品。
3. 把结果送入 `仓库`，形成家园资源循环。

核心规则：

1. demo 版本先允许“任意物品都能放入回收间”。
2. 回收结果随机变成另一件物品。
3. 可同时处理多个物品。
4. 可同时处理的数量和建筑等级相关。
5. 回收完成后需要玩家手动收取。
6. 收取结果进入 `仓库`，不直接掉到玩家身上。
7. 如果还有处理中或已完成未收取的内容，禁止拆除。

### 5. 农场

职责：

1. 提供稳定金币产出。
2. 给主城升级和其他建筑升级提供金币来源。

核心规则：

1. 农场按固定时间产出金币。
2. 金币需要手动收取。
3. 金币收取后直接进入玩家金币余额。
4. 农场产出不占 `仓库` 容量。
5. 若农场存在未收取状态，需要在首页和建筑详情里给出提醒。

### 6. 仓库

职责：

1. 作为家园系统的长期存储建筑。
2. 承接回收间产物和后续其他建筑的物品输出。
3. 提供容量压力，让建筑升级有明确价值。

当前优先级：

1. `仓库` 是这轮文档和后续实现的优先细化模块。
2. 正式版首版先做“家园存储闭环”，不接复杂背包整理。

核心规则：

1. 仓库升级提高的是“总格子数”。
2. 总格子数必须在 UI 中明确表达。
3. 当前阶段仓库主要承接家园内物品存储，不要求先补复杂拖拽整理。
4. 仓库中的物品基础规则应继续复用现有 `item` 体系，不新起一套物品底层逻辑。
5. 若仓库内还有存货，禁止拆除。
6. 回收间产物进入仓库时，需要先校验仓库容量是否足够。

### 7. 后续扩展建筑

当前正式版 demo 先不在主文档中继续展开其他建筑，但体系必须允许后续继续增加：

1. 新建筑仍走“场景建筑 + 详情页 UI”的统一结构。
2. 新建筑仍受主城等级、槽位和数量上限规则约束。

## 关键共通规则

### 1. 槽位规则

1. 槽位是场景中的固定空地，不做自由摆放。
2. 玩家决定某个已解锁槽位建造什么建筑。
3. 槽位解锁数量由主城等级决定，并走表配置。
4. 空槽位点击后打开建造选择页。

### 2. 建造规则

1. 可建建筑只能从当前已开放建筑列表中选择。
2. 同类建筑是否可重复、当前上限多少，全部走表配置。
3. 当前设计倾向中，同类建筑常见上限为 `2`，但最终以表配置为准。
4. 建造消耗金币。
5. 建造结果直接落在当前槽位。

### 3. 升级规则

1. 主城和其他建筑升级都消耗金币。
2. 其他建筑升级不能超过当前主城允许的等级上限。
3. 主城升级的门槛不是单纯金币，而是“任务组完成 + 金币足够”。
4. 正式版首版不把建造队列和升级计时作为必须范围。

### 4. 拆除规则

1. 除主城外，其他建筑允许拆除。
2. 拆除返还 `70%` 已投入金币。
3. 如果建筑内部仍有内容、处理中状态或未收取结果，则禁止拆除。
4. 被拆除后，槽位回到空地状态。

### 5. 主城任务规则

1. 主城任务是单独的任务体系，不和其他任务混表表达。
2. 主城任务按主城等级切换任务组。
3. 当前等级任务组全部完成后，主城才允许升级。
4. 主城任务页需要清楚告诉玩家“还差哪一项”。

### 6. 货币与资源规则

1. 当前正式版 demo 的通用升级与建造货币先统一为金币。
2. 农场负责稳定产金币。
3. 回收间负责把低价值物品随机转成另一件物品。
4. 仓库负责承接物品，不承接金币。

## 数据与同步边界

### 服务端数据

服务端至少维护以下权威数据：

1. 家园地块上的已加载内容清单或可还原加载数据。
2. 主城等级与当前主城任务组状态。
3. 建筑实例集合和槽位占用关系。
4. 各建筑的等级、内部状态和待收取状态。
5. 仓库当前容量与库存。
6. 回收间处理队列。
7. 农场待收金币。
8. 收藏馆当前已摆放的大红展示单位。

### 客户端数据

客户端只维护以下运行时态：

1. 首页和各建筑详情页的快照缓存。
2. 当前选中的槽位、建筑和页签。
3. 建造页、任务页、仓库页等局部交互状态。
4. 红点、提示和确认弹窗等临时态。

### 同步原则

1. 进入 `Home` 时必须拿到完整可展示快照。
2. 建造、升级、拆除、放入、取下、收取都采用请求后响应写回。
3. 重要变化要同步反映到首页、对应建筑页和红点状态。

## 包与实现边界

1. `cn.etetet.home` 负责家园模型、协议、服务端规则和客户端家园业务逻辑。
2. `cn.etetet.statesync` 负责 `Home` 场景表现、YIUI 页面和建筑详情页刷新。
3. `cn.etetet.map` 只负责切图、私有副本进入和场景交互入口，不承载家园业务规则。
4. `cn.etetet.item` 继续承接物品基础体系，仓库只做家园存储语义与容量管理。

## 当前实现优先级建议

为了把正式版 demo 跑通，当前建议实现顺序如下：

1. 主城详情和主城任务页。
2. 仓库正式版页面与容量闭环。
3. 物品回收间到仓库的产物闭环。
4. 农场金币收取闭环。
5. 大红收藏馆的摆放与取下闭环。

说明：

1. 这不是功能重要性排序，而是当前落地顺序建议。
2. `仓库` 提前，是因为它同时是回收间产物承接层和后续建筑扩展的公共底座。

## 正式版 Demo 系统级验收标准

- [ ] 玩家进入 `Home` 后能明确看见家园地块，以及根据家园数据加载出的主城、空地槽位和已建建筑。
- [ ] 主城作为默认拥有建筑，会通过家园数据正确加载到场景，并可从场景点击进入详情和主城任务页。
- [ ] 主城升级必须由“当前等级任务组全部完成 + 消耗金币”共同驱动。
- [ ] 玩家可以在已解锁槽位上建造 `大红收藏馆`、`物品回收间`、`农场`、`仓库`。
- [ ] 主城等级能正确限制其他建筑的等级上限和槽位解锁数量。
- [ ] 除主城外的建筑均支持拆除，且拆除返还 `70%` 金币。
- [ ] 建筑内部有内容或未收取结果时，拆除会被禁止。
- [ ] `物品回收间` 能完成“放入物品 -> 等待 -> 随机变成另一件物品 -> 手动收取进仓库”的真实闭环。
- [ ] `农场` 能完成“计时产金币 -> 手动收取 -> 金币直达余额”的真实闭环。
- [ ] `仓库` 能正确表达总格子数、当前占用和存储结果。
- [ ] `大红收藏馆` 能完成“摆上去 / 取下来”的展示闭环，当前 demo 默认容量为 `20`，正式实现由配置控制。
- [ ] 家园关键流程走真实快照与真实请求，不依赖纯本地假数据。
