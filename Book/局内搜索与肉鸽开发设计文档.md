# 局内搜索与肉鸽开发设计文档

## 1. 文档目标
- 将已确认需求转化为可开发的技术方案。
- 明确包级落点、协议定义、数据结构、联调顺序与验收方式。
- 约束实现过程：禁止硬编码、服务端权威、遵守ECS与ET分析器规范。

## 2. 已确认需求基线（2026-03-04）
- 容器产出支持两种模式：`ContainerPanel` 与 `GroundDrop`。
- 新动作名：`GenerateContainerLoot`（统一承载容器产出逻辑）。
- 搜索可中断（主动关UI/离开范围/死亡/切图），再次交互重置计时。
- 容器允许多人同时打开查看，拾取冲突先到先得。
- 肉鸽升级成长全走配置，不包含武器加成。
- 三选一不暂停时间。
- 三选一触发规则改为“等级X触发”（示例：2/4/6/9）。
- 选项池先采用单池。
- Buff复用 `BuffConfig`。

## 3. 设计原则
- ECA驱动：容器交互流程由流程图控制，代码只提供动作/条件执行能力。
- 服务端权威：容器状态、掉落、经验、升级、选项、Buff全由服务端决定。
- 客户端表现：UI只展示服务端状态，不做最终判定。
- 禁止硬编码：掉落、升级、触发等级、Buff映射全部来自配置或ECA参数。
- 并发安全：容器拾取与三选一选择使用协程锁，避免竞态。

## 4. 架构总览

### 4.1 容器搜索链路
1. `ECACheckRangeTimer` 触发进入/离开范围。
2. ECA流程执行 `ShowInteractButton/HideInteractButton`，服务端推送交互提示UI。
3. 玩家点击交互按钮，发送 `C2M_ECAInteract`。
4. 服务端触发 `OnPlayerInteract`：
   - `Closed`：显示搜索UI + 计时；计时结束执行 `GenerateContainerLoot` + `OpenContainerUI`。
   - `Opened`：直接 `OpenContainerUI`。
5. 玩家可发送：单个拾取、一键拾取、关闭容器、取消搜索。
6. 搜索被中断时取消计时并关闭搜索UI；下次交互重新开始。

### 4.2 肉鸽成长链路
1. `DamageHelper` 发布 `UnitDie`。
2. `UnitDie` 事件处理器筛选“玩家击杀怪物”，按配置发经验。
3. 经验达到阈值触发升级，应用基础属性成长（配置化）。
4. 若升级后命中触发等级（2/4/6/9等），入队待选次数。
5. 若当前无弹窗，立即下发三选一；玩家提交选择后服务端应用Buff。
6. 多次升级触发的选择按队列依次弹出，不暂停战斗时间。

## 5. 模块拆分与落点

### 5.1 `cn.etetet.eca`
- 变更点：
  - `ECAFlowActionKey` 新增 `GenerateContainerLoot`。
  - `ECAFlowNodeView` 增加该动作参数模板：`output_mode/loot_table/count/radius`。
- 兼容策略：
  - 保留 `SpawnItemsToGround`，在执行层做兼容映射到 `GenerateContainerLoot(output_mode=GroundDrop)`，避免旧流程图失效。

### 5.2 `cn.etetet.ecanode`（容器核心）
- 扩展 `ContainerComponent`（仅数据）：
  - 基础：`State`、`PointId`、`OutputMode`、`LootTable`、`DropCount`、`DropRadius`。
  - 面板产出：容器内物品列表（服务端权威）。
  - 会话态：每个玩家搜索状态、开始时间、对应timer key。
- 新增/扩展Helper（逻辑）：
  - `ContainerSearchHelper`：开始搜索、取消搜索、重置计时。
  - `ContainerLootHelper`：生成产出（容器内/地面掉落两模式）。
  - `ContainerTakeHelper`：单个拾取/一键拾取，含并发控制。
- 扩展 `ECAFlowActionInvokeHandler`：
  - 补齐 `ShowInteractButton/HideInteractButton/ShowSearchUI/OpenContainerUI/GenerateContainerLoot` 的实际行为。
- 关键修正：
  - 现有 `ECAFlowTimerHelper` 的 `point.FlowTimers[timerId]` 无法支持多人同点搜索。
  - 改为“玩家维度计时键”（示例：`{timer_id}:{playerId}`）或独立会话映射，保证多人并行搜索互不取消。

### 5.3 `cn.etetet.map`（交互入口）
- 新增Map场景消息处理器：
  - `C2M_ECAInteract*`
  - `C2M_ECASearchCancel*`
  - `C2M_ContainerTakeItem*`
  - `C2M_ContainerTakeAll*`
  - `C2M_ContainerClose*`
- 入口职责：
  - 校验point存在、是否在范围、单位状态合法。
  - 调用 `ECAPointComponent.OnPlayerInteract` 或容器Helper。
  - 返回错误码或触发服务端推送。

### 5.4 `cn.etetet.statesync`（肉鸽+UI主落点）
- 服务器组件：
  - `RogueProgressComponent`（等级/经验/待选队列/已选记录）。
  - `RogueChoiceComponent`（当前三选一选项、选择锁、弹窗状态）。
- 服务器逻辑：
  - `UnitDieEvent_RogueExpGain`。
  - `RogueProgressHelper`（经验结算、升级、属性应用、触发检测）。
  - `RogueChoiceHelper`（抽取选项、下发弹窗、处理选择）。
- 客户端：
  - 新增消息处理器驱动HUD与弹窗UI。
  - 在 `Main/HUD` 的YIUI体系中扩展：交互提示、搜索进度、容器面板、三选一弹窗、经验等级显示。

- `RogueMonsterExpConfig`
  - `UnitConfigId`
  - `Exp`

## 8.2 容器与ECA参数约定
- 在流程动作 `GenerateContainerLoot` 中读取：
  - `output_mode`：`ContainerPanel` / `GroundDrop`
  - `loot_table`
  - `count`
  - `radius`
- 不写死计时器ID、掉落数量、半径。

## 9. 并发与一致性设计
- 容器搜索并发：按玩家会话独立计时，互不覆盖。
- 容器拾取并发：按 `pointId`（必要时到 `pointId+slotIndex`）加协程锁。
- 先到先得：先入锁且通过库存校验者成功，后到请求返回“物品已被取走”。
- 三选一并发：同一玩家使用选择锁，`ChoiceSerial` 防重与防重复提交。
- 多次升级触发：进入待选队列，当前弹窗完成后弹下一个。

## 10. 错误码与日志

## 10.1 错误码（新增建议）
- 容器：
  - 点位不存在
  - 不在交互范围
  - 搜索已中断
  - 物品不存在/已被取走
  - 背包空间不足
- 肉鸽：
  - 无待选项
  - 选项非法
  - 重复提交

## 10.2 日志关键字
- 容器：`[ECAContainer]`
  - 进入/离开范围、交互、搜索开始/取消/完成、产出模式、拾取结果。
- 肉鸽：`[Rogue]`
  - 击杀来源、经验增量、升级前后、触发等级、弹窗下发、选择应用。

## 11. 开发任务分解（按阶段）

## 11.1 Phase 1：容器交互基础链路
- 新增协议（交互提示、交互请求、搜索状态、取消搜索）。
- 补齐ECA动作执行：`ShowInteractButton/HideInteractButton/ShowSearchUI`。
- 实现 `C2M_ECAInteract` 与 `C2M_ECASearchCancel`。
- 完成“中断后重置计时”。
- 验收：提示显示/隐藏、搜索可中断并可重开。

## 11.2 Phase 2：容器产出与拾取
- 新动作 `GenerateContainerLoot`（兼容旧动作）。
- 支持 `ContainerPanel` 与 `GroundDrop` 两模式。
- 完成 `OpenContainerUI`、`TakeItem`、`TakeAll`、`Close`。
- 实现并发锁与先到先得。
- 验收：多人同时打开、抢同一物品行为正确。

## 11.3 Phase 3：肉鸽经验升级
- 新增肉鸽配置与组件。
- 挂接 `UnitDie` 发经验。
- 实现升级与基础属性成长。
- 实时同步经验/等级HUD。
- 验收：击杀->经验->升级链路稳定。

## 11.4 Phase 4：三选一与Buff
- 实现触发等级规则（配置化：2/4/6/9）。
- 单池抽3选1，下发弹窗并处理选择。
- 选择后调用 `BuffHelper.CreateBuff`。
- 队列化处理多次触发。
- 验收：连续升级多次弹窗不丢失、不乱序。

## 13. 风险与处理
- 风险1：多人搜索计时互相覆盖。
  - 处理：改为玩家维度timer key。
- 风险2：地面掉落模式缺少现成世界掉落实体链路。
  - 处理：优先打通动作与协议接口，落地时复用现有可拾取实体体系；若缺失则补最小地面掉落实体实现。
- 风险3：UI资源制作周期影响联调。
  - 处理：先用简版YIUI占位界面，优先打通协议与逻辑。
