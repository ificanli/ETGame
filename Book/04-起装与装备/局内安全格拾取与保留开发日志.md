## 决策记录

### 2026-04-01 - 运行时安全格保持独立容器

- **背景**：用户已明确“安全格不在背包里面，单独有 UI 做了”，但当前搜索界面运行时仍把安全格问题折叠成普通背包落位缺口。
- **方案**：局内安全格继续保持独立 UI、独立运行时容器，不再把它伪装成背包内部隐藏槽位。
- **原因**：这样才能把一键拾取、拖拽、死亡保留和结算回写收束到一致的数据模型，避免继续用隐藏槽位制造显示与权威状态错位。
- **替代方案**：继续沿用 `ItemComponent` 内部隐藏安全槽位。放弃原因是会让拖拽区域语义、运行时回写和客户端展示继续耦在一起，问题只会越来越难收。

### 2026-04-01 - 一键拾取按单格价值阈值决定是否进安全格

- **背景**：用户要求“单格价值大于 X 放安全格，否则放背包”，且 `X` 必须走常量表，安全格放不下时回退普通背包。
- **方案**：新增 `RogueGlobalConfig.AutoSecureMinValuePerGrid`，按 `LoadoutBuyPrice * Count > AutoSecureMinValuePerGrid * (GridWidth * GridHeight)` 判断是否优先进安全格。
- **原因**：规则可配置、可热更，并且直接复用现有 `LoadoutBuyPrice`，不再引入第二套价值口径。
- **替代方案**：按总价或固定物品白名单硬编码。放弃原因是不可配置，且和“单格价值阈值”需求不一致。

## 问题日志

### 2026-04-01 - 旧文档仍按“安全格不进入局内”编写

- **现象**：起装需求文档、技术设计文档和 BUG-008 修复文档仍有多处写着“本期安全格不进入局内可交互运行时”。
- **原因**：用户在 BUG 排查过程中调整了方向，决定本期正式做安全格运行时，但历史文档未同步。
- **解决**：先更新计划和设计文档，把 BUG-008 口径改为“由功能补齐彻底收口”，再继续改代码。

### 2026-04-01 - `Map2G_LoadoutCarryResult` 缺少安全格尺寸字段导致编译失败

- **现象**：补齐死亡/撤离回写时，`EvacuationSettlementHelper`、`LoadoutStateHelper`、`UnitDieEvent_ClearLoadout` 开始引用 `SecureWidth/SecureHeight`，但 `Map2G_LoadoutCarryResult` 的 proto/generated 未同步，`dotnet build ET.sln` 失败。
- **原因**：前序代码已经开始消费安全格尺寸，但消息定义只补了 `FinalSecureItems`，没有补 `SecureWidth/SecureHeight`。
- **解决**：同步修改 `Packages/cn.etetet.equipment/Proto/Loadout_C_11100.proto` 与三端 `Loadout_C_11100.cs` 生成代码，补齐字段和 `MemoryPackOrder`。

### 2026-04-01 - `ET.ExcelExporter` 裸跑会在 `Program.cs:47` 越界

- **现象**：执行 `dotnet Bin/ET.ExcelExporter.dll` 后，导出器完成前置处理后在 `Program.cs:47` 抛 `IndexOutOfRangeException`。
- **原因**：导出器会直接读取 `args[0]` 作为 `configType`，裸跑没有传 `Luban/Json` 参数。
- **解决**：本轮统一改为执行 `dotnet .\\Bin\\ET.ExcelExporter.dll Luban`，成功同步 `RogueGlobalConfig` 的运行时二进制配置。
