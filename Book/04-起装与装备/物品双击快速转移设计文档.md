## 需求概述

用户希望在现有物品界面中补一个通用的“双击快速转移”操作，减少拖拽成本。

本轮明确范围：

1. `SearchPanel` 搜索界面：双击整堆转移，支持容器到背包、背包到容器。
2. `LobbyPanel` 起装界面固定槽：双击已装备枪械或其它固定槽物品，直接卸到仓库。
3. `LobbyPanel` 仓库区域：双击仓库物品，按默认语义放入背包。
4. `LobbyPanel` 背包与安全箱区域：双击整堆回仓库。
5. 如果上下文无法推导唯一有效目标，或者目标区域没有位置，本次操作直接静默失败，不额外弹提示。

## 技术方案

### 整体思路

不为 `SearchPanel` 单独写一套特殊逻辑，而是在已有点击/拖拽链路上补一层“单击延迟、双击优先”的通用交互收口：

1. 单击详情改为短延迟执行，避免双击时第一次点击先弹详情。
2. 双击命中后取消同一目标的待执行单击，并直接走现有移动/卸下/取出链路。
3. SearchPanel 只默认处理 `Container <-> Bag`，不把 `Secure` 混入默认目标，避免双击目标不唯一。
4. 起装界面复用现有 `PutToWarehouse`、`TakeFromWarehouse`、`HandleOwnedGridItemClickAsync` 等链路，不重新发明服务器协议。

### Entity/Component 设计

本次不新增运行时 Entity，仅在现有 UI Component 上增加少量交互状态字段：

1. `SearchPanelComponent` 增加点击版本号，用于取消延迟单击。
2. `LobbyPanelComponent` 增加固定槽、仓库、背包/安全箱各自的点击版本号，用于区分单击与双击。

这些字段只保存临时 UI 状态，不改变业务数据结构。

### 接口设计

不新增协议。

复用现有客户端请求：

1. `ECAInteractHelper.MoveContainerItem(...)`
2. `C2G_LoadoutPutToWarehouse`
3. `C2G_LoadoutTakeFromWarehouse`
4. `C2G_LoadoutMoveOwnedItem` 现有封装链路

### 数据结构

不新增 Excel、Proto 或运行时配置结构。

### 路由规则

#### SearchPanel

1. `ContainerSearch` / `CorpseLoot`：
   - 源区域为 `Container`，双击尝试放到 `Bag`
   - 源区域为 `Bag`，双击尝试放到 `Container`
   - 源区域为 `Secure`，本轮不做默认双击转移
2. `BackpackInspect`：不做默认双击转移

#### LobbyPanel

1. 固定槽：双击直接卸到仓库
2. 仓库 item：双击优先放入背包
3. 背包 / 安全箱：双击直接回仓库
