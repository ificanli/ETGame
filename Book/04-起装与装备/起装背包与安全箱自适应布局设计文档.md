**创建时间**：2026-04-16  
**最后更新**：2026-04-16  
**状态**：已完成

**涉及包**：cn.etetet.statesync

## 需求概述

当前正式起装页使用 `LobbyPanel`，背包与安全箱的格子内容已经会按照 `LoadoutComponent.BagWidth/BagHeight`、`SecureWidth/SecureHeight` 进行渲染，但外层 UI 仍然保留旧 prefab 的绝对定位：

- 背包背景没有跟随格子区域收缩或扩张
- 安全箱背景同样没有贴合自己的格子区域
- 安全箱没有稳定跟在背包下方，而是继续使用旧的绝对坐标
- 玩家更换不同尺寸背包后，布局视觉会错位

本期目标只处理当前正式页，不处理分辨率适配，要求：

- 背包背景与背包格子区域贴合
- 安全箱背景与安全箱格子区域贴合
- 安全箱自动摆在背包下方
- 尺寸必须跟随当前背包/安全箱格子数量变化，不能写死成单一尺寸

## 技术方案

### 整体思路

继续复用 `LobbyPanel` 当前已有的“按格子数渲染格子和物品”链路，不新做第二套 prefab 或第二套怪异布局逻辑，但方案从最初的“纯运行时重排”收口为“prefab 容器 + 运行时尺寸更新”的混合方案：

- 保留 `RenderOwnedGridArea` 负责格子和物品渲染
- 在同一条刷新链路里计算背包/安全箱当前网格的实际像素尺寸
- 在 prefab 中新增 `LoadoutOwnedAreaRoot`，由它统一承接背包块和安全箱块的纵向排布
- 给 `CurrentBagRoot / SecureBagRoot` 增加 `LayoutElement`，让块尺寸跟随运行时计算结果回填
- 把 `CurrentBagBoardRoot / SecureBoardRoot` 从“完全跟 root 拉伸”改为“运行时显式尺寸”
- 把 `Bg`、标题、提示文案等 chrome 节点按缓存的相对偏移重新布置
- 用 `VerticalLayoutGroup` 负责“安全箱排在背包下方”的静态排布，用运行时代码负责尺寸更新与内部 chrome 重排

这样可以最大化复用现有拖拽和点击链路，同时把“谁在谁下面”这类静态结构收回 prefab，避免长期让运行时代码承担静态布局职责。

### 布局设计

#### 1. 网格尺寸继续复用统一格子边长

- 继续使用 `LobbyPanelComponent.UnifiedCellSize`
- 继续复用 `GridSpacing`、`GridPadding`
- 板子最终尺寸统一按：
  - `width = padding * 2 + cols * cell + (cols - 1) * spacing`
  - `height = padding * 2 + rows * cell + (rows - 1) * spacing`

#### 2. prefab 负责纵向结构，运行时缓存块内相对布局关系

`CurrentBagRoot` 与 `SecureBagRoot` 下已经有：

- `Bg`
- `Title`
- `HintText`（仅安全箱）
- `BoardRoot`

本轮保留块内节点的现有视觉关系，但把块与块之间的纵向结构收回 prefab：

- 新增 `LoadoutOwnedAreaRoot`
- 给它挂 `VerticalLayoutGroup`
- 让 `CurrentBagRoot / SecureBagRoot` 成为它的直接子节点
- 给两个 root 补 `LayoutElement`

与此同时，在首次初始化时缓存块内节点的相对关系：

- 每个子节点相对 `BoardRoot` 左上角的偏移
- 每个标题/提示节点的尺寸
- 两个块相对父节点的起始位置和块间距

后续每次背包尺寸变化时，按新的 `BoardRoot` 尺寸重新计算整个块的包围盒，并同步：

- `BoardRoot`
- `Bg`
- `Root`
- `LayoutElement.preferredWidth / preferredHeight`

#### 3. 不破坏现有拖拽/点击语义

当前拖拽和点击链路直接依赖：

- `u_ComCurrentBagBoardRoot`
- `u_ComSecureBoardRoot`

因此本轮要求：

- 这两个节点继续保持为真实可点击、可投放的板子
- 不把交互挂到新的代理节点
- 只改它们的尺寸和运行时位置，不改语义入口
