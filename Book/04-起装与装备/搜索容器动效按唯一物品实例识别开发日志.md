## 决策记录

### 2026-04-16 - 搜索状态改为按物品实例而不是按 slot
- **背景**：容器内移动、交换、堆叠后会重复播放搜索动画。
- **方案**：给容器物品补唯一 `ItemUid`，并让客户端 `SearchPanel` 用 `ItemUid` 记录搜索开始、持续时间和完成状态。
- **原因**：问题根因是实例身份缺失，单纯按格子记录无法区分“同一物品换位置”和“真正新物品”。
- **替代方案**：只在 UI 层按 `ConfigId + Count + Slot` 或快照做止血；已放弃，因为移动、交换、拆堆/并堆场景下都不稳定，无法表达真正的实例身份。

### 2026-04-16 - 容器 item view 也按 `ItemUid` 复用
- **背景**：即便搜索状态改为按实例，如果容器 item view 仍按 `slot` 复用，物品换格时 UI 节点和搜索遮罩仍会被销毁重建。
- **方案**：`SearchPanel.RenderContainer()` 改为优先使用 `ItemUid` 作为容器 item 的 `viewId`。
- **原因**：这样物品在容器内移动时，现有 UI 节点、拖拽代理和搜索遮罩都能跟着同一实例走，表现更稳定。
- **替代方案**：保持 view 仍按 `slot` 复用，只把搜索状态按 `ItemUid` 保存；已放弃，因为搜索中的物品在换格时仍可能丢失当前遮罩载体，需要下一帧重新补建。

## 问题日志

### 2026-04-16 - 搜索动画重复播放根因确认
- **现象**：把已搜索过的物品在容器内移动后，又会重新播放搜索动画。
- **原因**：`SearchPanel` 当前按 `slot` 保存 `SlotSearchStartTimes / SearchedSlots / SlotSearchingEffects`，客户端和服务端容器数据都没有物品实例 id。
- **解决**：本轮补 `ItemUid` 数据链，并把搜索状态收口到实例维度。
