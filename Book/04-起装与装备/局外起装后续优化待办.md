# 局外起装后续优化待办

## 说明

当前目标以“先跑起来”为主，以下内容全部属于后续优化项，不影响现阶段继续联调与使用。

## UI / Prefab

- `EquipPanel` 的格子物品模板应收敛成一个通用模板，例如 `u_ComGridItemTemplate`，统一给背包、安全格、仓库复用。
- `EquipPanel` 的仓库区域目前是运行时动态补出 `WarehouseGridRoot`、`WarehouseItemsLayer`、`WarehouseItemTemplate`，后续应在 prefab 中显式提供这些节点。
- `u_ComWarehouseLoopScroll` 当前被直接复用为仓库二维显示面板，命名已经不准确，后续应改成更明确的仓库棋盘根节点命名。
- 当前 `u_ComCurrentBagItemTemplate`、`u_ComSecureItemTemplate` 仍然保留，后续应删除重复模板与冗余绑定。
- 仓库格子选中态目前是代码里直接改背景色，后续应收敛成统一的选中视觉规范。

## 交互

- 仓库当前是“点击选中，再点固定槽位/背包区域放入”，后续应补完整拖拽交互。
- 仓库当前只做二维展示，不保存局外仓库内的摆放位置；后续如要支持真正仓库整理，需要增加仓库内移动与持久化位置。
- 仓库物品过多时，目前只做本地自动排布，后续需要补滚动、分页或扩容方案。
- 固定槽位、背包、安全格、仓库四块区域的点击/拖拽反馈需要统一。

## 数据 / 协议

- 服务端仓库已经改成离散物品列表，但现阶段仍保留 `StorageConfigIds + StorageCounts` 聚合字段做兼容；后续可在完整切换后移除旧字段。
- 当前从仓库取物仍按 `ConfigId + Count` 请求，后续如果要精确到某个仓库实例，应改成带 `ItemUid` 的协议。
- 客户端选装弹窗当前仍基于聚合后的仓库列表显示，后续可按业务需要决定是否切到离散实例视图。
- 需要补仓库尺寸配置来源，避免后续出现“显示尺寸”“可存容量”“实际规则”三套口径不一致。

## 代码结构

- `LobbyPanelComponent` 中仍保留了旧的 `WarehouseLoop` 相关字段，后续应清理。
- 仓库二维显示是新增的 partial 逻辑，后续可进一步抽成更通用的格子容器渲染辅助类，减少背包/安全格/仓库三处重复。
- 仓库自动排布目前是客户端本地临时算法，后续如果仓库也要保存布局，需要迁移到正式的数据模型与服务端校验。

## 后续建议顺序

1. 先做通用 `GridItemTemplate`，把 prefab 结构收干净。
2. 再补仓库显式节点与滚动方案，去掉运行时兜底节点创建。
3. 最后再决定仓库是否要保存摆放位置，以及是否把取物协议切到 `ItemUid`。
