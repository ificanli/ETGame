## 需求概述

当前 `SearchPanel` 的容器搜索动效按 `slot` 记录“是否已搜索”。  
这会导致同一个物品在容器内被移动、交换或参与堆叠后，只要落到新的格子，就会被当成“新物品”再次播放搜索动画。

用户期望的正确行为是：

1. 只有玩家第一次搜索到某个容器物品实例时才播放搜索动画。
2. 同一物品在容器内移动、交换位置后，不应重复播放。
3. 堆叠时应沿用保留下来的那堆物品实例身份，不应把纯位置变化误判为新物品。
4. 真正新生成到容器中的物品，仍应正常播放搜索动画。

## 技术方案

### 整体思路

这次不做 UI 层“按 slot 止血”，而是把容器物品实例身份补到正式数据链路：

1. 服务端容器条目新增 `ItemUid`，作为容器内单个物品实例的稳定标识。
2. 容器打开 / 更新协议把 `ItemUid` 同步给客户端。
3. 客户端运行时容器数据保留 `ItemUid`。
4. `SearchPanel` 把搜索开始时间、持续时间、已搜索集合、搜索动效索引统一改为按 `ItemUid` 记录。
5. 容器切换时仍按 `PointId` 整体清空搜索态；同一容器内的移动/交换/堆叠则保留实例身份。

这样可以把“第一次搜索”从“第一次见到某个格子”修正为“第一次见到某个物品实例”。

### Entity/Component 设计

本次不新增 Entity。

调整已有数据结构：

1. `ContainerItemEntry`
   - 新增 `long ItemUid`
2. `ContainerClientItemData`
   - 新增 `long ItemUid`
3. `SearchPanelComponent`
   - 搜索缓存从按 `slot` 改为按 `itemUid`

这些改动保持 ECS 分层不变：

1. 服务端 `ContainerComponent` 继续只持有容器数据。
2. 搜索动效逻辑仍只在客户端 `SearchPanelComponentSystem` 中处理。

### 接口设计

修改容器同步消息：

1. `ContainerItemData`
   - 新增 `int64 ItemUid`

不新增新的容器消息类型，继续复用：

1. `M2C_ContainerOpen`
2. `M2C_ContainerUpdate`

### 数据结构与身份语义

`ItemUid` 语义约定如下：

1. 容器首次生成物品时分配新的唯一 `ItemUid`
2. 纯移动：原 `ItemUid` 跟随物品移动
3. 交换：两个 `ItemUid` 随各自物品交换位置
4. 堆叠：保留目标格物品的 `ItemUid`，源格被并入后删除
5. 新刷入或重新创建的物品：生成新的 `ItemUid`

这样能让“被并入消失的那件物品实例”自然失效，也能保证保留的那堆物品在客户端继续被识别为同一个实例。
