# BUG-006 怪物死亡后尸体残留血条 — 修复方案

> 文档版本：v1.0  
> 创建时间：2026-03-26  
> 关联 BUG：BUG-006（BUG追踪.md）

---

## 1. 现象描述

怪物被击杀后：
- 原怪物 Unit 被销毁（Dispose）
- 服务端生成 MonsterCorpse（Virtual Unit）用于搜索
- **客户端屏幕上，怪物位置处的血条没有消失，残留悬浮在空中**

---

## 2. 血条系统结构

项目中有两套血条组件：

| 组件 | 挂载方式 | 隐藏机制 | 使用场景 |
|------|---------|---------|---------|
| `HPViewComponent` | 挂在 Unit 的子 YIUI View 上，血条 UI 在 HUD Canvas（2D 覆盖层）| `SetUICache()`：将 RectTransform 移回 `UICache`（隐藏容器）| 普通怪/玩家血条 |
| `HPView3DComponent` | 挂在 Unit 的子 YIUI View 上，血条在世界空间 Canvas（3D 跟随）| `u_DataShow.SetValue(false)`：数据绑定控制 GameObject 显隐 | 部分 3D 世界血条 |

两者的 `LateUpdate` 逻辑都能在**正常存活状态**下正确隐藏血条（距离超出、屏幕外、HP≤0 均触发隐藏）。

---

## 3. 根本原因分析

### 3.1 正常隐藏路径（不触发时机）

```
LateUpdate 每帧：
  UpdateHP() → HP=0, MaxHP=0 → return 0
    → SetUICache()  ← 隐藏！
```

这条路径依赖 **LateUpdate 至少再跑一帧**才能执行。

### 3.2 问题触发时机

```
怪物 HP → 0
  → 服务端发送销毁消息
  → 客户端收到后调用 unit.Dispose()
      → HPViewComponent.Destroy() 被调用
          → 方法体为空！（什么都没做）
      → LateUpdate 在本帧已经执行过，
        下一帧 Entity 已经 IsDisposed，不再进入 LateUpdate
  → 血条 UIBase 的 RectTransform 仍在 HUDPanel/ComHPContent 下
    → 血条 GameObject 保持可见，悬浮残留
```

**根因总结**：`HPViewComponent.Destroy` 和 `HPView3DComponent.Destroy` 的方法体均为空，Unit 被 Dispose 时没有主动隐藏血条 UI，导致血条 GameObject 在 HUD Canvas 上成为"孤儿节点"，继续渲染。

### 3.3 为什么 MonsterCorpse 不会触发隐藏

MonsterCorpse 是新创建的 Virtual Unit，**不带 HPViewComponent/HPView3DComponent**，因此不会有新的血条出现，也不会去清理旧的血条残留。

### 3.4 `SetUICache` 在 Destroy 时的安全性

`SetUICache` 依赖 `self.YIUIMgr()`：

```csharp
private static void SetUICache(this HPViewComponent self)
{
    if (self.UIBase.OwnerRectTransform.parent != self.YIUIMgr().UICache)
    {
        self.UIBase.OwnerRectTransform.SetParent(self.YIUIMgr().UICache);
    }
}
```

在 Unit.Dispose() 调用链中，`YIUIMgr()` 通过 Scene 路径查找，Scene 此时仍存在，**不会为 null**。UIBase 及其 OwnerRectTransform 在 `Destroy` 回调时也尚未被 YIUI 框架销毁（YIUI 池化回收发生在稍后），因此可以安全调用。

需要加一层 null 保护，防止极端情况下提前销毁：

```csharp
if (self.UIBase?.OwnerRectTransform == null) return;
var mgr = self.YIUIMgr();
if (mgr == null || mgr.UICache == null) return;
```

## 4. 修复方案

### 4.1 修改 `HPViewComponentSystem.cs`

**文件路径**：  
`Packages/cn.etetet.statesync/Scripts/HotfixView/Client/YIUISystem/Main/HPViewComponentSystem.cs`

**修改前**（第 41-44 行）：
```csharp
[EntitySystem]
private static void Destroy(this HPViewComponent self)
{
}
```

**修改后**：
```csharp
[EntitySystem]
private static void Destroy(this HPViewComponent self)
{
    // Unit 销毁时，立即将血条归位到 UICache 隐藏，防止血条残留在 HUD Canvas 上
    if (self.UIBase?.OwnerRectTransform == null) return;
    var mgr = self.YIUIMgr();
    if (mgr?.UICache == null) return;
    if (self.UIBase.OwnerRectTransform.parent != mgr.UICache)
    {
        self.UIBase.OwnerRectTransform.SetParent(mgr.UICache);
    }
}
```

### 4.2 修改 `HPView3DComponentSystem.cs`

**文件路径**：  
`Packages/cn.etetet.statesync/Scripts/HotfixView/Client/YIUISystem/Main/HPView3DComponentSystem.cs`

**修改前**（第 21-24 行）：
```csharp
[EntitySystem]
private static void Destroy(this HPView3DComponent self)
{
}
```

**修改后**：
```csharp
[EntitySystem]
private static void Destroy(this HPView3DComponent self)
{
    // Unit 销毁时，立即隐藏 3D 血条，防止残留渲染
    self.u_DataShow?.SetValue(false);
}
```

## 7. 测试验证

| 测试用例 | 预期结果 |
|---------|---------|
| 击杀怪物，站在尸体旁边 | 血条立即消失，不出现残留 |
| 击杀怪物后立即开搜索面板 | 搜索面板打开正常，血条无残留 |
| 同时击杀多只怪物 | 所有怪物血条均立即消失 |
| 玩家自己死亡 | 玩家血条也应立即隐藏（同路径修复） |
| 场景切换/撤离时 Unit 批量销毁 | 无报错，无残留血条 |
| `YIUIMgr` 或 `UICache` 为 null（极端情况）| 防御性 return，无 NullReferenceException |

---

## 8. 潜在关联问题

- **玩家死亡时血条残留**：玩家 Unit 也会走 Dispose 流程，同一修复路径覆盖。  
- **机器人/NPC 死亡**：只要挂有 HPViewComponent，均受益于此修复。  
- **其他 YIUI View 组件的 Destroy 空体**：建议全局搜索 `Destroy` 为空体的 YIUI View 组件，评估是否都需要类似的清理逻辑。
