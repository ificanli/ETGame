# BUG-012 匹配成功后匹配界面未隐藏修复方案

> 文档版本：v1.0  
> 创建时间：2026-03-31  
> 最后更新：2026-03-31  
> 状态：已完成  
> 关联 BUG：BUG-012（BUG追踪.md）

---

## 1. 现象描述

当前大厅从 `LobbyPanel` 发起匹配后，会打开 `MatchView` 作为“匹配中”等待弹层。

用户现场反馈的异常表现是：

- 玩家已经匹配成功并正常进入地图
- 后续在地图中传送回 `Home` 场景时
- 大厅里仍然残留着“匹配中 / 取消匹配”的等待界面

用户要求本次修复满足两个约束：

1. 匹配成功后就隐藏等待界面，不要等回 `Home` 才被动清理
2. 修复要兼顾残留兜底，避免历史脏状态在 `LobbyPanel` 再次打开时继续出现

---

## 2. 根因判断

当前客户端链路存在两个缺口：

1. `LobbyPanelComponentSystem.SendMatchRequest` 在打开 `MatchView` 后，只等待 `Wait_SceneChangeFinish`
   - 它没有消费 `G2C_MatchSuccessHandler` 发出的 `Wait_MatchSuccess`
   - 因此“匹配成功”这个时刻没有任何 UI 关闭动作
2. `LobbyPanel` 打开时没有对 `MatchView` 做残留清理
   - 如果前一次匹配流程异常中断，或 UI 生命周期和预期不完全一致
   - 旧的 `MatchView` 就可能在重新回到 `Home` 后继续显示

因此这个问题的本质不是“回 Home 时又打开了匹配界面”，而是：

- 匹配成功时没有及时关闭
- `LobbyPanel` 再次打开时又没有兜底清理

---

## 3. 修复目标

本次修复只解决等待界面的生命周期，不改匹配协议和场景切换协议：

1. 客户端收到匹配成功通知后，立即关闭 `MatchView`
2. 后续继续等待场景切换完成，再按既有流程关闭 `LobbyPanel`
3. `LobbyPanel` 每次打开时，额外做一次无动画兜底清理，防止残留界面再次出现
4. 执行 `dotnet build ET.sln` 验证编译通过

---

## 4. 技术方案

### 4.1 整体思路

保持现有包依赖边界：

- `cn.etetet.match` 继续只负责在 `G2C_MatchSuccessHandler` 中发出 `Wait_MatchSuccess`
- `cn.etetet.statesync` 作为依赖 `match` 的 UI 包，负责消费这个等待信号并关闭 `MatchView`

具体做法：

1. 在 `SendMatchRequest` 中，打开 `MatchView` 后先等待 `Wait_MatchSuccess`
2. 收到匹配成功后立即关闭 `MatchView`
3. 再等待 `Wait_SceneChangeFinish`，沿用现有进图完成和关闭 `LobbyPanel` 的流程
4. 在 `LobbyPanel.YIUIOpen` 中补一次 `MatchView` 兜底关闭
