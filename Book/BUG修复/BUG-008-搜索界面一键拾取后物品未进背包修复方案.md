# BUG-008 搜索界面一键拾取后物品未进背包修复方案

> 文档版本：v1.3  
> 创建时间：2026-03-29  
> 最后更新：2026-03-30  
> 状态：已完成  
> 关联 BUG：BUG-008（BUG追踪.md）

---

## 1. 现象描述

在 `SearchPanel` 搜索容器时：

- 点击“一键拾取”后，容器里满足条件的物品会从左侧列表消失
- 右侧背包没有出现对应物品
- 2026-03-30 实机回归又发现：手动把容器物品拖到背包时，请求会返回成功，但背包里写入的物品配置和尺寸仍可能不对
- 2026-03-30 继续现场日志定位确认：当本局 live unit 根本没有背包时，一键拾取和把容器物品拖到背包区都会失败，但客户端此前没有明确提示，表面上仍像“物品没进背包”

用户要求本次修复遵循两条约束：

1. 按共用链路修复，不只修单个 UI 入口
2. 当背包空间不足时，保持“能拿先拿，剩余留在容器并返回背包满”

---

## 2. 根因判断

当前服务端存在两条不同的“容器入包”链路：

- `C2M_ContainerTakeAll / C2M_ContainerTakeItem -> ContainerRuntimeHelper.TakeAll / TakeItem -> ItemHelper.AddItem`
- `C2M_ContainerMoveItem -> ContainerRuntimeHelper.MoveContainerToBag`

首轮修复前，`ItemHelper.AddItem` 的新建物品逻辑仍基于旧的一维 `FindEmptySlot()`：

- 只判断某个线性槽位是否为空
- 不校验该槽位作为二维锚点时，物品的 `GridWidth / GridHeight` 是否能在当前背包布局里合法放下

2026-03-29 首轮修复后，自动入包链路已经改成二维合法找位。

但 2026-03-30 实机回归确认，`MoveContainerToBag` 仍有三处老问题：

- 只判断 `targetSlot < Capacity`，没有校验目标槽位作为二维锚点是否合法
- 新建背包物品时直接沿用容器侧原始 `ConfigId`，没有归一旧配置 `10001~10012 -> 22001~22012`
- 直接 `CreateBagItem` 时没有写入正确 `GridWidth / GridHeight`，客户端会收到错误尺寸

而当前局内背包显示与拖拽已经升级为二维格子语义：

- 客户端 `SearchPanel` 渲染会按二维占位合法性摆放物品
- 手动拖拽容器到背包走的是明确目标槽位逻辑，会天然满足二维合法锚点约束

因此现在会出现两类错误数据：

- 自动入包时：服务端认为“找到了空槽，已成功入包”
- 客户端收到 `M2C_UpdateItem` 后，因该锚点的二维占位非法而无法正常渲染
- 容器侧物品已移除，于是表现为“物品消失，没有进背包”

以及：

- 手动拖拽入包时：服务端对非法二维锚点仍返回成功
- 旧配置容器物品会以原始 `ConfigId` 和默认 `1x1` 直接写进背包
- 客户端表现与真实物品尺寸不一致，继续制造“看起来进了，实际布局错了”的脏数据

2026-03-30 第三轮现场日志继续确认，本次用户手上的现场还有一层新根因，不是第二轮服务端二维修复继续失效，而是本局 live unit 根本没有背包：

- 客户端 `C2G_ConfirmLoadout` 上报的是 `BackpackConfigId=0, BagWidth=0, BagHeight=0`
- Gate -> Map 的 `LoadoutRuntimeSync` 同步到 live unit 时也是 `bag=0x0`
- 后续打开背包时，`M2C_SyncBagData` 返回 `Capacity=0, Width=0, Height=0`
- 用户点击一键拾取或拖拽容器物品时，服务端 `ItemHelper.AddItem` 会稳定报 `bag is full`

这与当前设计文档和服务端确认起装实现是一致的：

- 设计允许“空背包进图”
- 当没有装备背包时，局内背包容量就是 `0`

因此第三轮不调整服务端规则。用户明确选择保留“空背包可进图”语义，只补客户端提示，避免再把“没有背包导致无法入包”误判成“拾取链路失效”。

---

## 3. 修复目标

1. 一键拾取、单件拾取、手动拖拽容器到背包，三条链路都必须和当前二维背包规则一致
2. 多格物品只能落到合法二维锚点
3. 已能合法放入的物品继续入包；不能放入的物品保留在容器
4. 返回值继续沿用现有语义：部分成功时返回 `ERR_ECAContainerBagFull`
5. 容器物品入包时必须统一归一旧配置 ID，并写入真实 `GridWidth / GridHeight`
6. 修复尽量下沉到通用物品/背包层，避免后续其他自动入包入口重复踩坑

## 4. 技术方案

### 4.1 在 `cn.etetet.item` 下沉二维找位能力

文件：
`Packages/cn.etetet.item/Scripts/Model/Share/LoadoutGridPlacementHelper.cs`

补充共享二维锚点查找能力：

- 基于现有 `GridPlacementItemInfo` 和 `ArePlacementsValid`
- 给定当前背包已有摆放、背包宽高、目标物品宽高
- 从左上到右下扫描第一个合法锚点

这样高层玩法不需要各自复制一份二维找位算法。

### 4.2 在 `ItemHelper.AddItem` 改成二维合法入包

文件：
`Packages/cn.etetet.item/Scripts/Hotfix/Server/ItemHelper.cs`

调整新建物品堆时的找位逻辑：

- 保留原有“先尝试堆叠已有同类物品”的行为
- 对于必须新建的新物品，不再调用一维 `FindEmptySlot()`
- 改为根据当前 `ItemComponent` 的实际物品列表和背包宽高，寻找合法二维锚点
- 找不到合法位置时抛出 `bag is full`，维持现有调用方错误处理语义

### 4.3 保持 `ContainerRuntimeHelper.TakeAll` 的部分成功语义

文件：
`Packages/cn.etetet.ecanode/Scripts/Hotfix/Server/ContainerRuntimeHelper.cs`

`TakeAll` 的整体流程不改：

- 每个槽位依次尝试入包
- 成功则移出容器
- 失败则记录 `hasBagFailure`
- 最终容器刷新并向客户端广播
- 返回 `ERR_ECAContainerBagFull` 或 `ERR_Success`

本次只依赖下沉后的二维找位修复，不改它“能拿先拿”的业务语义。

### 4.4 修正 `ContainerRuntimeHelper.MoveContainerToBag` 的旧一维入包语义

文件：
`Packages/cn.etetet.ecanode/Scripts/Hotfix/Server/ContainerRuntimeHelper.cs`

针对手动拖拽容器物品到背包，补上服务端兜底：

- 把容器物品 `ConfigId` 统一归一到当前有效配置
- 读取真实 `GridWidth / GridHeight`
- 目标槽位为空时，校验该槽位是否是合法二维锚点；不合法则返回 `ERR_ECAContainerBagFull`
- 与背包已有物品交换时，同时校验交换后新进背包物品在目标锚点是否合法
- 创建背包物品时写入归一后的 `ConfigId` 与真实 `GridWidth / GridHeight`

### 4.5 复核 `MoveBagToContainer` / `ItemHelper.MoveItem` 的同类二维风险

文件：
`Packages/cn.etetet.ecanode/Scripts/Hotfix/Server/ContainerRuntimeHelper.cs`
`Packages/cn.etetet.item/Scripts/Hotfix/Server/ItemHelper.cs`

进一步补齐服务端校验：

- `MoveBagToContainer` 在“容器目标槽已有物品，需要换回背包”时，也要校验换回背包的容器物品是否能合法落到源锚点
- `ItemHelper.MoveItem` 补服务端二维合法落点/交换校验，避免客户端漏校验或恶意请求把非法锚点写进背包

### 4.6 空背包场景补客户端提示，不改服务端规则

文件：
`Packages/cn.etetet.statesync/Scripts/HotfixView/Client/YIUISystem/Main/SearchPanelComponentSystem.cs`

第三轮只补客户端提示层，不改“空背包可进图”的既有规则：

- 一键拾取入口 `TakeQualifiedItems` 在发请求前先判断当前是否确实有可用背包
- 如果当前 `LoadoutComponent / ItemComponent` 都表明背包不可用，直接弹 `TipsTextViewComponent`
- 拖拽到背包区时，若 UI 命中了背包面板，但实际上没有任何可映射的真实背包槽位，也立即提示，而不是静默返回

这样可以覆盖两类最容易误判的操作：

- 点击“一键拾取”但局内没装备背包
- 把容器物品拖到背包区域，但 live unit 实际容量为 `0`
