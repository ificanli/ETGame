# BUG-009-匹配机器人无法攻击怪物修复方案

**创建时间**：2026-03-30  
**最后更新**：2026-03-30  
**状态**：已完成  
**关联任务**：M0.2-W2 #11  
**涉及包**：cn.etetet.btnode, cn.etetet.statesync

## 需求概述

匹配机器人当前已经能正常生成、挂载 `300011` AI、初始化武器和自动开火 Buff，但在实机中出现“机器人看得到怪物、会移动控距、却始终不开火”的问题。  
本次修复目标有两部分：

1. 确认现有 AI 机器人文档是否存在，并在修复完成后把真实行为补回文档。
2. 修复匹配机器人对怪物的攻击链路，保证机器人能够稳定选中怪物并在武器射程内开火。

## 技术方案

### 整体思路

现有问题不是单点失效，而是三段链路对“攻击距离”的理解不一致：

1. `AI_RobotWeaponCombatCheck` 以 `18m` 搜索战斗目标，并把结果写入 `TargetComponent`。
2. 自动开火的 `BTWeaponHasTarget` 重新走 `TargetSelectorComponent`，而它的 `MaxRange` 是当前武器射程，导致短射程武器在接敌前就拿不到目标。
3. `AI_RobotWeaponCombat` 的默认控距固定为 `5m~8m`，对 `3m` 近战/霰弹类武器明显过远，机器人会稳定停在自己武器射程外。
4. 自动开火 Buff `200200` 中的 `BTWeaponInRange` 又把射程写死为 `10m`，与运行时武器射程不一致。

修复方案：

1. `BTWeaponHasTarget` 优先复用 `TargetComponent` 中已经由 AI 选出的目标，避免 AI 目标和武器目标脱节。
2. `BTWeaponInRange` 改为优先使用 `TargetSelectorComponent.MaxRange` 作为实时射程，和当前武器一致。
3. `AI_RobotWeaponCombat` 的理想距离区间改为按当前武器实际射程动态收敛，短射程武器会主动贴近，长射程武器保持现有中距离控距。
4. 回写《怪物与机器人AI行为说明》，把 `300011` 的运行时距离策略更新为“随武器射程动态调整”。

本次不新增 Entity / Component，只调整现有组件的协作方式：

- `TargetSelectorComponent`：继续保存当前武器实时索敌/射程信息。
- `WeaponComponent`：继续提供当前武器有效射程。
