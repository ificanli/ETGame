## 决策记录

### 2026-04-21 - 本轮先做端到端时序埋点，不直接上本地预测切枪

- **背景**：当前已静态确认切枪链路依赖服务端广播确认，但玩家感受到的总延迟里还可能叠加客户端枪模资源加载和视图刷新耗时。
- **方案**：先给 `UIClick -> ClientSend -> ServerRecv -> ServerBroadcast -> ClientRecv -> ClientApply -> UIRefresh -> ViewRefreshDone` 整条链路加统一日志，再根据真实耗时决定是否进入“客户端本地预测切枪”方案。
- **原因**：如果不先拆时序，直接改成本地预测，很容易把“网络慢”和“本地视图慢”两类问题混在一起，后续回归会失去判断基准。
- **替代方案**：直接把客户端点击改成立即本地切槽。放弃原因是当前还没有证据证明主要瓶颈只在服务器，盲改会把诊断窗口关闭。

### 2026-04-21 - 射击先补时序日志，不直接改成本地预测开火

- **背景**：你追加反馈“射击本身也有延迟”，而现有 `WeaponFireTrace` 只有离散日志点，无法像切枪一样直接量化服务端确认与客户端表现耗时。
- **方案**：在 `BTWeaponCanFireHandler`、`BTWeaponFireHandler` 和 `M2C_WeaponFireHandler` 补 `serverNow / clientNow` 时序日志，统一成 `ServerCanFireReady/Blocked -> ServerFire -> ServerSend -> ClientRecv -> ClientProjectileLoad -> ClientProjectileDone`。
- **原因**：当前射击表现同样是服务端权威驱动，但没有统一时间点就没法判断究竟是网络回包慢，还是客户端投射物/资源表现慢。
- **替代方案**：直接改成本地预测开火。放弃原因是现在还缺少量化证据，直接改会把“权威慢”和“表现慢”混在一起。

### 2026-04-21 - 切枪直接改成本地预测，不再继续等待权威回包

- **背景**：最新日志里，切枪的服务端处理耗时仍然只有 `1ms`，本地枪模刷新只有 `3ms`，真正的延迟主要卡在 `ClientSend -> ServerRecv` 与 `ServerBroadcast -> ClientApply`。
- **方案**：在客户端切枪入口增加同槽/空槽拦截，并对合法请求先执行本地预测切枪，立即刷新 HUD 和枪模；服务端 `M2C_SwitchWeapon` 后续继续做校正。
- **原因**：日志已经足够证明，等待权威回包本身就是切枪体感卡顿的主因，再继续只看日志没有收益。
- **替代方案**：维持原逻辑，只依赖服务端回包切枪。放弃原因是已知瓶颈明确，无法改善体验。

### 2026-04-21 - 武器栏未选中槽位不再额外染色

- **背景**：切枪改为本地预测后，你继续回归时反馈“切到哪个武器，另一个武器就变成白色”。
- **方案**：保留 `WeaponSelect` 作为当前武器唯一高亮来源，移除“未选中占用槽位”的额外灰白背景染色；空槽与换弹态特殊底色继续保留。
- **原因**：当前 prefab 已拆出 `WeaponBg / WeaponIcon / WeaponSelect` 三层结构，未选中槽位再做背景染色收益很低，反而会让图标观感发白/发灰。
- **替代方案**：继续调整 prefab 或给图标层单独补更多颜色兜底。放弃原因是这次不是资源结构问题，最小修复点就在现有运行时着色逻辑。

### 2026-04-21 - 选中高亮改成真实高亮框，不再使用默认白图

- **背景**：在未选中槽位发白修掉后，你继续反馈“高亮为什么是纯白色”，并明确要走“整个高亮框”的方案。
- **方案**：直接修改 `WeaponItem.prefab` 的 `WeaponSelect`，绑定项目已有选择框 sprite，颜色改成暖金系，并把节点层级调到 `WeaponBg` 与 `WeaponIcon` 之间。
- **原因**：当前白块的根因不是运行时颜色逻辑，而是 `WeaponSelect` 没有 sprite，alpha 拉高后 Unity 会直接铺默认白图；这类问题应优先在 prefab 资源层收口。
- **替代方案**：只改 `WeaponSelect.color` 或继续压低 alpha。放弃原因是没有 sprite 时，不管怎么调颜色，本质上都还是“整块图层”，不是用户要的高亮框。

## 问题日志

### 2026-04-21 - 当前切枪延迟来源至少有两段

- **现象**：点击武器切换按钮后，武器栏高亮、当前槽位与枪模切换都不是立刻完成。
- **原因**：静态代码确认客户端不会本地立即切槽，而是必须等 `M2C_SwitchWeapon`；随后枪模刷新还要走异步视图和 prefab 加载链路。
- **解决**：本轮先补链路日志，把网络确认耗时和客户端视图耗时拆开。

### 2026-04-21 - 最新 `Editor.log` 已能确认切枪主要卡在权威确认链路

- **现象**：最近一段 `WeaponSwitchTrace` 中，`ClientSend(1776738466505) -> ServerRecv(1776738467058)` 约 `553ms`，`ServerBroadcast(1776738467059) -> ClientApply(1776738467524)` 约 `465ms`，而 `ViewRefreshDone.totalCostMs=2`。
- **原因**：最近这次切枪卡顿并不是枪模刷新或 prefab 加载导致，而是请求到服务端、再从服务端广播回客户端这一整段耗时明显偏大。
- **解决**：切枪结论先定为“主要卡在权威确认链路”；射击链路继续补同级别时序日志，下一轮复现时按同样方法量化。

### 2026-04-21 - 最新日志确认射击慢主要是权威回包，且叠加了武器规则因素

- **现象**：本机玩家一段实际开火日志中，`ServerSend(1776739961651) -> ClientRecv(1776739961946)` 约 `295ms`，但 `ClientProjectileDone.totalCostMs=2`；同时 `50001` 多次出现 `ServerCanFireBlocked ... moving=True`，切到 `50003` 后又连续 `HasTarget no target`。
- **原因**：射击表现慢的主要耗时在服务端权威回包，不在客户端投射物实例化；另外自动步枪不能移动射击、冲锋枪射程更短，也会造成“怎么还没打”的体感。
- **解决**：当前先保留射击侧日志结论，不直接改本地预测开火；先把切枪体感问题落地修掉。

### 2026-04-21 - 编译首次失败是文件锁，不是代码错误

- **现象**：第一次执行 `dotnet build ET.sln` 时，`ET.Hotfix.csproj` 报 `CS2012`，提示 `obj\Debug\ET.Hotfix.dll` 正被其他进程占用。
- **原因**：当时本机存在多个 Unity `Compiling...` 进程，热更产物暂时被 Unity 编译链路锁住。
- **解决**：等待占用释放后重试 `dotnet build ET.sln`，第二次编译通过，`0 warning / 0 error`。

### 2026-04-21 - 本轮编译被无关文件阻塞

- **现象**：本轮执行 `dotnet build ET.sln` 时，除 `ET.Model.dll` 被 Unity / `VBCSCompiler` 临时占用外，还出现了与本次武器改动无关的编译错误。
- **原因**：当前工程里已有其他文件处于不可编译状态，包括：
- `Packages/cn.etetet.statesync/Scripts/HotfixView/Client/YIUISystem/Main/MainPanelComponentSystem_LevelUpToast.cs`
  缺少 `CanvasGroup.DOFade` / `RectTransform.DOAnchorPos` 可用扩展。
- `Packages/cn.etetet.statesync/Scripts/HotfixView/Client/M2C_RogueLevelUp_FeedbackHandler.cs`
  触发 ET 分析器 `ETAE001`，原因是 `await` 后继续访问 `resourcesLoader`。
- **解决**：先明确这些错误不来自本次武器改动，再把本轮切枪预测改动和日志结论回写文档，避免把“构建失败”误记为当前修复逻辑本身出错。
- **替代方案**：顺手修复无关文件。放弃原因是这些不是本次任务引入的改动，且可能覆盖用户正在处理的其他工作。

### 2026-04-21 - 武器栏 UI 修正后整仓编译复验通过

- **现象**：在收口“未选中武器槽位发白”后，需要确认这次 UI 调整没有引入新的编译问题。
- **原因**：当前 `WeaponItemComponentSystem.cs` 处在武器切换日志、本地预测切枪和图标刷新逻辑的交汇点，必须重新跑一次整仓验证。
- **解决**：再次执行项目规定的唯一编译命令 `dotnet build ET.sln`，当前已通过，`0 warning / 0 error`。

### 2026-04-21 - 武器栏未选中槽位发白

- **现象**：切到某个武器后，另一个武器槽位视觉上会变白/泛灰，像被洗掉颜色。
- **原因**：`WeaponItemComponentSystem.RefreshBackgroundColor(...)` 会对“未选中但有武器”的槽位继续做背景灰化；在当前 prefab 观感下，这个染色会把未选中槽位显得发白。
- **解决**：未选中占用槽位恢复为正常背景，仅保留 `WeaponSelect` 负责当前武器高亮；同时把未选中时 `WeaponSelect` 的 alpha 收口到 `0`，避免残余覆盖感。

### 2026-04-21 - 武器栏选中高亮显示成纯白块

- **现象**：当前武器的高亮不是边框，而是一整块纯白色覆盖在槽位上。
- **原因**：`WeaponItem.prefab` 的 `WeaponSelect` 节点只有颜色没有 sprite，运行时 `SetSelected(true)` 把 alpha 提到 `1` 后，Unity 直接使用默认白图整块渲染。
- **解决**：给 `WeaponSelect` 绑定项目内已有的选择框 sprite，并把它放到背景和图标之间，只保留“框感”不盖住武器图标。
