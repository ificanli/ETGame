## 决策记录

### 2026-03-31 - BUG 与需求彻底分轨

- **背景**：当前 W1/W2 周计划同时维护需求项和 BUG 项，已经出现 `BUG-003` 编号冲突，继续沿用会导致追踪口径失真。
- **方案**：把 BUG 统一迁移到 `Book/BUG追踪.md`，周计划只保留需求/Feature；对已经被历史文档引用的原任务编号，仅保留迁移映射，不再继续在周计划里维护详情。
- **原因**：这样可以保证 BUG 编号全局唯一，同时不破坏既有修复文档对原周计划序号的历史引用。
- **替代方案**：继续在周计划和 BUG 文档中双写。放弃原因是现状已经出现编号冲突，双写只会继续扩大歧义。

### 2026-03-31 - 等待界面在匹配成功时立即关闭，而不是继续绑在切场完成上

- **背景**：用户给出的真实现象是“匹配成功后界面没隐藏，回 Home 时还能看到”，说明问题时机在匹配成功，而不是单纯在 Home 打开阶段。
- **方案**：`SendMatchRequest` 先等待 `Wait_MatchSuccess` 并立即关闭 `MatchView`，再继续等待 `Wait_SceneChangeFinish` 完成原有进图收尾；同时在 `LobbyPanel.YIUIOpen` 再补一次无动画兜底清理。
- **原因**：这样既满足“匹配成功后立即隐藏”的需求，又能防御历史残留或异常生命周期。
- **替代方案**：只在 `Home` 场景重新打开 `LobbyPanel` 时清理。放弃原因是这只能治残留，不能修正真正错误的关闭时机。

## 问题日志

### 2026-03-31 - 匹配成功信号与等待界面关闭时机脱节

- **现象**：客户端已经收到匹配成功并正常进图，但“匹配中”弹层没有及时关闭，后续回 `Home` 时仍可能残留。
- **原因**：`SendMatchRequest` 只等待 `Wait_SceneChangeFinish`，没有消费 `Wait_MatchSuccess`；`LobbyPanel` 打开时也没有残留清理。
- **解决**：准备把关闭动作前移到 `Wait_MatchSuccess`，并在 `LobbyPanel` 打开时补一次兜底清理。
