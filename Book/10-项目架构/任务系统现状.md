# 任务系统现状

> **文档状态**：2026-03-27 首次整理，基于 `cn.etetet.quest` 当前代码结构审阅。
> 本文只描述当前实现现状，不代表方案文档中的完整目标已经落地。

## 1. 模块定位

**包**：`cn.etetet.quest`  
**完成度**：⚠️ 服务端基础实体和接取/提交逻辑已落地，客户端同步与 UI 主链路未闭环

任务系统当前处于“服务端骨架可跑、客户端链路不完整”的状态。

## 2. 当前已实现内容

### 2.1 服务端实体模型

- `QuestComponent` 挂在 `Unit` 上，维护：
  - `FinishedQuests`
  - `QuestObjectives`（按目标类型聚合）
- `Quest` 作为 `QuestComponent` 子 Entity
- `QuestObjective` 作为 `Quest` 子 Entity

当前任务实例结构是：

`Unit -> QuestComponent -> Quest -> QuestObjective`

### 2.2 服务端任务实例创建与提交

- `QuestSystem.Awake`
  - 按 `QuestConfig.ObjectiveIds` 自动创建 `QuestObjective`
- `QuestObjectiveSystem.Awake`
  - 按 `QuestObjectiveConfig.Type` 把目标挂进 `QuestComponent.QuestObjectives`
- `QuestComponentSystem`
  - `GetQuest`
  - `IsPreQuestFinished`
  - `AddQuest`
  - `TrySubmitQuest`
  - `RemoveQuest`
- `QuestHelper`
  - `AddQuest`
  - `SubmitQuest`
  - `GetQuest`
  - `UpdateObjectiveCount`
  - `CanAcceptQuest`

### 2.3 已实现的服务端消息入口

#### 接取任务

- `C2M_AcceptQuestHandler`
  - 从 `QuestConfig` 取任务配置
  - 校验接任务 NPC 是否存在
  - 校验玩家与 NPC 距离
  - 校验是否已接取 / 是否已完成 / 前置任务
  - 调用 `QuestHelper.AddQuest`

#### 提交任务

- `C2M_SubmitQuestHandler`
  - 查当前任务实例
  - 校验提交 NPC 是否存在
  - 校验玩家与 NPC 距离
  - 校验所有目标是否已完成
  - 调用 `QuestHelper.SubmitQuest`

#### 同步与增量消息

- `QuestHelper.AddQuest` 会给自己发送 `M2C_CreateQuest`
- `QuestHelper.SubmitQuest` 会给自己发送 `M2C_UpdateQuest`
- `QuestHelper.UpdateObjectiveCount` 会给自己发送 `M2C_UpdateQuestObjective`
- 服务端也已有 `C2M_SyncQuestDataHandler`
- 服务端有 `C2M_QueryAvailableQuestsHandler` 入口

## 3. 客户端当前落地点

### 3.1 已有内容

- 场景初始化时会在 Client Scene 上添加 `QuestComponent`
- 客户端有 `Quest / QuestObjective` 数据模型
- 已有 `M2C_SyncQuestDataHandler`
  - 可按服务端下发数据重建客户端任务树
- 已有任务相关静态逻辑类：
  - `QuestNPCInteractionEvent`
  - `QuestProgressNotification`

### 3.2 仍是骨架或 TODO 的内容

- 登录后同步任务数据的逻辑仍然是 TODO 注释，没有真正发请求
- `M2C_UpdateQuestObjectiveHandler` 只打印日志，没有真正更新客户端目标
- NPC 对话框 / 任务面板 / 可接任务列表 UI 没有落地
- 新任务可接、任务完成、进度更新提示都还是日志占位

## 4. 当前未闭环的关键问题

### 4.1 登录同步没有真正打通

虽然有 `LoginFinish_InitQuestData` 事件，但内部 `RequestSyncQuestData` 仍是注释代码，因此当前不能认为“登录后一定会自动同步任务状态”。

### 4.2 可接任务查询入口基本是空壳

`C2M_QueryAvailableQuestsHandler` 当前只做了：

- NPCId 判空
- 查 NPC 是否存在

之后没有真正把可接任务结果写回响应。

### 4.3 增量更新链路不完整

- 服务端会发 `M2C_UpdateQuestObjective`
- 客户端 Handler 还没有真正写入数据

这意味着即便服务端目标计数有变化，客户端也未必能正确显示。

### 4.4 UI 没有接上

`UnitClickHelper` 相关链路目前还停留在“检查任务并显示 UI”的注释语义，没有实际任务对话框/任务面板。

### 4.5 包内 README 已过时

`Packages/cn.etetet.quest/README.md` 仍在使用旧的客户端命名描述，和当前实际类结构不一致，容易误导后续维护。

## 5. 测试现状

- 在 `Packages/cn.etetet.test/Scripts/Hotfix/Test/` 下，当前没有看到任务系统专门测试
- 当前不宜认定为“已形成稳定回归覆盖”

## 6. 当前判断

- **可以认为已实现的部分**：服务端任务实例结构、接取/提交校验、任务目标实体组织
- **不能认为已完成的部分**：登录同步、可接任务查询、增量目标同步、客户端 UI
- **结论**：任务系统当前应归类为“服务端骨架已具备，但客户端主链路未闭环”
