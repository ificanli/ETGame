# 家园系统现状

> **文档状态**：2026-03-27 首次整理，基于 `cn.etetet.home`、`cn.etetet.map` 以及现有测试代码审阅。
> 本文区分“已实现的运行时能力”和“方案/Proto 已定义但尚未接通的部分”。

## 1. 模块定位

**包**：`cn.etetet.home`  
**完成度**：⚠️ 服务端运行时模型与 Helper 已有，私有 Home 进入链路和服务端测试存在，网络消息与客户端 UI 仍未闭环

## 2. 当前已实现内容

### 2.1 Home 私有副本基础

- `Home` 私有副本链路已经存在
- 玩家进图时，`M2M_UnitTransferRequestHandler` 会在：
  - `unit.UnitType == Player`
  - `mapName == "Home"`
  
  的条件下调用 `HomeEnterHelper.OnEnterHome(unit)`

### 2.2 进入 Home 时的服务端初始化

`HomeEnterHelper.OnEnterHome` 当前会：

- 检查 `PlayerHomeComponent` 是否已存在
- 首次进入时为玩家 `Unit` 创建 `PlayerHomeComponent`
- 初始化：
  - `HomeVersion = 1`
  - `LastSettleTime = ServerNow`

### 2.3 当前服务端数据模型

#### `PlayerHomeComponent`

挂在 `Unit` 上，当前记录：

- `HomeVersion`
- `LastSettleTime`
- `UnlockedBuildingConfigIds`

#### `HomeBuilding`

挂在 `PlayerHomeComponent` 下，当前记录：

- `ConfigId`
- `Level`
- `State`
- `SlotId`
- `LastCollectTime`
- `LastProductionTime`

#### `HomeProductionComponent`

挂在 `Unit` 上，当前记录：

- `ProductionOrders`

#### `HomeContractComponent`

挂在 `Unit` 上，当前记录：

- `LastRefreshTime`
- `AvailableContracts`
- `ActiveContracts`

### 2.4 当前已实现的服务端 Helper 逻辑

- `HomeBuildHelper.Build`
- `HomeUpgradeHelper.Upgrade`
- `HomeDemolishHelper.Demolish`
- `HomeCollectHelper.Collect`
- `HomeProductionHelper.StartProduction`
- `HomeProductionHelper.CollectProduction`
- `HomeContractHelper.RefreshContracts`
- `HomeContractHelper.AcceptContract`
- `HomeContractHelper.CollectContractReward`

也就是说，**“建造 / 升级 / 拆除 / 收取 / 生产 / 合同”这些服务端逻辑本身并不是空的**。

## 3. Proto 与当前实现关系

`Packages/cn.etetet.home/Proto/Home_C_15600.proto` 已经定义了：

- `M2C_HomeSnapshot`
- `C2M_HomeBuildRequest / M2C_HomeBuildResponse`
- `C2M_HomeUpgradeRequest / M2C_HomeUpgradeResponse`
- `C2M_HomeDemolishRequest / M2C_HomeDemolishResponse`
- `C2M_HomeCollectRequest / M2C_HomeCollectResponse`
- `C2M_HomeStartProductionRequest / M2C_HomeStartProductionResponse`
- `C2M_HomeCollectProductionRequest / M2C_HomeCollectProductionResponse`
- `C2M_HomeAcceptContractRequest / M2C_HomeAcceptContractResponse`
- `C2M_HomeCollectContractRewardRequest / M2C_HomeCollectContractRewardResponse`
- `M2C_HomeContractsChanged`

但当前要特别区分：

- **Proto 已定义**
- **消息 Handler 已真正接通**

这两件事在家园模块里目前并不等价。

## 4. 当前没有接通的部分

### 4.1 进入 Home 时只初始化了 `PlayerHomeComponent`

当前 `HomeEnterHelper.OnEnterHome` 没有同步初始化：

- `HomeProductionComponent`
- `HomeContractComponent`

但生产和合同 Helper 又依赖这两个组件，因此当前链路是断开的。

### 4.2 消息处理器目录是空的

当前目录：

- `Scripts/Hotfix/Server/Handler/`
- `Scripts/Hotfix/Client/Handler/`

没有看到实际处理器文件。

这意味着：

- Proto 已定义
- 服务端 Helper 已存在
- 但“客户端请求 -> 服务端 Handler -> 响应/推送”这条链路没有真正落地

### 4.3 客户端/UI 仍停留在计划文档

`Packages/cn.etetet.home/Doc/home-ui-plan.md` 已经把很多客户端组件、Handler、View、YIUI 结构写出来了，但当前代码里还没有对应的大部分文件落地。

当前更准确的说法应该是：

- **UI 方案已写**
- **客户端实现未接完**

而不是“家园客户端已具备完整 UI”

### 4.4 参数大量硬编码

当前 Helper 中可见的硬编码包括：

- 被动产出物品和速率
- 最小收取间隔
- 生产时长、默认产物
- 合同数量、有效期、奖励、目标值
- 建筑最大等级

因此当前家园更接近“服务端玩法样机”，不是正式配置化系统。

## 5. 测试现状

家园模块当前是这 5 个补文档模块里测试相对最完整的一个。

`Packages/cn.etetet.test/Scripts/Hotfix/Test/` 下可以看到：

- `Test_Home_EnterLoad_Test`
- `Test_Home_Build_Test`
- `Test_Home_Collect_Test`
- `Test_Home_Production_Test`
- `Test_Home_Upgrade_Test`
- `Test_Home_Demolish_Test`
- `Test_Home_Contract_Test`
- `Test_Home_MapIdEqualsPlayerId_Test`
- `Test_Home_TwoPlayers_Isolated_Test`

但需要注意，这些测试当前主要验证的是：

- 私有副本隔离
- 服务端组件挂载
- 服务端 Helper 与数据结构

并不是在验证完整的客户端消息链路和 UI。

## 6. 当前判断

- **可以认为已实现的部分**：Home 私有副本进入、服务端数据模型、服务端 Helper、基础自动化测试
- **不能认为已完成的部分**：消息 Handler、快照/推送链路、客户端缓存组件、Home 面板 UI、配置化
- **结论**：家园系统当前应归类为“服务端样机与测试基础已有，网络和客户端闭环未完成”
