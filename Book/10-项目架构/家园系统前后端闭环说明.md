# 家园系统前后端闭环说明

**关联模块**：`cn.etetet.home`、`cn.etetet.map`  
**关联文档**：[家园系统现状.md](家园系统现状.md)  
**目的**：补齐家园系统从进 Home、服务端数据、协议定义到客户端 UI 的真实闭环说明。  
**说明**：本文只记录当前工程里的真实链路，不把 Proto 或方案文档等同于“已经做完的功能”。

## 1. 当前真正接通的入口

### 1.1 进入 Home 地图

入口：`M2M_UnitTransferRequestHandler`

当前地图侧在玩家切图进入 `Home` 时，会做这几件事：

1. 把 `Unit` 挂进当前 `Map` 场景。
2. 执行 `MapUnitEnterHelper` 的通用地图运行时初始化。
3. 当 `mapName == "Home"` 时，调用 `HomeEnterHelper.OnEnterHome(unit)`。

### 1.2 Home 侧初始化

入口：`HomeEnterHelper.OnEnterHome`

当前这段逻辑只会：

1. 检查玩家身上是否已有 `PlayerHomeComponent`。
2. 如果没有，则创建一个默认的 `PlayerHomeComponent`。
3. 初始化：
   - `HomeVersion = 1`
   - `LastSettleTime = TimeInfo.Instance.ServerNow()`

注意：这里不会自动创建下面两个组件：

- `HomeProductionComponent`
- `HomeContractComponent`

所以“进入 Home 就自动拥有完整家园快照”这件事，在当前实现里并不存在。

### 1.3 客户端进入 Home 后的表现

入口：`SceneChangeFinishEvent_CreateUIHelp`

客户端切到 `Home` 后会：

1. 等待 `2000ms`
2. 补挂 `LoadoutComponent`
3. 打开 `LobbyPanel`
4. 如有结算，则再尝试打开 `SettlementPanel`
5. 关闭 `LoadingPanel`

这里没有专门的家园 UI 打开逻辑，也没有家园数据同步逻辑。

## 2. 服务端当前已经具备的样机能力

虽然没有完整网络闭环，但服务端侧已经存在一批 Helper 和模型：

- `HomeBuildHelper`
- `HomeUpgradeHelper`
- `HomeDemolishHelper`
- `HomeCollectHelper`
- `HomeProductionHelper`
- `HomeContractHelper`

以及这些数据模型/系统：

- `PlayerHomeComponent`
- `HomeBuilding`
- `HomeProductionComponent`
- `HomeContractComponent`

这说明家园系统当前更接近“服务端样机能力和数据结构已搭好”，而不是“客户端已经能完整操作家园”。

## 3. Proto 已有，但网络闭环没有接通

`Home_C_15600.proto` 当前已经定义了：

- `M2C_HomeSnapshot`
- 建造/升级/拆除/收取
- 开始生产/收取生产
- 接受合同/领取合同奖励
- `M2C_HomeContractsChanged`

也就是说，协议层已经把“家园应该怎么同步和交互”描述出来了。

但当前工程里的实际情况是：

1. `Packages/cn.etetet.home/Scripts/Hotfix/Server/Handler/` 目录只有 `.meta`，没有真正的服务端消息处理器。
2. `Packages/cn.etetet.home/Scripts/Hotfix/Client/Handler/` 目录也只有 `.meta`，没有真正的客户端消息处理器。
3. 进入 Home 时没有地方发送 `M2C_HomeSnapshot`。
4. 客户端也没有地方消费这些消息并刷新家园界面。

因此 Proto 只能说明“消息格式已设计出来”，不能说明“前后端已经闭环”。

## 4. 当前真实闭环判断

| 链路 | 当前状态 | 说明 |
|---|---|---|
| 切图进入 Home | 已接通 | 地图侧能识别 `Home` 并调用 `HomeEnterHelper` |
| 创建基础家园数据 | 部分接通 | 只创建 `PlayerHomeComponent`，不是完整家园快照 |
| 建造/升级/拆除/收取 Helper | 服务端样机可用 | 已有逻辑实现，但未通过网络消息对外暴露 |
| 生产/合同数据 | 服务端能力存在 | 组件与 Helper 存在，但进入 Home 时不会自动初始化 |
| `M2C_HomeSnapshot` 首次同步 | 未接通 | 没有发送入口 |
| `C2M_Home*` 请求处理 | 未接通 | 没有服务端 Handler |
| 客户端家园消息处理 | 未接通 | 没有客户端 Handler |
| 家园专属 UI | 未接通 | 当前进入 Home 只打开 `LobbyPanel` |

## 5. 现有测试覆盖到哪一层

当前 `cn.etetet.test` 包里已经有这些家园测试：

- `Test_Home_Build_Test`
- `Test_Home_Upgrade_Test`
- `Test_Home_Demolish_Test`
- `Test_Home_Collect_Test`
- `Test_Home_Production_Test`
- `Test_Home_Contract_Test`
- `Test_Home_EnterLoad_Test`
- `Test_Home_TwoPlayers_Isolated_Test`
- `Test_Home_MapIdEqualsPlayerId_Test`

这些测试说明：

1. 服务端 Helper、私有 Home 地图、玩家隔离这些基础能力已经有验证。
2. 但它们不等于“客户端按钮点一下就能完整收发协议并刷新 UI”。

## 6. 对任务 4 的文档结论

家园系统现状文档已经说明它是“服务端样机与测试基础已有，网络和客户端闭环未完成”；本文进一步把断点落到了更具体的位置：

1. 进入 Home 只会创建最基础的 `PlayerHomeComponent`。
2. Proto 虽然完整，但 `Handler` 目录实际上还没接通。
3. 客户端目前只有进 Home 后打开 `LobbyPanel` 的通用逻辑，还没有家园专属链路。

因此当前家园系统不能被描述成“已有完整前后端闭环”，更准确的说法仍然是“服务端样机能力存在，协议和客户端闭环未接通”。
