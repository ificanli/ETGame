## 决策记录

### 2026-04-13 - 不再沿用旧文档中的单一根因结论

- **背景**：仓库里已有《匹配卡住问题排查与修复》旧稿，但其中记录的 `HomeStorage` Gate handler 类型问题已经在当前代码中修复。
- **方案**：保留原问题上下文，但将设计文档整体改写为当前有效版本，明确现阶段真正要处理的是匹配成功后的服务端转图问题。
- **原因**：继续以过期文档指导修复，容易把工作引向已经解决的路径。
- **替代方案**：新建第二份平行文档。已放弃，因为会让同一问题出现两份设计口径。

### 2026-04-13 - 匹配转图失败后改走 GateMap 临时重建兜底

- **背景**：当前现场症状是匹配成功后客户端一直等不到切场，旧的 UI 修复和 `HomeStorage` handler 修复都解释不了这一点。
- **方案**：保留原有 `LocationType.Unit -> 当前地图 Unit -> Transfer` 主链路；主链路失败并重试后，改为在 Gate 上临时创建 `GateMap` Unit，复用正式 `TransferHelper.TransferLock(...)` 直接进目标地图。
- **原因**：这样能在不新开协议的前提下先恢复可玩，同时把登录进 Home 与匹配兜底统一到同一套建 Unit / 转图逻辑。
- **替代方案**：只补 `LocationType.Unit` 清理，不做兜底。已放弃，因为历史脏数据和未来异常转图仍可能继续把玩家卡在匹配态。

### 2026-04-13 - 先统一登录进 Home 与匹配兜底的建 Unit 口径

- **背景**：原 `C2G_EnterMapHandler` 自己内联了一套“临时建 GateMap Unit -> 应用起装 -> Transfer”的逻辑，如果匹配兜底再复制一遍，会形成两套转图实现。
- **方案**：新增 `GateMapTransferHelper`，让 `C2G_EnterMapHandler` 和 `Match2G_MatchSuccessHandler` 共用它。
- **原因**：后续只需维护一套临时 GateMap 转图逻辑，减少再分叉。
- **替代方案**：在 `Match2G_MatchSuccessHandler` 内直接复制 `C2G_EnterMapHandler` 代码。已放弃，因为会放大后续维护成本。

## 问题日志

### 2026-04-13 - 旧 `BUG-012` 修复已落地，但匹配仍然卡住

- **现象**：当前仓库里，`LobbyPanel` 匹配等待窗关闭逻辑和 `HomeStorage` 的 handler 类型修复都已存在，但用户现场依然反馈“点击匹配后卡住”。
- **原因**：问题已经从客户端 UI 层转移到匹配成功后的服务端转图链路。
- **解决**：把本问题从 `Home收取异常与音频缺失临时止血` 中拆出，单独立项处理。

### 2026-04-13 - `LocationType.Unit` 直接销毁路径缺少清理

- **现象**：`TransferHelper` 只在标准跨图时维护 `Lock/UnLock`，但 `G2Map_LogoutHandler` 直接移除玩家 Unit 时没有同步清理 location。
- **原因**：旧 actor 有机会残留在 location 中，后续 Gate 重新按 `LocationType.Unit` 发消息时会命中失效 actor。
- **解决**：在 `G2Map_LogoutHandler` 补 `LocationProxyComponent.Remove(LocationType.Unit, unit.Id)`。

### 2026-04-13 - GateMap helper 首轮编译触发 ETAE001

- **现象**：`dotnet build ET.sln` 首轮失败，分析器报 `GateMapTransferHelper.cs(32,34): ETAE001`，指出 `gateMapComponent` 在 `await` 后被直接访问。
- **原因**：`await gateMapComponent.Create(...)` 之后直接读取了 `gateMapComponent.Fiber.Id`，违反 ET 的 EntityRef 访问规则。
- **解决**：改为先从 `gateMapComponentRef` 重新取回实体，再访问 `Fiber.Id`；第二轮 `dotnet build ET.sln` 已通过。

### 2026-04-13 - 最新日志确认 HomeStorage RPC 被错误发往 GateSession actor

- **现象**：最新 `Editor.log` 里，玩家登录进 `Home` 时出现 `actor sender timeout: ET.Map2G_HomeStorageSummaryRequest`，并进一步导致 `M2M_UnitTransferResponse Error: 100001002`。
- **原因**：`HomeStorageGateHelper` 使用 `UnitGateInfoComponent.ActorId` 发 RPC；该 actor 实际绑定的是 `PlayerSessionComponent`，其 mailbox 类型 `GateSession` 只转发消息给客户端 Session，不会分发给 `MessageLocationHandler<Player,...>`。
- **解决**：给 `Player` 本体补 `MailBoxComponent(MailBoxType.UnOrderedMessage)`，同时为 `UnitGateInfoComponent` 增加 `PlayerActorId`；所有 `Map2G_*` 服务端消息统一改走 `PlayerActorId`。
