# 成就系统现状

> **文档状态**：2026-03-27 首次整理，基于 `cn.etetet.achievement` 当前代码结构审阅。
> 本文只描述“当前实现到哪里”，不等同于原始设计目标。

## 1. 模块定位

**包**：`cn.etetet.achievement`  
**完成度**：⚠️ 已有服务端实体、事件推进和查询/领取 RPC，主链路尚未真正接入游戏流程

成就模块当前更接近“代码骨架 + 查询接口 + 进度事件处理器”，而不是已经对玩家真正开放的完整功能。

## 2. 当前已实现内容

### 2.1 服务端数据结构

- `AchievementComponent` 挂在 `Unit` 上，维护：
  - `CompletedAchievements`
  - `ClaimedAchievements`
  - `ActiveAchievements`
  - `AchievementProgress`
  - `TypeMapping`
  - `TotalPoints / EarnedPoints`
  - `RecentAchievements`
- `Achievement` 作为子 Entity，已经具备：
  - `ConfigId`
  - `Status`
  - `Type`
  - `Progress / MaxProgress`
  - `Points`
  - `PreAchievementIds`
  - `RewardIds`
  - `CategoryId`
  - `IsHidden`
  - `CompleteTime / ClaimTime`
  - `ConditionParams`

### 2.2 服务端运行时逻辑

- `AchievementComponentSystem` 已有以下基础能力：
  - `AddAchievement`
  - `GetAchievement`
  - `UpdateAchievementProgress`
  - `CompleteAchievement`
  - `ClaimAchievementReward`
  - `GetAchievementList`
  - `GetAchievementStats`
- 已定义成就相关事件结构：
  - 进度更新
  - 成就完成
  - 奖励领取
  - 击杀怪物
  - 等级提升
  - 任务完成
  - 道具收集
  - 地图探索
- 已有 5 类服务端事件处理器：
  - 击杀怪物
  - 等级提升
  - 任务完成
  - 道具收集
  - 地图探索

这些处理器会遍历 `ActiveAchievements`，按 `AchievementType` 更新进度，并在达到上限时转为完成状态。

### 2.3 协议与查询入口

服务端已经实现以下查询/领取入口：

- `C2M_GetAchievements`
- `C2M_GetAchievementStats`
- `C2M_GetAchievementDetail`
- `C2M_GetAchievementCategories`
- `C2M_ClaimAchievement`

客户端当前已有 `ClientAchievementHelper`，可直接发起上述 RPC 调用。

## 3. 当前没有闭环的部分

### 3.1 没看到主链路接入入口

当前代码里没有看到稳定的“玩家进入游戏时自动挂载并初始化成就组件”的入口，因此：

- `AchievementComponent` 很可能不会自然出现在玩家 `Unit` 上
- `Initialize()` 也没有实际调用链
- 即便事件处理器存在，也可能没有运行对象可更新

### 3.2 配置驱动尚未接通

以下逻辑仍是明确 TODO：

- 从配置表加载成就数据
- 激活符合条件的成就
- 根据配置生成奖励
- 根据配置生成分类名、图标、详情文案

`AchievementSystem.Awake`、`ActivateEligibleAchievements`、`GrantAchievementReward` 目前都还没有真正接配置。

### 3.3 领取奖励仍是占位

- `ClaimAchievementReward` 会修改状态和点数
- 但真实奖励发放逻辑还没有接到背包/奖励系统
- `C2M_ClaimAchievement_Handler` 当前直接构造了一个模拟奖励：
  - `Type = 1`
  - `Count = 100`

所以当前“领取奖励成功”更多是协议层占位，不是完整业务闭环。

### 3.4 详情与分类仍是占位文案

- 成就详情名字目前是 `Achievement {id}`
- 描述是固定占位字符串
- 图标是固定 `achievement_icon`
- 分类名和分类图标也是代码里手写的默认映射

这意味着“列表/详情可查”不等于“配置化内容已完成”。

### 3.5 客户端未真正落地

当前客户端可确认的内容只有：

- Proto
- 客户端数据模型
- `ClientAchievementHelper`

当前未看到：

- 场景初始化挂载
- 成就缓存同步 Handler
- `M2C_AchievementProgress / M2C_AchievementComplete` 的客户端处理
- 成就面板、View、YIUI 或 HotfixView 落地

## 4. 测试现状

- 在 `Packages/cn.etetet.test/Scripts/Hotfix/Test/` 下，当前没有看到成就模块专门测试
- 因此当前状态主要依赖静态代码判断，不宜认定为“已回归通过”

## 5. 当前判断

- **可以认为已实现的部分**：服务端数据骨架、进度推进逻辑、查询/领取 RPC 入口
- **不能认为已完成的部分**：组件接入、配置化、真实奖励、客户端缓存与 UI
- **结论**：成就系统当前应归类为“骨架已完成，但尚未接入主链路”
