# 匹配入口战绩 UI 设计文档

## 1. 文档用途
- 这份文档只解决一件事：`战绩` 从哪里进、界面怎么拼、节点怎么摆。
- 目标是让 UI 可以直接对照示意图和节点清单制作 `prefab`。
- 本文只覆盖 V1：`战绩列表 + 单场详情 + 事件时间轴复盘`。
- 当前“回放”定义为事件时间轴复盘，不是逐帧视频回放。

## 2. 设计结论

本期不使用 `Explore` 页签。

入口改为：
- 在 `LobbyPanel.prefab` 的 `MatchPanel` 区域增加一个 `战绩` 按钮。
- 点击 `战绩` 按钮后，打开独立弹层 `BattleRecordPanel`。
- 玩家关闭弹层后，仍停留在 `MatchPanel`，不切一级页签。

这样做的原因：
- `MatchPanel` 是“准备开局”的区域，玩家最容易在这里查看近期战绩。
- 不污染 `EquipPanel`，避免把起装、仓库、财富、战绩全部堆在一个面板里。
- 不占用 `Explore` 预留区域，后续探索玩法仍可单独使用。

## 3. 总体页面关系

### 3.1 入口关系

```text
LobbyPanel
└── MatchPanel
    ├── 模式选择区
    ├── 开始匹配按钮
    └── 战绩按钮  -> 打开 BattleRecordPanel
```

### 3.2 面板关系

```text
LobbyPanel (保持在 Match 页)
    └── 点击“战绩”
            ↓
      BattleRecordPanel (独立弹层)
            ├── 左侧：战绩列表
            └── 右侧：战绩详情 + 事件时间轴
```

## 4. 主界面入口设计

## 4.1 放置位置
- 放在 `MatchPanel` 内。
- 与 `开始匹配` 按钮同属底部操作区。
- 推荐位置：`开始匹配` 右侧，或者其下方一行并列双按钮。

不建议：
- 不建议把 `战绩` 做成很小的文字链接。
- 不建议把 `战绩` 塞到模式卡片内部。

## 5. 战绩弹层 BattleRecordPanel 设计

## 5.1 弹层定位
- 类型：独立 `Panel`
- 层级：与 `SettlementPanel` 同类，覆盖在大厅之上
- 打开方式：从 `MatchPanel` 点击按钮打开
- 关闭方式：右上角关闭按钮 / 点击遮罩空白 / ESC

推荐命名：
- `BattleRecordPanel.prefab`
- 推荐放在 `Packages/cn.etetet.statesync/Assets/GameRes/YIUI/Common/Prefabs/`

## 5.2 整体布局

采用左右双栏布局：
- 左栏固定宽度，用于战绩列表和筛选

## 5.3 面板分区

### 5.3.1 顶部栏
- 标题：`战绩记录`
- 筛选按钮组：
- `全部`
- `撤离`
- `阵亡`
- `放弃`
- 模式下拉：
- `全部模式`
- `搜打撤`
- `1v1`
- `3v3`
- 右上角关闭按钮

### 5.3.2 左侧列表区
- 纵向滚动
- 默认展示最近 20 场
- 默认选中最近一场
- 支持切换筛选后刷新列表

### 5.3.3 右侧详情区
- 顶部为“本局摘要卡”
- 底部为“事件时间轴复盘”
- 如果没有明细事件，则显示空状态

## 11. Prefab 制作建议

## 11.1 不建议直接改 Lobby 整体结构
- `LobbyPanel.prefab` 只增加一个 `战绩` 按钮事件。
- 战绩内容使用独立 `BattleRecordPanel.prefab`。
- 这样风险最小，不会破坏现有大厅分页逻辑。

## 11.2 BattleRecordPanel 结构建议

```text
BattleRecordPanel
├── Mask
├── Window
│   ├── Header
│   │   ├── TitleText
│   │   ├── FilterGroup
│   │   ├── ModeDropdown
│   │   └── CloseButton
│   ├── LeftPanel
│   │   ├── RecordListScrollView
│   │   │   └── Content
│   │   └── RecordEmptyText
│   └── RightPanel
│       ├── SummaryCard
│       ├── TimelineTitleText
│       ├── TimelineScrollView
│       │   └── Content
│       └── TimelineEmptyText
└── Cache
```

## 11.3 MatchPanel 最小改造
- 只新增：
- `BattleRecordButton`
- `BattleRecordButtonText`

不建议：
- 不建议重做 `MatchPanel` 全布局
- 不建议把战绩内容直接塞进 `MatchPanel` 内部常驻显示

## 13. 制作顺序建议

UI 制作建议按下面顺序做：

1. 先在 `MatchPanel` 补 `战绩` 按钮
2. 新建 `BattleRecordPanel.prefab`
3. 先把弹层外框、左右双栏和空状态搭出来
4. 再做 `RecordItemTemplate`
5. 再做 `TimelineItemTemplate`
6. 最后补筛选条、关闭按钮、选中态和颜色细节

## 14. 本期不做的内容
- 不做逐帧视频回放
- 不做战斗轨迹播放
- 不做伤害明细表
- 不做高级检索
- 不做跨页签嵌套复杂导航

## 15. 最终建议

V1 最稳妥的 UI 方案就是：
- `MatchPanel` 增加一个 `战绩` 按钮
- 点击后打开独立 `BattleRecordPanel`
- `BattleRecordPanel` 采用“左列表 + 右详情时间轴”双栏布局
- 右侧的“回放”只做事件时间轴复盘

这样 UI 成本低、逻辑清晰、后续继续扩展事件类型也不会推翻界面结构。
