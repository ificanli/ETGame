# 360° 旋转摇杆移动异常 — 问题分析与修复方案

**现象：** 持续 360° 旋转摇杆时，出现预测方向错误、停止输入后角色仍继续滑动。

---

## 调用链回顾

每帧 `SyncLocalPredictionState`（`InputSystemComponentSystem.cs` ~199行）执行顺序：

```
1. ResolveLocalConstrainedPrediction  →  NavMesh 约束后的 constrainedDirection / Speed / blocked
2. SetPredictionMotion(inputDirection, speed)                ← 写入 PredictedDirection / PredictedSpeed
3. SetConstrainedPredictionMotion(constrainedDir, ...)      ← 无条件覆盖 PositionPredictionDirection
```

每帧收到服务端位置包时，`ResolveLocalPositionPrediction` 根据服务端实际位移修正预测状态。

---

## 问题一：停止输入后角色仍在滑动（根本原因）

**文件：** `GameObjectComponentSystem.cs` ~576行

```csharp
private static void UpdatePredictionTarget(this UnitViewInterpolationComponent self)
{
    // PredictionCorrectionSpeedRatio = 0.3f
    float correctionSpeed = self.PredictedSpeed * PredictionCorrectionSpeedRatio;
    self.VisualCorrection = Vector3.MoveTowards(self.VisualCorrection, Vector3.zero, correctionSpeed * Time.deltaTime);
    self.TargetPosition = self.BuildPredictionTarget();
}
```

**触发路径：**

1. 360° 旋转期间频繁碰墙，`SetConstrainedPredictionMotion`（~438行）blocked=true 时执行：

```csharp
self.VisualCorrection += self.PredictedDelta;  // 各方向预测误差累积进 VisualCorrection
self.PredictedDelta = Vector3.zero;
```

圆周运动各方向的预测误差不能完全抵消，`VisualCorrection` 积累出净偏移量。

2. 松开摇杆后：`PredictedSpeed → 0` → `correctionSpeed → 0` → `MoveTowards` 步长为 0 → **`VisualCorrection` 永久冻结，永不归零。**

3. 最终表现：`TargetPosition = AuthoritativePosition + PredictedDelta + VisualCorrection`，`VisualCorrection` 有残余偏移，角色视觉位置持续偏离权威位置，看起来像「停止后还在滑」。

---

## 问题二：VisualCorrection 累积量过大

`MaxPredictionCorrectionDistance = 5f`，上限过宽。

360° 旋转期间多次 blocked，每次将 `PredictedDelta` 转入 `VisualCorrection`，理论上可以积累到 5 个单位的偏移。正常直线撞墙不会有此问题，但圆周运动会逐步积累。

---

## 问题三：AdvancePrediction 中旋转朝向基于原始输入，非约束方向

**文件：** `GameObjectComponentSystem.cs` ~556行

```csharp
if (self.PredictedDirection.sqrMagnitude > 0.000001f)
{
    unit.Rotation = quaternion.LookRotation((float3)self.PredictedDirection, math.up());
}
```

`PredictedDirection` 是原始摇杆输入方向，`PositionPredictionDirection` 才是 NavMesh 约束后的实际移动方向。

旋转摇杆时两者频繁不一致，导致角色**朝向与实际移动方向不匹配**，视觉上看起来像「预测方向错误」。

---

## 修复方案

### 修复1（必修）：`correctionSpeed` 设置最低保底值

**文件：** `GameObjectComponentSystem.cs` ~576行

```csharp
// 修改前
float correctionSpeed = self.PredictedSpeed * PredictionCorrectionSpeedRatio;

// 修改后
const float MinCorrectionSpeed = 2f;  // 停止输入后仍以 2 单位/秒归零 VisualCorrection
float correctionSpeed = Mathf.Max(self.PredictedSpeed * PredictionCorrectionSpeedRatio, MinCorrectionSpeed);
```

**效果：** 无论是否有输入，`VisualCorrection` 始终以至少 2 单位/秒的速度归零，停止输入后约 0.5~2.5 秒内偏移完全消退，滑动感消失。

**副作用评估：** 正常移动时 `PredictedSpeed * 0.3` 通常大于 2f（角色速度 >6.7 单位/秒），保底值不介入。仅在极低速或停止时生效，对正常移动手感无影响。

---

### 修复2（建议）：缩小 `MaxPredictionCorrectionDistance`

**文件：** `GameObjectComponentSystem.cs` ~262行（常量定义区）

```csharp
// 修改前
private const float MaxPredictionCorrectionDistance = 5f;

// 修改后
private const float MaxPredictionCorrectionDistance = 1.5f;
```

**效果：** 限制 `VisualCorrection` 最大积累量，即使修复1未生效，角色最多偏离 1.5 单位，配合修复1后归零更快。

**副作用评估：** 高延迟时（>200ms）服务端纠偏幅度被缩小，可能出现轻微位置跳变。如果服务器帧率稳定（<100ms 延迟），1.5f 足够，可视情况调整为 2f。

---

### 修复3（可选）：`AdvancePrediction` 中朝向使用约束方向

**文件：** `GameObjectComponentSystem.cs` ~556行

```csharp
// 修改前
if (self.PredictedDirection.sqrMagnitude > 0.000001f)
{
    unit.Rotation = quaternion.LookRotation((float3)self.PredictedDirection, math.up());
}

// 修改后
Vector3 facingDirection = self.PositionPredictionDirection.sqrMagnitude > 0.000001f
    ? self.PositionPredictionDirection
    : self.PredictedDirection;
if (facingDirection.sqrMagnitude > 0.000001f)
{
    unit.Rotation = quaternion.LookRotation((float3)facingDirection, math.up());
}
```

**效果：** 优先使用 NavMesh 约束后的实际移动方向作为朝向，旋转摇杆时不再出现朝向与移动方向错误不一致的问题。

**副作用评估：** 贴墙滑动时朝向会跟着约束方向变化，而不是跟摇杆方向。取决于游戏设计意图——如果希望朝向始终跟摇杆走（如 twin-stick shooter），保留原逻辑；如果希望朝向跟移动走，采用此修复。

---

## 优先级建议

| 修复 | 优先级 | 解决问题 |
|------|--------|----------|
| 修复1：correctionSpeed 保底值 | **必修** | 停止输入后滑动 |
| 修复2：缩小 MaxPredictionCorrectionDistance | 建议 | 累积偏移量过大 |
| 修复3：朝向使用约束方向 | 可选 | 旋转时朝向与移动不一致 |
