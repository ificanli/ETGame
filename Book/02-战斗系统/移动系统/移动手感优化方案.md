# 移动手感优化方案：保留防穿墙 + 恢复最佳手感

## 背景

防穿墙功能加入后，移动出现延迟感和输入不匹配问题。需要在保留防穿墙的前提下，把手感恢复到最佳状态。

---

## 防穿墙机制说明

系统有两道防线，互相独立：

### 第一道：客户端本地 NavMesh 约束（实时，无延迟）

```
InputSystemComponentSystem.SyncLocalPredictionState
  → ResolveLocalConstrainedPrediction
  → pathfinding.TryMoveAlongSurface
```

每帧在客户端本地做 NavMesh 检测，玩家输入的当帧就能阻止预测位置穿墙，**不需要等服务端回包**。

### 第二道：服务端 NavMesh 约束（权威，有网络延迟）

```
JoystickMoveComponentSystem.Tick
  → pathfinding.TryMoveAlongSurface
  → unit.Position = nextPos（NavMesh 约束后的权威位置）
  → 通过 M2C_JoystickMove 同步给客户端
```

服务端位置是最终权威，客户端视觉层最终会被修正到服务端权威点附近。

### 客户端视觉层的角色

```
服务端权威位置 (unit.Position)   →  永远在 NavMesh 内
  ↓ ApplyAuthoritativePosition
AuthoritativePosition            →  权威锚点
  ↓ + PredictedDelta + VisualCorrection
TargetPosition                   →  视觉目标点（可能短暂偏离 NavMesh 表面）
  ↓ MoveVisualTowardsTarget
transform.position               →  实际渲染位置
```

客户端修改只影响视觉层平滑方式，**不修改 `unit.Position`（逻辑位置），不存在穿墙风险**。

即使客户端视觉位置在缓动期间短暂偏离 NavMesh 表面，玩家的逻辑位置仍然被第一道防线（本地 NavMesh 约束）限制在合法区域内。

## 问题根源

### 问题1：撞墙时视觉硬切（抖动/闪动）

**文件：** `Packages/cn.etetet.map/Scripts/HotfixView/Client/Unit/GameObjectComponentSystem.cs` ~430行
**函数：** `SetConstrainedPredictionMotion`

```csharp
// 当前问题代码
if (blocked && self.PredictionEnabled)
{
    self.PredictedDelta = Vector3.zero;
    self.VisualCorrection = Vector3.zero;
    self.TargetPosition = self.AuthoritativePosition;  // 直接硬切到服务端权威点
}
```

撞墙时直接把视觉位置强制跳到服务端权威点，造成明显抖动和闪动感。

---

### 问题2：服务端同步时 blocked 路径无缓动

**文件：** `GameObjectComponentSystem.cs` ~357行
**函数：** `ApplyAuthoritativePosition`

```csharp
// 当前问题代码
if (self.PositionPredictionBlocked)
{
    previousVisualTarget = serverPosition;  // 强制从服务端点开始，无任何平滑
}
```

服务端每次同步到来时，只要处于 blocked 状态就直接从 serverPosition 开始，没有任何平滑过渡。

---

### 问题3：blocked 判定过于激进

**文件：** `GameObjectComponentSystem.cs` ~517行
**函数：** `ResolveLocalPositionPrediction`

```csharp
// 当前问题代码
self.PositionPredictionBlocked = expectedMoveDistance > MinAuthoritativePredictionDistance;
```

只要玩家有输入且服务端位置当帧没有变化（包括网络抖动、极短帧率差等），就判定为 blocked，频繁误触发。

---

### 问题4：贴墙滑动角度容忍度过低

**文件：** `Packages/cn.etetet.map/Scripts/HotfixView/Client/InputSystemComponentSystem.cs` ~285行
**函数：** `TryGetAlignedConstrainedMotion`

```csharp
// 当前问题代码
if (directionDot <= 0.001f)  // 输入方向与实际可走方向接近垂直就放弃
{
    constrainedDirection = float3.zero;
    constrainedSpeed = 0f;

}
```

贴墙滑动角度稍大就被判断为 blocked，本来可以继续沿墙滑行的情况被卡死。

## 优化方案

### 修改1：`SetConstrainedPredictionMotion` — blocked 时缓动归零

**文件：** `GameObjectComponentSystem.cs` ~430行

```csharp
// 改后
if (blocked && self.PredictionEnabled)
{
    // 把已有 PredictedDelta 并入 VisualCorrection
    // 由 UpdatePredictionTarget 以 PredictionCorrectionSpeedRatio 速度缓动消除
    self.VisualCorrection += self.PredictedDelta;
    self.PredictedDelta = Vector3.zero;
    // 防止偏移过大
    if (self.VisualCorrection.sqrMagnitude > MaxPredictionCorrectionDistance * MaxPredictionCorrectionDistance)
    {
        self.VisualCorrection = self.VisualCorrection.normalized * MaxPredictionCorrectionDistance;
    }
    // 不强制 TargetPosition，让 UpdatePredictionTarget 自然收敛
}
```

**效果：** 撞墙时视觉位置不再硬切，而是平滑滑回服务端权威点。

---

### 修改2：`ApplyAuthoritativePosition` — blocked 时保留平滑

**文件：** `GameObjectComponentSystem.cs` ~357行

```csharp
// 改后
if (self.PositionPredictionBlocked)
{
    // 不再硬切，用 ClampStationaryPredictionLead 给一点缓冲
    previousVisualTarget = self.ClampStationaryPredictionLead(serverPosition, previousVisualTarget);
}
```

**效果：** 服务端同步到来时，即使处于 blocked 状态，视觉位置也能平滑过渡，不闪烁。

---

### 修改3：`ResolveLocalPositionPrediction` — 保守的 blocked 判定

**文件：** `GameObjectComponentSystem.cs` ~515行
**依赖：** `UnitViewInterpolationComponent` 新增字段 `public int WallBlockedCount;`（同时在 `Awake` 和 `ResetPrediction` 中初始化为 0）

```csharp
// 改后：连续 2 帧服务端静止才触发 blocked
self.PositionPredictionDirection = Vector3.zero;
self.PositionPredictionSpeed = 0f;
if (expectedMoveDistance > MinAuthoritativePredictionDistance)
{
    self.WallBlockedCount++;
    self.PositionPredictionBlocked = self.WallBlockedCount >= 2;
}
else
{
    self.WallBlockedCount = 0;
    self.PositionPredictionBlocked = false;
}
```

同时，在 `authoritativeMoveDistance > MinAuthoritativePredictionDistance` 的分支中重置：
```csharp
self.WallBlockedCount = 0;
```

**效果：** 单帧服务端位置无变化不会立即触发 blocked，避免网络抖动误判。

---

### 修改4：`TryGetAlignedConstrainedMotion` — 放宽滑墙角度

**文件：** `InputSystemComponentSystem.cs` ~285行

```csharp
// 改前
if (directionDot <= 0.001f)

// 改后
if (directionDot <= -0.1f)  // 方向超过约 96° 才放弃，允许近似垂直的贴墙滑动
```

**为什么不会穿墙：** `constrainedNextPos` 是由 `TryMoveAlongSurface` 算出的 NavMesh 合法位置，这里只是判断「这个合法的滑动方向是否值得继续走」，不存在走到非法位置的路径。

**效果：** 玩家以斜角贴墙时，只要不是完全反向就允许继续滑动，改善贴墙走廊手感。

## 验证方法

1. 向墙壁正面走去，观察是否有硬切/抖动
2. 沿着墙壁方向斜角行走，观察是否能贴墙滑动
3. 频繁改变方向，观察是否有延迟感
4. 在网络模拟延迟环境下测试，观察 blocked 状态是否被频繁误触发
5. 查看 `[NavMove]` 日志，确认 `blocked` 状态只在真正撞墙时出现
