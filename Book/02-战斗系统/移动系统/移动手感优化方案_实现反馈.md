### 方案未提及的额外改进

#### HoldLocalPredictionOnStationarySync 机制（~522-531行）

```csharp
bool hasLocalConstrainedMotion = !self.PositionPredictionBlocked &&
    self.PositionPredictionDirection.sqrMagnitude > 0.000001f &&
    self.PositionPredictionSpeed > 0.01f;
if (hasLocalConstrainedMotion)
{
    self.HoldLocalPredictionOnStationarySync = true;
    self.WallBlockedCount = 0;
    ...
    return;
}
```

当服务端静止（authoritativeMoveDistance=0）但本地有有效约束运动时，不判定为 blocked，而是标记 `HoldLocalPredictionOnStationarySync=true`，让 `ApplyAuthoritativePosition` 在 `else` 分支中用 `ClampStationaryPredictionLead` 限制偏移。

**效果：** 贴墙滑动时服务端回包稍慢，不会误触发 blocked，手感更流畅。这是方案的合理延伸，不是问题。

## 潜在问题

### ⚠️ 问题A（无需处理）：SetConstrainedPredictionMotion else 分支清零时机

`blocked=false` 时 `WallBlockedCount=0` 是**预期行为**：本地判定已能滑过，不应再累计 blocked 计数，与修改3配合正确。

**结论：** 无问题。

### ⚠️ 问题B（低风险，可选修复）：ApplyAuthoritativePosition blocked 路径跳过 ClampPredictionTargetToNavmesh

**位置：** ~364行

```csharp
if (self.PositionPredictionBlocked)
{
    previousVisualTarget = self.ClampStationaryPredictionLead(serverPosition, previousVisualTarget);
    // ← 注意：未调用 ClampPredictionTargetToNavmesh
}
else
{
    previousVisualTarget = self.ClampPredictionTargetToNavmesh(unit, previousVisualTarget, serverPosition);
    ...
}
```

`blocked` 时 `previousVisualTarget = AuthoritativePosition + PredictedDelta + VisualCorrection`。
`PredictedDelta` 已被修改1清零，但 `VisualCorrection` 可能仍有残余偏移。
`ClampStationaryPredictionLead` 只限制偏移距离（`speed * 0.12f`，约 0.6~1.2 单位），不做 NavMesh 贴合检测。

**风险：** 极端情况（角色被传送到墙边后立即撞墙）下，`VisualCorrection` 残余值可能让视觉位置短暂偏出 NavMesh 较远。

**严重程度：** 低。视觉位置偏出 NavMesh 不影响逻辑，`VisualCorrection` 会通过 `UpdatePredictionTarget` 缓动归零，且 `MaxPredictionCorrectionDistance=5f` 保底限制。

**可选改进：**
```csharp
if (self.PositionPredictionBlocked)
{
    previousVisualTarget = self.ClampPredictionTargetToNavmesh(unit, previousVisualTarget, serverPosition);
    previousVisualTarget = self.ClampStationaryPredictionLead(serverPosition, previousVisualTarget);
}
```
