# 客户端移动预测与防穿墙方案

## 目标

同时满足以下目标：

1. 本机平地移动保持即时响应与顺滑手感。
2. 本机贴墙时允许滑墙，但绝不穿墙。
3. 服务端继续保持权威位置，客户端只负责即时预测与显示。
4. 快速转向、松手停步时，客户端预测不能把旧输入继续重复消费。

## 旧骨架的问题与价值

旧版本的顺滑移动来自以下链路：

1. 本机输入只更新预测方向和速度。
2. `UnitViewInterpolationComponent` 负责本机视图预测。
3. 服务端 `M2C_JoystickMove` 负责更新权威 `unit.Position`。
4. 视图层通过 `ApplyAuthoritativePosition` 将权威位置与本机预测衔接。

这条骨架的优点是平地顺滑，但单独使用时不能保证“绝不穿墙”，因为客户端预测如果没有墙体约束，视觉上会先冲进墙里，再等待服务端回正。

## 最终方案

采用“三层职责分离”：

1. 本机输入层：
只生成输入方向与输入速度，不直接写本机逻辑位置。

2. 本机预测层：
客户端本地 `TryMoveAlongSurface` 只约束预测显示路径，不改权威 `unit.Position`。
本机看到的即时阻挡、滑墙，来自本地预测层。

3. 服务端权威层：
服务端继续使用 `TryMoveAlongSurface` 生成最终权威位置。
客户端收到 `M2C_JoystickMove` 后，不再只拿当前输入硬拼权威位置，而是通过“服务端已处理输入序号”回执做精确纠偏。

4. 输入回执与重放层：
`M2C_JoystickMove` 带回 `LastProcessedInputSequence`。
客户端保存短窗口输入历史，从权威位置开始只重放“服务端尚未处理”的输入，再继续接当前本地输入做预测。

## 执行链路

### 1. 输入阶段

`InputSystemComponentSystem.SyncLocalPredictionState`

1. 读取输入方向。
2. 如果本机有 `UnitViewInterpolationComponent`，只更新预测运动状态。
3. 使用客户端本地 NavMesh 约束预测移动方向和速度。
4. 不直接写 `unit.Position`。
5. 发送输入时记录 `InputSequence + worldDirection + sendTime + speed` 到本地短历史。

### 2. 本机预测阶段

`UnitViewInterpolationComponentSystem`

1. `PredictedDirection/PredictedSpeed` 表示输入意图。
2. `PositionPredictionDirection/PositionPredictionSpeed` 表示本地约束后的实际预测运动。
3. `AdvancePrediction` 只推进预测显示位置。

### 3. 服务端同步阶段

`M2C_JoystickMoveHandler`

1. 服务端消息始终写入权威 `unit.Position`。
2. 服务端消息额外带回 `LastProcessedInputSequence`，告诉客户端这帧权威结果已经消费到哪一笔输入。
3. 不再用“平地小误差忽略，大误差硬回正”作为本机主链路。

### 4. 权威回灌阶段

`ChangePosition_SyncGameObjectPos`

1. 本机单位收到服务端权威位置后，不直接瞬间同步 `Transform`。
2. 先按 `LastProcessedInputSequence` 丢弃已确认输入。
3. 以服务端权威位置为起点，只重放未确认输入，并走同一套本地 NavMesh 约束。
4. 再把“重放后的预测位移 + 当前本地输入约束结果”喂给 `UnitViewInterpolationComponent`。
5. 这样快速转向时不会把旧方向再次吃一遍，松手时也不会因为尾包继续多走一段。

## 关键原则

1. 逻辑真相只有一份：服务端权威位置。
2. 客户端可以即时预测，但预测只作用于显示层。
3. 客户端本地碰撞用于即时手感，服务端碰撞用于最终裁决。
4. 不能让客户端预测层和服务端权威层同时抢写本机逻辑位置。
5. 客户端纠偏必须基于“服务端已确认到哪笔输入”，不能只基于当前位置和当前摇杆方向猜测。

## 验收标准

1. 平地移动手感恢复到接近旧版本。
2. 贴墙直推时本机不能穿墙。
3. 贴墙斜推时本机可以沿墙滑动。
4. 本机不再频繁瞬移或持续发黏。
5. 快速转向时不再出现“输入一次走两步”或“转一圈又补转一圈”。
