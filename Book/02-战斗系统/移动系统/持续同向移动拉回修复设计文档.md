# 持续同向移动拉回修复设计文档

**创建时间**：2026-03-26
**最后更新**：2026-03-27
**状态**：已完成并通过实机验收
**关联任务**：M0.2-W1 #2
**涉及包**：cn.etetet.map, cn.etetet.statesync

## 需求概述

当前摇杆移动在以下场景仍存在明显手感问题：

1. 玩家朝同一方向持续推动摇杆时，角色会被服务端权威位置周期性拉回。
2. 日志显示服务端持续广播同向移动结果，但客户端每次收到权威包后都会把本地前向预测清零。
3. 用户目标不是“靠阈值掩盖抖动”，而是恢复平地持续移动时客户端预测与服务端结果基本一致的旧手感，同时保持现有“沿墙滑动但绝不穿墙”。
4. 最新日志表明，剩余抖动不只发生在停步或贴墙场景，持续移动阶段也会出现 `targetPos` 跳变与角色抖动。

## 问题定位

最新日志和代码链路复核后，当前剩余问题已经收敛为客户端预测前置量失控：

1. 在没有新权威包到达的间隙，客户端 `AdvancePrediction` 仍会持续累加 `PredictedDelta`。
2. 当累计前置量超过一个合理预测窗后，`targetPos` 会逐步远离 `authPos`。
3. 下一次权威包到达时，客户端 reconcile 会按新的权威位置重建回放结果，`targetPos` 被迫回撤或改向，于是体感上表现为持续移动中的抖动/瞬移。
4. 这段问题日志里大量样本同时满足 `blocked=False`、`hold=False`、`visualCorrection=(0,0,0)`，说明根因不是撞墙缓冲本身，而是客户端预测层内部的前置量管理失衡。

## 目的

本轮修复目标明确如下：

1. 保留“沿墙滑动但绝不穿墙”的现有能力，不回退服务端墙约束。
2. 恢复平地持续同向移动时，客户端预测与服务端结果基本一致的顺滑手感。
3. 杜绝客户端预测在权威包间隙无上限累积，避免持续移动阶段的周期性抖动和回撤。
4. 保持停步、转向、贴墙、离墙恢复等既有场景不被这轮修复破坏。

## 技术方案

### 整体思路

沿用“服务端权威 + 客户端本地 NavMesh 约束预测 + 输入回执回放”的现有骨架，但修正客户端预测前置量的生成和回放边界。

当前实现只会：

1. 以服务端权威位置为起点，回放尚未确认的输入历史。
2. 把回放结果作为新的 `PredictedDelta`。

前几轮修复已经解决了以下问题：

1. 当玩家持续按住同一方向时，当前输入虽然已经被服务端确认，但客户端渲染层仍然需要保留一个短前向 lead。
2. 现实现里一旦“未确认历史输入”为空，`PredictedDelta` 就会在每个权威包到达时被重置为 0。
3. 这会让客户端在“本地前进一小段”与“权威包清零预测”之间反复拉扯，形成持续被拉回的手感。

但最新日志说明，还存在第二层问题：

1. 即使保留了活跃输入 lead，如果 `PredictedDelta` 在权威包间隙继续无限增长，后续权威回放仍然会产生明显回撤和抖动。
2. 因此修复不能只处理“每包清零”，还必须限制“持续增长”和“回放重建”两个阶段的预测前置量。

修复原则：

1. `PendingMoveInputs` 只负责“未确认历史输入回放”。
2. 当前仍在按住的活跃输入，需要在权威回放之后继续保留前向预测 lead。
3. `PredictedDelta` 只表示逻辑回放结果，不再承担“显示层避免后退抖动”的职责。
4. 如果新的回放目标会退到当前 `viewPos` 后方，则把这部分回退量单独放入显示层缓冲，并按可视速度逐步回收。
5. 这个 lead 和缓冲后的目标仍然必须继续走同一套客户端本地 NavMesh 约束，不能绕开碰撞。
6. 停步、撞墙、方向突变、权威显著偏离等场景，仍然允许现有强纠偏逻辑生效。
7. 本轮新增“双层限幅”：
   - 运行中增长限幅：`AdvancePrediction` 对持续累加的 `PredictedDelta` 做上限控制。
   - 权威回放重建限幅：`TryReconcileAuthoritativeMove`、`ClampReplayPredictionPosition`、`ApplyAuthoritativeReplay` 共同限制回放阶段可重建的前置量。

## 实现步骤

1. 根据最新日志确认“持续同向输入时 `PredictedDelta` 被每包清零”和“持续移动阶段 `PredictedDelta` 继续失控增长”的触发条件。
2. 修改客户端 reconcile，使其在回放未确认输入后保留当前活跃输入的前向预测 lead，并继续经过本地 NavMesh 约束。
3. 在 `AdvancePrediction` 中限制运行时增长的预测前置量，避免权威包间隙越积越大。
4. 在 `TryReconcileAuthoritativeMove` 和 `ApplyAuthoritativeReplay` 中限制权威回放可重建的预测前置量。
5. 当新的权威回放目标发生超限重定向时，增加显示层目标限速，杜绝 `targetPos` 单包后退或单包急转向造成的瞬移/抖动。
6. `PendingStopActive` 期间，不再让未确认的旧移动尾包重新推动本地已冻结的停步视图；直到 stop ack 到达前，回放目标都以本地冻结视图为上限。
7. 回归停步、撞墙、贴墙滑动、离墙恢复和持续同向平地移动场景，避免恢复“可穿墙”或“松手尾走”。
8. 执行 `dotnet build ET.sln`，记录编译与验证结果。

## 验收标准

- [x] 持续同向平地移动时，不再出现周期性被拉回
- [x] 权威包到来时，`targetPos` 不再直接退到当前视图后方引发瞬移/抖动
- [x] 停步后不恢复“继续多走一段”的旧问题
- [x] 贴墙滑动仍可沿墙移动，且不穿墙
- [x] 权威明显偏离时仍能纠正，不引入大瞬移
- [x] `dotnet build ET.sln` 通过
