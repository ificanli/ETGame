## 决策记录

### 2026-04-14 - 命中闪白改走通用材质方案

- **背景**：用户反馈怪物受伤没有闪白，但代码里 `M2C_WeaponHitHandler -> HitFeedbackHelper` 已经在调用。
- **方案**：不再依赖 `_HitFlashAmount` / `_HitFlashColor` 这两个工程里无人接入的 shader 属性，改为直接驱动 renderer 的 runtime materials，临时提亮 `_BaseColor` / `_Color` 并拉高 `_EmissionColor`。
- **原因**：现有怪物材质基本都是 URP Lit，直接利用已存在的颜色和 emission 属性，兼容性更高，不需要额外补 shader 资源。
- **替代方案**：继续用 `MaterialPropertyBlock` 写 `_HitFlashAmount`。已放弃，因为当前材质和 shader 根本不识别这两个属性，属于空打。

### 2026-04-14 - 不把命中特效缺失和闪白反馈绑死

- **背景**：排查 `M2C_WeaponHitHandler` 时发现，`weaponConfig.HitEffect` 为空会直接 `return`，导致后面的闪白和缩放也一并不执行。
- **方案**：把命中特效实例化改为可选分支，`HitEffect` 为空只记 warning，但仍继续执行闪白和缩放。
- **原因**：特效资源缺失不应该把基础受击反馈也吃掉，否则现场看到的会是“整条命中反馈都没了”。
- **替代方案**：保持现状，要求所有武器先补齐 `HitEffect`。已放弃，因为这会让表现层基础反馈继续被资源缺口绑死。

### 2026-04-14 - 命中闪白二次收口为“乘算增亮 + emission 叠加”

- **背景**：第一次改成通用材质方案后，用户现场仍反馈“能看到怪物变大一点，但一点颜色都没有”。
- **方案**：把 `_BaseColor / _Color` 的处理从“lerp 到白色”改成“按倍率乘亮”，并且把 `_EmissionColor` 从固定覆盖改成“在原始 emission 上叠加白色 boost”；同时只处理 `SkinnedMeshRenderer / MeshRenderer`。
- **原因**：现有怪物材质这两个颜色乘子大多本来就是纯白 `1,1,1`，继续 lerp 到白色几乎等于无变化；而固定覆盖 emission 会吃掉原材质自带的发光信息。
- **替代方案**：继续调大旧的 lerp 系数或单纯延长时长。已放弃，因为根因不是“强度太小”，而是旧算法对白色底材质天然不敏感。

### 2026-04-14 - 连发停火回落改为客户端本地超时兜底

- **背景**：现场反馈“持枪 idle 和走路是一样的”，顺着 Animator 排查确认玩家实际使用 `HeroBase.controller`，其中连发状态由 `IsFiring` Bool 驱动；代码当前只有开火置 `true` 和换弹清零，正常停火没有回落点。
- **方案**：在 `WeaponViewComponent` 上记录 `RapidFireStopVersion`，连发武器每次开火都刷新版本并启动一个按 `AttackIntervalMs` 计算的短延时；若延时结束后版本未变化，则自动执行 `IsFiring=false`。同时在换弹开始、切枪、卸枪时立即清零并推进版本。
- **原因**：服务端当前没有显式“停火”消息，客户端只能靠最后一发时间兜底；把状态收口在 `WeaponViewComponent` 上，既避免静态全局状态，也能天然按单位隔离。
- **替代方案**：新增服务端停火消息。已放弃，因为改动面更大，这个问题本质上是客户端表现状态缺少回落。

## 问题日志

### 2026-04-14 - 命中反馈逻辑存在但画面无效果

- **现象**：怪物被命中时没有任何闪白表现。
- **原因**：`HitFeedbackHelper` 写入的是 `_HitFlashAmount` / `_HitFlashColor`，但工程里的怪物材质只有 `_BaseColor` / `_Color` / `_EmissionColor`，没有接专用闪白 shader 属性。
- **解决**：将命中闪白改为运行时通用材质方案，并补充文档说明。

### 2026-04-14 - 通用材质方案已执行，但对白色底材质仍几乎无感

- **现象**：用户现场反馈“怪物受击时能看到缩放，但一点颜色都没有”。
- **原因**：当前怪物材质的 `_BaseColor / _Color` 乘子大多已经是纯白 `1,1,1`，所以“继续 lerp 到白色”在数学上几乎是 no-op；而 `_EmissionColor` 原实现又是固定覆盖，部分材质上甚至会削弱原本的发光。
- **解决**：将闪白改成“亮度乘算 + 在原始 emission 上叠加白色 boost”，并收敛到真正的网格 renderer。

### 2026-04-14 - 首版实现被 ET Hotfix 限制拦下

- **现象**：第一次 `dotnet build ET.sln` 报 `ET0004/ET0005/ET0015`，指出 Hotfix 程序集中不能声明普通静态字段和内部状态类。
- **原因**：首版实现为了处理多次命中重入，写了静态字典和内部状态类，不符合 ET 热更分析器约束。
- **解决**：改成纯局部数组实现，不保留任何静态运行时状态；第二次 `dotnet build ET.sln` 已通过。

### 2026-04-14 - 连发武器正常停火后 `IsFiring` 不会自动归零

- **现象**：自动步枪/冲锋枪停止开火后，角色仍停留在 ArmedFire / Run_and_Shoot 分支，持枪 idle 和走路看起来像同一套表现。
- **原因**：`M2C_WeaponFireHandler` 对连发武器只会 `SetBool(\"IsFiring\", true)`；而 `IsFiring=false` 目前只在 `EventWeaponReloadStateChanged_SyncAnimation` 的“开始换弹”路径里执行，目标死亡、脱离索敌、切枪等场景都不会回落。
- **解决**：在客户端武器视图组件里增加连发停火版本号和延迟回落逻辑；每次连发开火刷新延迟，停火静默一小段时间后自动清零；换弹/切枪时同步强制清零。

### 2026-04-14 - 本轮整仓编译被并行进程文件锁阻塞

- **现象**：执行 `dotnet build ET.sln` 时，`ET.Hotfix` / `ET.HotfixView` 已成功输出，但在后续 `ET.Aspire.dll` 写入阶段报 `CS2012`，提示文件被其他进程占用。
- **原因**：仓库当前存在并行工作，`Packages/cn.etetet.aspire/DotNet~/obj/Debug/ET.Aspire.dll` 被外部进程持有。
- **解决**：不处理其他模块的并行进程，只将本轮验证结果如实写入文档；当前可以确认武器动画这条热更链路已通过编译阶段，完整整仓 build 需待外部文件锁释放后重跑。

## 开发总结

> 开发结束后填写

- **实际完成**：已确认“怪物受伤不闪白”的真实根因是现有材质不支持 `_HitFlashAmount/_HitFlashColor`，并已把命中反馈改成运行时通用材质方案；同时拆掉 `HitEffect` 为空时对闪白/缩放的连带提前返回。

- **与设计的偏差**：原设计里写的是“靠 shader 自定义属性 + MaterialPropertyBlock”，实际资源并未接入，因此命中反馈改为 `_BaseColor/_Color/_EmissionColor` 通用方案；另外原文档中的 `IsFiring` 超时回落还是 TODO，本轮已正式落地到客户端武器视图组件。
- **后续待办**：进游戏验证自动步枪/冲锋枪在“停火、目标死亡、脱离索敌、切枪、换弹”五种场景下是否都能及时退出 firing 循环，并确认怪物受击时的白闪是否已经足够明显。
- **补充**：命中闪白本轮又确认了一层材质侧根因：很多怪物的 `_BaseColor/_Color` 本来就是纯白，所以旧的 lerp-to-white 方案天然不显色；现已改成“亮度乘算 + 原始 emission 叠加”，且完整 `dotnet build ET.sln` 已补跑通过。
