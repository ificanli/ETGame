# 射击打击感与武器差异化设计文档

**创建时间**：2026-04-09
**最后更新**：2026-04-09
**状态**：设计中
**关联任务**：M0.2-W3 #11（合并 W1 #12 武器体验差异化设计）
**涉及包**：cn.etetet.statesync, cn.etetet.map, cn.etetet.excel

## 需求概述

当前 5 种武器（散弹枪/狙击枪/步枪/火箭炮/冲锋枪）的射击体验高度同质化：

1. **动作**：所有枪械共用一个 `Fire` 触发器，没有区分单发和连发动画
2. **音效**：已按 WeaponTypeId 分类定义了 4 种音效常量，但部分未实装
3. **特效**：所有枪械共用同一套 `Laser_Red` 特效，无枪口火焰，无相机抖动
4. **数值**：当前 5 把枪的伤害/射速/射程/弹匣等参数需要全面重调

目标：让每种枪械类型有清晰可感知的差异化射击手感，提升领导体验包的战斗打击感。

## 技术方案

### 整体思路

不改变现有武器数据模型（双槽 WeaponComponent），在已有的 M2C_WeaponFire / M2C_WeaponHit 消息链路上**逐层叠加表现**：

1. **动作差异化**：WeaponConfig 新增 `FireAnimationType` 字段，客户端按类型播放不同动画
2. **枪口火焰特效**：WeaponConfig 新增 `MuzzleFlashEffect` 字段，开火时在枪口挂载
3. **相机抖动（通用接口）**：在 `CombatLockCameraComponent` 上提供 `ApplyShake` 通用方法，供大招释放、大型场景事件等调用；**不绑定普通射击**（逐发触发会导致反馈过于密集）
4. **命中反馈**：目标受击闪白 + 短暂缩放抖动（客户端本地表现，不需要新协议）
5. **数值全面重调**：调整 5 把枪的 Damage / AttackIntervalMs / MagazineSize / ReloadTimeMs / AttackRange

选择此方案的原因：改动集中在客户端表现层和 Excel 配置，不改服务端核心战斗逻辑，风险可控。

### 动作系统设计

#### 现有动画架构

角色动画通过 `AnimatorComponent` 驱动，它在 Unit 创建时自动挂载：

```
Unit → AnimatorComponent → UnityEngine.Animator
```

**关键机制**：
- `AnimatorComponent.Awake()` 自动从 GameObject 获取 Animator 并缓存所有参数名到 `HashSet<string> Parameter`
- 所有 `SetTrigger/SetBool/SetFloat` 调用内部先执行 `HasParameter(name)` 检查，参数不存在时静默 return，不会报错
- 角色模型和武器模型是**分离的 GameObject**——武器挂在绑点（RightHand 等）上，射击动画影响的是角色身体姿态

**当前已有的 Animator 参数**：

| 参数名 | 类型 | 用途 | 来源 |
|--------|------|------|------|
| `Fire` | Trigger | 射击动画（所有武器共用） | M2C_WeaponFireHandler |
| `HasWeapon` | Bool | 持枪/空手姿态切换 | WeaponConfigHelper.ApplyAnimatorState |
| `MoveSpeed` | Float | 移动混合树驱动 | UnitViewInterpolationComponent |

#### 改造方案

将原来的 `Fire` Trigger 拆分为 `FireSingle` / `FireRapid`，通过 WeaponConfig 的 `FireAnimationType` 字段决定使用哪个。

**射击动作分类**：

| 类型 | FireAnimationType | 对应武器 | 动画行为 | Animator 参数 |
|------|------------------|---------|---------|--------------|
| **单发射击** (SingleShot) | 1 | 散弹枪(1) / 狙击枪(2) / 火箭炮(4) | 每次开火播完一个完整的射击-回位动作 | `SetTrigger("FireSingle")` |
| **连发射击** (RapidFire) | 2 | 步枪(3) / 冲锋枪(5) | 高频触发，动画短促循环 | `SetTrigger("FireRapid")` |

说明：当前没有按住逻辑，连发枪械通过服务端高频触发 M2C_WeaponFire 消息，客户端每次收到都播 `FireRapid` 动画。

#### 代码改动

**文件**：`M2C_WeaponFireHandler.cs`

```csharp
// ── 原代码（约第37行） ──
animatorComponent?.SetTrigger("Fire");

// ── 改为 ──
string fireTrigger = weaponConfig.FireAnimationType == 2 ? "FireRapid" : "FireSingle";
animatorComponent?.SetTrigger(fireTrigger);
```

**安全性**：如果 Animator Controller 中没有 `FireSingle` / `FireRapid` 参数，`HasParameter` 检查会静默跳过，不影响任何其他逻辑。如果保留了旧的 `Fire` 参数也不会冲突——只是不会被触发。

#### WeaponConfig 新增字段

| 字段名 | 类型 | 说明 | 示例值 |
|--------|------|------|--------|
| `FireAnimationType` | int | 1=SingleShot, 2=RapidFire | 散弹枪=1, 步枪=2 |

#### 资源对接指南（用户操作）

##### 1. Animator Controller 改造

在角色的 Animator Controller（挂在角色 Prefab 根节点或子节点上的 Animator 组件）中：

**新增 2 个 Trigger 参数**：
- `FireSingle`
- `FireRapid`

> 旧的 `Fire` 参数可以保留（不会被代码触发了），也可以删除。

##### 2. 动画状态机配置

```
                          ┌─────────────────┐
                          │  Any State       │
                          └──┬──────────┬────┘
          FireSingle Trigger │          │ FireRapid Trigger
                             ▼          ▼
                    ┌────────────┐  ┌───────────┐
                    │ FireSingle │  │ FireRapid  │
                    │ (State)    │  │ (State)    │
                    └─────┬──────┘  └─────┬─────┘
                          │ HasExitTime   │ HasExitTime
                          ▼               ▼
                    ┌─────────────────────────┐
                    │  Idle / Locomotion       │
                    └─────────────────────────┘
```

**Transition 设置**：
- `Any State → FireSingle`：Condition = `FireSingle` trigger，**Has Exit Time = false**，Transition Duration ≈ 0.05s
- `Any State → FireRapid`：Condition = `FireRapid` trigger，**Has Exit Time = false**，Transition Duration ≈ 0.02s
- `FireSingle → Idle`：**Has Exit Time = true**，让动画播完再回到 Idle
- `FireRapid → Idle`：**Has Exit Time = true**，让动画播完再回到 Idle

##### 3. AnimationClip 规格

| Clip | 建议时长 | 动作描述 | 关键帧要求 |
|------|---------|---------|-----------|
| **FireSingle** | 300~500ms | 明显的后坐力 + 回位。上半身向后仰，双手后推，然后回到持枪 Idle 姿态 | 第0帧：Idle 姿态 → 30%处：后坐力最大点 → 100%：回到 Idle |
| **FireRapid** | 50~100ms | 短促的微抖。轻微的手臂/肩膀抖动，幅度很小 | 第0帧：Idle → 50%处：微后仰 → 100%：回到 Idle |

**注意事项**：
- `FireRapid` 会被高频触发（步枪 150ms/发，冲锋枪 80ms/发），所以 Clip 时长**必须短于开火间隔**，否则动画会被不断打断重播
- 推荐 `FireRapid` 时长 ≤ 武器的 `AttackIntervalMs`（步枪=150ms，冲锋枪=80ms）
- 如果只想做一个通用的射击动画，可以只配 `FireSingle`，然后把步枪/冲锋枪的 `FireAnimationType` 也设为 1——效果就是所有枪都用同一个动画，退化到当前行为
- 如果暂时没有动画资源，不配 `FireSingle`/`FireRapid` 参数即可，代码静默跳过，和当前行为一样

##### 4. 验证方法

在 Unity 中运行游戏，进入战斗后：
1. 开散弹枪/狙击枪/火箭炮 → 应看到 `FireSingle` 动画（后坐力大，回位明显）
2. 开步枪/冲锋枪 → 应看到 `FireRapid` 动画（短促抖动，高频闪烁）
3. 在 Animator 窗口实时观察：当前激活的 State 应该在 `FireSingle` / `FireRapid` 之间正确切换

**特效资源（用户手动准备）**：
- 每种武器类型可以配不同的枪口火焰（颜色/大小/形状差异化）
- 散弹枪：大而散的橙色火焰
- 狙击枪：细长的蓝白色闪光

- 火箭炮：大范围的橙红色火焰+烟雾

### 相机抖动（通用接口，不绑定射击）

> **设计决策**：相机抖动不绑定普通射击——逐发触发会导致反馈过于密集，尤其步枪/冲锋枪等高射速武器。相机抖动作为通用接口保留，供大招释放、大型场景事件（爆炸、Boss 登场等）调用。

#### 接口设计

```csharp
// 通用调用方式，任何需要相机震动的地方都可以调
CombatLockCameraComponent cam = myUnit.GetComponent<CombatLockCameraComponent>();
cam?.ApplyShake(intensity: 0.5f, durationMs: 300);
```

#### 典型使用场景（后续接入）

| 场景 | 建议 Intensity | 建议 DurationMs |
|------|---------------|-----------------|
| 大招释放 | 0.5 - 0.8 | 300 - 500 |
| Boss 登场/阶段切换 | 0.8 - 1.2 | 400 - 600 |
| 大范围爆炸 | 0.6 - 1.0 | 300 - 400 |
| 火箭炮命中（如需单独加） | 0.4 | 200 |

#### 各武器闪光时长

| 武器 | HitFlashDurationMs | 设计意图 |
|------|-------------------|---------|
| 散弹枪 | 150 | 重击感，闪光明显 |
| 狙击枪 | 200 | 沉重单发，闪光最持久 |
| 步枪 | 60 | 快速闪烁，连发节奏 |
| 火箭炮 | 250 | 最强冲击，视觉最重 |
| 冲锋枪 | 40 | 极快闪烁，高频但不糊成一片 |

#### 触发逻辑

```
收到 M2C_WeaponHit
  → 找到目标 Unit 的所有 Renderer
  → 读取攻击方武器的 HitFlashDurationMs（从消息中的 WeaponConfigId 获取）
  → 计算：fadeOutStart = duration * (1 - HitFlashFadeOutRatio)
  → 前 40% 时间：_HitFlashAmount = 1，颜色 = HitFlashColor
  → 后 60% 时间：_HitFlashAmount 从 1 Lerp 到 0
```

实现方式：通过 MaterialPropertyBlock 设置 `_HitFlashAmount` 和 `_HitFlashColor`。需要 Shader 支持这两个属性（如果 Shader 不支持则跳过，先做相机抖动和枪口火焰）。

#### 目标受击抖动

```
收到 M2C_WeaponHit
  → 目标 GameObject 短暂缩放抖动
  → 缩放到 1.05，在 100ms 内恢复到 1.0
```

### 数值重调

#### 当前数值（基线）

| WeaponId | 类型 | Damage | AttackIntervalMs | MagazineSize | ReloadTimeMs | AttackRange | BulletCount | SpreadAngle |
|----------|------|--------|-----------------|--------------|-------------|-------------|-------------|-------------|
| 50009 | 散弹枪(1) | 20 | 1500 | 4 | 2200 | 3 | 4 | 30 |
| 50010 | 狙击枪(2) | 20 | 500 | 1 | 2200 | 3 | 1 | 0 |
| 50011 | 步枪(3) | 20 | 100 | 1 | 2200 | 3 | 1 | 0 |
| 50012 | 火箭炮(4) | 20 | 3000 | 1 | 2200 | 3 | 1 | 0 |
| 50013 | 冲锋枪(5) | 20 | 50 | 1 | 2200 | 3 | 1 | 0 |

**问题**：所有枪 Damage 都是 20、射程都是 3、换弹时间都是 2200ms，完全没有差异化。弹匣容量除散弹枪为 4 外其余都是 1。

#### 重调目标数值

设计原则：
- **DPS 大致相当**（±20%），通过射速×单发伤害平衡
- **射程拉开梯度**：近→远 = 散弹枪 < 冲锋枪 < 步枪 < 火箭炮 < 狙击枪
- **弹匣与换弹时间反映节奏**：大弹匣+快换弹 = 持续输出型，小弹匣+慢换弹 = 爆发型
- **散弹枪特殊**：多子弹+散射角 = 近距高爆发，远距衰减

| WeaponId | 类型 | Damage | AttackIntervalMs | MagazineSize | ReloadTimeMs | AttackRange | BulletCount | SpreadAngle | 设计意图 |
|----------|------|--------|-----------------|--------------|-------------|-------------|-------------|-------------|---------|
| 50009 | 散弹枪(1) | 15 | 1200 | 6 | 2500 | 4 | 5 | 35 | 近距爆发，单发 5×15=75 但需贴脸；换弹慢，节奏感强 |
| 50010 | 狙击枪(2) | 120 | 2000 | 5 | 3000 | 12 | 1 | 0 | 远程点杀，单发高伤害但射速慢；拉远打，失距离优势则劣势 |
| 50011 | 步枪(3) | 18 | 150 | 30 | 2000 | 7 | 1 | 3 | 全能中距，持续输出稳定；大弹匣中等换弹；微散射增加手感 |
| 50012 | 火箭炮(4) | 200 | 3500 | 3 | 3500 | 10 | 1 | 0 | 单发超高伤害，射速极慢；远距AOE定位（AOE待后续实现） |
| 50013 | 冲锋枪(5) | 10 | 80 | 40 | 1500 | 5 | 1 | 5 | 近中距泼水，超高射速低单发；最大弹匣最快换弹；散射略大 |

#### DPS 对比验算

| 武器 | 单发总伤害 | 每秒射击次数 | 理论 DPS | 定位 |
|------|-----------|-------------|---------|------|
| 散弹枪 | 75 (15×5) | 0.83 | 62.5 | 贴脸爆发 |
| 狙击枪 | 120 | 0.5 | 60 | 远程点杀 |
| 步枪 | 18 | 6.67 | 120 | 中距稳定（基准线） |
| 火箭炮 | 200 | 0.29 | 57 | 单发超爆（补AOE后提升） |
| 冲锋枪 | 10 | 12.5 | 125 | 近距泼水 |

> 步枪和冲锋枪 DPS 偏高是有意设计——它们需要持续命中，实际战场 DPS 受命中率和走位影响会打折；散弹枪/狙击枪/火箭炮则是"打到就是赚到"的爆发型。

**在动画触发之后、投射体创建之前插入**：
```csharp
// 枪口火焰
string muzzleFlashEffect = weaponConfig.MuzzleFlashEffect;
if (!string.IsNullOrEmpty(muzzleFlashEffect))
{
    // 获取枪口位置（复用现有 WeaponViewComponent.GetFirePoint 逻辑）
    WeaponViewComponent weaponView = caster.GetComponent<WeaponViewComponent>();
    Vector3 muzzlePos = weaponView != null
        ? weaponView.GetFirePoint(caster, weaponConfig)
        : GetBindPosition(caster, BindPoint.Bullet);
    Quaternion muzzleRot = caster.GetComponent<GameObjectComponent>().GameObject.transform.rotation;

    // 加载并实例化
    ResourcesLoaderComponent loader = root.GetComponent<ResourcesLoaderComponent>();
    GameObject prefab = await loader.LoadAssetAsync<GameObject>(muzzleFlashEffect);
    if (prefab != null)
    {
        GameObject flash = UnityEngine.Object.Instantiate(prefab, muzzlePos, muzzleRot);
        int durationMs = weaponConfig.MuzzleFlashDurationMs > 0 ? weaponConfig.MuzzleFlashDurationMs : 100;
        UnityEngine.Object.Destroy(flash, durationMs / 1000f);
    }
}
```

**注意**：如果枪口火焰资源不存在（空字符串），整段跳过，不影响现有逻辑。

**CombatLockCameraComponent 新增字段**：

**CombatLockCameraComponentSystem 新增方法**：
```csharp
public static void ApplyShake(this CombatLockCameraComponent self, float intensity, int durationMs)
{
    self.ShakeIntensity = intensity;
    self.ShakeDurationMs = durationMs;
    self.ShakeElapsedMs = 0;
    self.IsShaking = true;
}
```

**Update 中叠加抖动**：在现有 `finalOffset` 计算后，追加：
```csharp
if (self.IsShaking)
{
    self.ShakeElapsedMs += Time.deltaTime * 1000f;
    if (self.ShakeElapsedMs >= self.ShakeDurationMs)
    {
        self.IsShaking = false;
    }
    else
    {
        float t = self.ShakeElapsedMs / self.ShakeDurationMs;
        float decay = 1f - t; // 线性衰减
        float offsetX = UnityEngine.Random.Range(-1f, 1f) * self.ShakeIntensity * decay;
        float offsetY = UnityEngine.Random.Range(-1f, 1f) * self.ShakeIntensity * decay;
        finalOffset += new Vector3(offsetX, offsetY, 0);
    }
}
```

**调用示例**（不在本次射击流程中调用，留给后续功能）：
```csharp

cam?.ApplyShake(0.6f, 400);

// Boss 登场时
cam?.ApplyShake(1.0f, 500);
```
