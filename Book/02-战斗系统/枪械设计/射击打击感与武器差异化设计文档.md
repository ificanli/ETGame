# 射击打击感与武器差异化设计文档

**创建时间**：2026-04-09
**最后更新**：2026-04-17
**状态**：开发中
**关联任务**：M0.2-W3 #11（合并 W1 #12 武器体验差异化设计）
**涉及包**：cn.etetet.statesync, cn.etetet.map, cn.etetet.excel

## 需求概述

当前 5 种武器（散弹枪/狙击枪/步枪/火箭炮/冲锋枪）的射击体验高度同质化：

1. **动作**：所有枪械共用一个 `Fire` 触发器，没有区分单发和连发动画
2. **音效**：已按 WeaponTypeId 分类定义了 4 种音效常量，但部分未实装
3. **特效**：所有枪械共用同一套 `Laser_Red` 特效，无枪口火焰，无相机抖动
4. **数值**：当前 5 把枪的伤害/射速/射程/弹匣等参数需要全面重调

目标：让每种枪械类型有清晰可感知的差异化射击手感，提升领导体验包的战斗打击感。

## 技术方案

### 整体思路

不改变现有武器数据模型（双槽 WeaponComponent），在已有的 M2C_WeaponFire / M2C_WeaponHit 消息链路上**逐层叠加表现**：

1. **动作差异化**：WeaponConfig 新增 `FireAnimationType` 字段，客户端按类型播放不同动画
2. **枪口火焰特效**：WeaponConfig 新增 `MuzzleFlashEffect` 字段，开火时在枪口挂载
3. **相机抖动（通用接口）**：在 `CombatLockCameraComponent` 上提供 `ApplyShake` 通用方法，供大招释放、大型场景事件等调用；**不绑定普通射击**（逐发触发会导致反馈过于密集）
4. **命中反馈**：目标受击闪白 + 短暂缩放抖动（客户端本地表现，不需要新协议）
5. **数值全面重调**：调整 5 把枪的 Damage / AttackIntervalMs / MagazineSize / ReloadTimeMs / AttackRange
6. **狙击枪特殊机制**：当前持有狙击枪时，玩家主视野半径直接等于当前武器生效射程；切回非狙击枪后恢复原 AOI 基线
7. **冲锋枪持续朝向**：当前持有冲锋枪且目标仍在当前生效射程内时，移动中的角色持续朝向目标，不再在“移动方向转向”和“开火瞬间朝目标转向”之间来回抢旋转

选择此方案的原因：改动集中在客户端表现层和 Excel 配置，不改服务端核心战斗逻辑，风险可控。

### 动作系统设计

#### 现有动画架构

角色动画通过 `AnimatorComponent` 驱动，它在 Unit 创建时自动挂载：

```
Unit → AnimatorComponent → UnityEngine.Animator
```

**关键机制**：
- `AnimatorComponent.Awake()` 自动从 GameObject 获取 Animator 并缓存所有参数名到 `HashSet<string> Parameter`
- 所有 `SetTrigger/SetBool/SetFloat` 调用内部先执行 `HasParameter(name)` 检查，参数不存在时静默 return，不会报错
- 角色模型和武器模型是**分离的 GameObject**——武器挂在绑点（RightHand 等）上，射击动画影响的是角色身体姿态

**当前 Animator 参数**：

| 参数名 | 类型 | 用途 | 来源 |
|--------|------|------|------|
| `FireSingle` | Trigger | 单发射击动画（一次性播放） | M2C_WeaponFireHandler |
| `IsFiring` | Bool | 连发射击动画（循环播放） | M2C_WeaponFireHandler / ReloadStateChanged |
| `IsReloading` | Bool | 换弹动画（循环播放） | EventWeaponReloadStateChanged |
| `HasWeapon` | Bool | 持枪/空手姿态切换 | WeaponConfigHelper.ApplyAnimatorState |
| `MoveSpeed` | Float | 移动混合树驱动 | UnitViewInterpolationComponent |

#### 改造方案

将原来的 `Fire` Trigger 拆分为两种驱动方式：
- **单发武器**（FireAnimationType=1）：`SetTrigger("FireSingle")` — 每次开火触发一次完整的射击-回位动画
- **连发武器**（FireAnimationType=2）：`SetBool("IsFiring", true)` — 进入循环射击动画，换弹/停火时 `SetBool("IsFiring", false)` 退出

**射击动作分类**：

| 类型 | FireAnimationType | 对应武器 | 动画行为 | Animator 驱动 |
|------|------------------|---------|---------|--------------|
| **单发射击** (SingleShot) | 1 | 散弹枪 / 狙击步枪 / 手枪 / 榴弹炮 | 每次开火播完一个完整的射击-回位动作 | `SetTrigger("FireSingle")` |
| **连发射击** (RapidFire) | 2 | 自动步枪 / 冲锋枪 / 射线枪 | 循环播放射击动画，停火时退出 | `SetBool("IsFiring", true/false)` |

#### 代码改动

**文件**：`M2C_WeaponFireHandler.cs`

```csharp
if (weaponConfig.FireAnimationType == 2)
{
    // 连发武器：设 Bool 进入循环射击动画
    animatorComponent?.SetBool("IsFiring", true);
}
else
{
    // 单发武器：每次开火触发一次完整射击动画
    animatorComponent?.SetTrigger("FireSingle");
}
```

**文件**：`EventWeaponReloadStateChanged_SyncAnimation.cs`

```csharp
animatorComponent?.SetBool("IsReloading", args.IsReloading);
// 开始换弹时，结束连发射击动画
if (args.IsReloading)
{
    animatorComponent?.SetBool("IsFiring", false);
}
```

**IsFiring 退出时机**：
- 弹药耗尽 → 服务端触发换弹 → `IsReloading=true` 同步到客户端 → `IsFiring=false`
- 手动换弹 → 同上
- 目标死亡/脱离索敌/停止自动开火 → 服务端不再发 `M2C_WeaponFire` → 客户端通过“最后一发时间 + 超时”自动把 `IsFiring` 归 false
- 切枪/卸枪 → 客户端切槽位时立即把 `IsFiring` 归 false，避免上一把枪的连发状态串到新武器

#### 连发停火回落方案

2026-04-14 补充收口：现场复盘确认“持枪 idle 和走路看起来一样”的根因之一，是连发武器把 `IsFiring` 置为 `true` 后，只有换弹链路会清零；正常停火场景没有回落点，导致角色长期停在 ArmedFire / Run_and_Shoot 这一支。

本轮改为客户端本地兜底：

1. 连发武器每次收到 `M2C_WeaponFire` 时，刷新一次 `RapidFireStopVersion`。
2. 同时按 `max(AttackIntervalMs * 2, 250ms)` 启一个停火延迟。
3. 延迟结束后如果版本号没有变化，说明这段时间没有再收到新的开火消息，则自动执行 `IsFiring=false`。
4. 换弹开始、切枪、卸枪时，立即执行 `IsFiring=false`，并同时推进版本号，取消旧的停火延迟任务。

这样即便服务端没有专门的“停火”消息，客户端也能在正常停火后可靠回到 ArmedLocomotion，对应持枪 idle / 持枪走路混合树。

**安全性**：如果 Animator Controller 中没有对应参数，`HasParameter` 检查会静默跳过。

#### WeaponConfig 字段

| 字段名 | 类型 | 说明 | 示例值 |
|--------|------|------|--------|
| `FireAnimationType` | int | 1=SingleShot, 2=RapidFire | 散弹枪=1, 自动步枪=2 |

#### 资源对接指南（用户操作）

##### 1. Animator Controller 改造

在角色的 Animator Controller 中：

**新增参数**：
- `FireSingle`（Trigger）— 单发射击
- `IsFiring`（Bool）— 连发射击循环

> 旧的 `Fire` 参数可删可留，代码不再触发它。

##### 2. 动画状态机配置

```
                          ┌─────────────────┐
                          │  Any State       │
                          └──┬──────────┬────┘
          FireSingle Trigger │          │ IsFiring = true
                             ▼          ▼
                    ┌────────────┐  ┌───────────┐
                    │ FireSingle │  │ FireRapid  │
                    │ (一次性)    │  │ (循环Loop) │
                    └─────┬──────┘  └─────┬─────┘
                          │ HasExitTime   │ IsFiring = false
                          ▼               ▼
                    ┌─────────────────────────┐
                    │  Idle / Locomotion       │
                    └─────────────────────────┘
```

**Transition 设置**：

| Transition | Condition | Has Exit Time | Duration |
|-----------|-----------|--------------|----------|
| Any State → FireSingle | `FireSingle` trigger | false | 0.05s |
| Any State → FireRapid | `IsFiring = true` | false | 0.05s |
| FireSingle → Idle | — | true（播完退出） | 0.1s |
| FireRapid → Idle | `IsFiring = false` | false | 0.1s |

##### 3. AnimationClip 规格

| Clip | Loop | 建议时长 | 动作描述 |
|------|------|---------|---------|
| **FireSingle** | 否 | 300~500ms | 明显的后坐力 + 回位。上半身向后仰，双手后推，然后回到持枪 Idle 姿态 |
| **FireRapid** | **是** | 100~200ms | 持续的短促抖动循环。轻微手臂/肩膀抖动，幅度小，循环无接缝 |

**注意事项**：
- `FireRapid` 是循环动画，只要 `IsFiring=true` 就一直播放，不需要关心时长和射速的匹配
- 如果暂时没有动画资源，不配参数即可，代码静默跳过
- 如果只有一个射击动画，可以把 `FireSingle` 的 clip 也挂在 `FireRapid` 上（设为 Loop）

### 狙击枪视野机制

#### 规则口径

1. 仅当**当前持有武器**是狙击枪时生效，不是“背包里有狙就生效”。
2. 生效后的主视野半径直接等于**当前武器生效射程**，包含肉鸽词条等运行时射程修正。
3. 若狙击枪射程低于玩家默认 AOI，主视野也要同步收窄；例如默认视野 `10`，当前狙击枪射程 `8`，则最终主视野半径就是 `8`。
4. 切回非狙击枪、卸下武器或重建武器运行时时，需要恢复原 AOI 基线，不能污染其他视野来源。

#### 实现方案

1. 不新增 Excel 字段，也不新增协议。
2. 复用现有 `NumericType.AOI` 数值链路，把“武器驱动的额外/负向视野修正”挂到 `NumericType.AOIFinalAdd`。
3. `WeaponRuntimeStatsHelper.RefreshUnitWeaponRuntimeStats(...)` 在刷新当前槽位生效射程后，同步把玩家 AOI 最终结果收敛到当前狙击枪射程。
4. `WeaponInitHelper.ResetWeaponRuntime(...)` 在移除 `WeaponComponent` 前先回退该偏移，避免残留。
5. 客户端迷雾半径优先读取“当前持有狙击枪的生效射程”，其余情况再回到现有 `FogVisionRadius / NumericType.AOI` 逻辑。

#### 验收标准补充

1. 切到狙击枪后，`TargetSelectorComponent.MaxRange` 与玩家主视野半径一致。
2. 狙击枪射程降低到默认 AOI 以下时，主视野半径也会同步缩小。
3. 切回非狙击枪后，玩家视野恢复到原本 AOI 基线，不残留狙击枪修正。

### 冲锋枪持续朝向机制

#### 规则口径

1. 仅当**当前持有武器**是冲锋枪时生效，不影响自动步枪、手枪等其他枪械。
2. 只要当前目标仍在**当前武器生效射程**内，角色即便一边移动一边射击，也持续朝向目标。
3. 若当前目标丢失、死亡、脱离射程、切枪或开始换弹，则恢复为现有“按移动方向转向”的默认逻辑。
4. 本轮只收口整个人物根朝向，不做上下半身分离动画。

#### 实现方案

1. 服务端权威移动层新增“冲锋枪持续朝向目标”的统一判断：优先取 `TargetComponent.Unit`，失败时回退到 `TargetSelectorComponent.CurrentTargetId`，并用当前武器生效射程做合法性校验。
2. 只要校验通过，服务端移动旋转和对外广播的朝向方向都优先使用“朝目标方向”，而不是“朝移动方向”。
3. 客户端本地预测不能直接依赖高层武器视图状态，因此把“期望朝向方向 + 过期时间”缓存到 `cn.etetet.map` 的通用移动权威状态组件。
4. 冲锋枪每次收到 `M2C_WeaponFire` 时刷新一次该缓存；切枪、换弹、卸枪时立即清掉，避免旧目标朝向串到后续武器。
5. `map` 包本地预测与插值层只消费这份通用缓存：缓存有效就按目标方向转，否则继续按移动方向转。

#### 验收标准补充

1. 冲锋枪移动射击时，角色根朝向持续锁定当前射程内目标，不再在目标方向和移动方向之间快速抖动。
2. 目标死亡、脱离射程、切枪、换弹后，角色恢复按移动方向转向。
3. 该规则只影响冲锋枪，不影响自动步枪、手枪、狙击枪等其他武器的现有表现。

##### 4. 验证方法

在 Unity 中运行游戏，进入战斗后：
1. 开散弹枪/狙击步枪/手枪/榴弹炮 → 应看到 `FireSingle` 动画（一次性后坐力+回位）
2. 开自动步枪/冲锋枪/射线枪 → 应看到 `FireRapid` 循环动画（持续抖动），换弹时循环停止
3. 在 Animator 窗口实时观察：`IsFiring` 在连发期间为 true，换弹时变为 false

#### 触发逻辑

```
收到 M2C_WeaponFire
  → 在 caster 的 MuzzleBindPoint 位置实例化 MuzzleFlashEffect
  → MuzzleFlashDurationMs 后销毁
  → 朝向 = caster 面向方向
```

**特效资源（用户手动准备）**：
- 每种武器类型可以配不同的枪口火焰（颜色/大小/形状差异化）
- 散弹枪：大而散的橙色火焰
- 狙击枪：细长的蓝白色闪光
- 步枪/冲锋枪：小而快的黄色火焰
- 火箭炮：大范围的橙红色火焰+烟雾

### 相机抖动（通用接口，不绑定射击）

> **设计决策**：相机抖动不绑定普通射击——逐发触发会导致反馈过于密集，尤其步枪/冲锋枪等高射速武器。相机抖动作为通用接口保留，供大招释放、大型场景事件（爆炸、Boss 登场等）调用。

#### 接口设计

```csharp
// 通用调用方式，任何需要相机震动的地方都可以调
CombatLockCameraComponent cam = myUnit.GetComponent<CombatLockCameraComponent>();
cam?.ApplyShake(intensity: 0.5f, durationMs: 300);
```

#### 典型使用场景（后续接入）

| 场景 | 建议 Intensity | 建议 DurationMs |
|------|---------------|-----------------|
| 大招释放 | 0.5 - 0.8 | 300 - 500 |
| Boss 登场/阶段切换 | 0.8 - 1.2 | 400 - 600 |
| 大范围爆炸 | 0.6 - 1.0 | 300 - 400 |
| 火箭炮命中（如需单独加） | 0.4 | 200 |

```
收到 M2C_WeaponHit
  → 找到目标 Unit 的所有 Renderer
  → 读取攻击方武器的 HitFlashDurationMs（从消息中的 WeaponConfigId 获取）
  → 计算：fadeOutStart = duration * (1 - HitFlashFadeOutRatio)
  → 前 40% 时间：_HitFlashAmount = 1，颜色 = HitFlashColor
  → 后 60% 时间：_HitFlashAmount 从 1 Lerp 到 0
```

实现方式修正：

1. 现场复盘确认，当前怪物/敌方单位材质普遍只有 `_BaseColor` / `_Color` / `_EmissionColor`，工程里没有任何 shader 或材质真正接入 `_HitFlashAmount` / `_HitFlashColor`。
2. 因此不能再依赖“专用 shader 参数 + MaterialPropertyBlock”的方案，否则代码会执行但画面没有反馈。
3. 正式实现改为运行时通用材质闪白：
   - 首次受击时只处理目标身上的 `SkinnedMeshRenderer / MeshRenderer`，拿到其 runtime materials
   - 缓存各材质原始 `_BaseColor` / `_Color` / `_EmissionColor` 与 `_EMISSION` keyword 状态
   - 受击期间不再做“lerp 到白色”，而是对 `_BaseColor` / `_Color` 做乘算增亮；因为现有怪物材质这两个颜色乘子大多本来就是 `1,1,1`
   - 同时在原始 `_EmissionColor` 上叠加白色 HDR boost，避免覆盖掉材质自带的发光颜色
   - 渐隐结束后恢复原始颜色和 emission 状态

这样不要求怪物资源额外接专用 shader，现有 URP Lit 材质即可生效。

#### 目标受击抖动

```
收到 M2C_WeaponHit
  → 目标 GameObject 短暂缩放抖动
  → 缩放到 1.05，在 100ms 内恢复到 1.0
```

#### 重调目标数值

设计原则：
- **DPS 大致相当**（±20%），通过射速×单发伤害平衡
- **射程拉开梯度**：近→远 = 散弹枪 < 冲锋枪 < 步枪 < 火箭炮 < 狙击枪
- **弹匣与换弹时间反映节奏**：大弹匣+快换弹 = 持续输出型，小弹匣+慢换弹 = 爆发型
- **散弹枪特殊**：多子弹+散射角 = 近距高爆发，远距衰减

**CombatLockCameraComponentSystem 新增方法**：
```csharp
public static void ApplyShake(this CombatLockCameraComponent self, float intensity, int durationMs)
{
    self.ShakeIntensity = intensity;
    self.ShakeDurationMs = durationMs;
    self.ShakeElapsedMs = 0;
    self.IsShaking = true;
}
```

**Update 中叠加抖动**：在现有 `finalOffset` 计算后，追加：
```csharp
if (self.IsShaking)
{
    self.ShakeElapsedMs += Time.deltaTime * 1000f;
    if (self.ShakeElapsedMs >= self.ShakeDurationMs)
    {
        self.IsShaking = false;
    }
    else
    {
        float t = self.ShakeElapsedMs / self.ShakeDurationMs;
        float decay = 1f - t; // 线性衰减
        float offsetX = UnityEngine.Random.Range(-1f, 1f) * self.ShakeIntensity * decay;
        float offsetY = UnityEngine.Random.Range(-1f, 1f) * self.ShakeIntensity * decay;
        finalOffset += new Vector3(offsetX, offsetY, 0);
    }
}
```

**调用示例**（不在本次射击流程中调用，留给后续功能）：
```csharp

cam?.ApplyShake(0.6f, 400);

// Boss 登场时
cam?.ApplyShake(1.0f, 500);
```
