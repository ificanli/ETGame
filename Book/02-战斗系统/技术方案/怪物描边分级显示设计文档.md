# 怪物描边分级显示设计文档

**创建时间**：2026-04-16
**最后更新**：2026-04-16
**状态**：已完成
**关联任务**：M0.2-W3 #41
**涉及包**：cn.etetet.map, cn.etetet.statesync

## 需求概述

为了让玩家在局内更快识别怪物威胁级别，需要给怪物补一层常驻描边：

- 普通小怪：红色描边
- 精英怪 / Boss：橙色描边

本次需求只处理局内怪物的可视化分级，不改服务端战斗判定、不新增网络协议，也不要求在每个怪 prefab 上手工逐个挂组件。

## 技术方案

### 整体思路

本轮采用“客户端运行时统一挂描边壳层”的方案：

1. `cn.etetet.map` 提供通用单位视图描边能力：
   - 新增一份最小 URP outline shader；
   - 在单位 `GameObjectComponent` 上按现有 `Renderer` 复制一层 outline 子渲染器；
   - 单位销毁时统一清理 outline 子节点与运行时材质。
2. `cn.etetet.statesync` 提供业务判定与样式下发：
   - 只对 `UnitType.Monster` 生效；
   - 普通怪使用红色样式；
   - 精英 / Boss 使用橙色样式。
3. 不直接修改现有怪物原材质：
   - 当前 `XiaoMao / XiaoHou / XiaoYing / XiaoE / BearBoss` 的 `Material_1.mat` 均为普通 `URP Lit` 材质，没有现成 outline 参数；
   - 直接改原材质会污染原模型资源，也不利于统一控制开关。

### 为什么不继续复用 Highlighters

原计划可以基于已做过的 `Highlighters URP17` 兼容修复继续接入，但本地仓库核查后发现：

- Unity 生成的 `Highlighters*.csproj` 仍然存在；
- 实际 `Assets/Highlighters-Outlines/...` 源码目录与对应 DLL/ScriptAssemblies 当前均不存在。

因此本轮如果继续依赖该插件，会在“代码能写、工程里没类型”这一步卡死。相比之下，自建一条最小 outline 壳层方案更稳，也更容易后续维护。

### Entity / Component 设计

新增 `MonsterOutlineVisualComponent`，挂在客户端 `Unit` 上，仅保存：

- 是否已应用描边
- 当前描边颜色
- 当前描边宽度
- 当前怪物档位

组件不管理 Unity 对象；Unity 渲染对象仍由 `GameObjectComponent` 承接，保持地图包视图职责集中。

### 怪物档位判定

本轮不新增协议，直接基于客户端已有 `UnitInfo.ConfigId` 判定：

- `UnitType != Monster`：不处理
- 普通怪：红色描边
- 精英 / Boss：
  - `1015` 重装鳄鱼（精英）
  - `1016` 机械巨熊巴鲁（Boss）

为了避免把裸数字散落在视图逻辑中，具体判断收敛到单独 helper 中，并保留基于 `UnitConfig.Name` 的容错分支，便于后续配置名调整时继续识别。

### Shader 与渲染策略

使用最小 inverse-hull 方案：

- 复制原始 `MeshRenderer / SkinnedMeshRenderer`
- 统一替换为 outline shader
- 顶点沿法线外扩 `_OutlineWidth`
- `Cull Front` 只绘制背面外壳，形成轮廓边
- `ZTest LEqual`，避免描边穿墙透出

首版只做纯色常驻轮廓，不做脉冲、闪烁和命中动态变化。
