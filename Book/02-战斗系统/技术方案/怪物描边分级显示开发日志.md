## 决策记录

### 2026-04-16 - 放弃继续直接接入 Highlighters
- **背景**：用户希望先做怪物描边，但仓库里并没有找到可直接引用的 `Highlighters-Outlines` 插件源码或 DLL。
- **方案**：改为自建最小客户端运行时 outline 壳层方案，避免依赖缺失的第三方插件。
- **原因**：现有工程只保留了 `Highlighters*.csproj` 痕迹，继续按插件类型写接入代码会直接卡在 Unity 类型解析阶段。
- **替代方案**：等待用户重新补齐插件目录后再接；该方案会阻塞当前任务，不采用。

### 2026-04-16 - ModelView 标记类补 `EnableClass`
- **背景**：运行时 outline 壳层需要一个 `MonoBehaviour` 标记类来过滤复制出来的描边 renderer，但 `ModelView` 程序集中的普通 class 会被 ET 分析器限制。
- **方案**：为 `UnitOutlineMarker` 显式添加 `[EnableClass]`。
- **原因**：这是当前 ET 分析器认可的最小修复，不需要改动现有 outline 缓存与过滤逻辑。
- **替代方案**：彻底移除 marker 类，改成按命名或对象列表反向过滤；改动面更大，本轮不采用。

## 问题日志

### 2026-04-16 - 本地仓库缺失 Highlighters 插件源码
- **现象**：`HighlightersUrp.csproj` 仍引用 `Assets/Highlighters-Outlines/...`，但实际磁盘上该目录不存在，也未找到对应 `Highlighters*.dll`。
- **原因**：当前仓库内只保留了 Unity 生成工程文件，第三方插件源码 / 程序集未随当前工作区保留。
- **解决**：调整实现方案，改为在 `cn.etetet.map` 内补一条自有 outline 视图能力。

### 2026-04-16 - `ET0032` 拦截 `UnitOutlineMarker`
- **现象**：首次执行 `dotnet build ET.sln` 时，`UnitOutlineMarker` 被分析器报错为“Model/ModelView 程序集禁止声明非 Object 类”。
- **原因**：`UnitOutlineMarker` 是 `ModelView` 层的 `MonoBehaviour` 标记类，但未声明 `[EnableClass]`。
- **解决**：为 `UnitOutlineMarker` 补 `[EnableClass]` 后重新编译，分析器错误消失。

### 2026-04-16 - 测试场景进程占用 `Bin` 目录 DLL
- **现象**：`dotnet build ET.sln` 第二次失败时，`ET.Mathematics.dll` 与 `ET.MemoryPack.dll` 无法复制到 `Bin`，日志显示被 `.NET Host (34668)` 锁定。
- **原因**：本机残留了 `dotnet .\\Bin\\ET.App.dll --SceneName=Test --Console=1` 测试场景进程。
- **解决**：结束 `PID 34668` 后重跑 `dotnet build ET.sln`，整仓编译通过。
