# 战斗操作和相机操作技术方案 - 第7部分：锁定目标相机参数还原

## 1. 本次交付目标

本次不是只做视频观感分析，而是直接在当前工程里落一版可运行的“移动前视偏移 + 锁定目标偏移”组合相机实现，并同步整理真实参数来源。

本次交付包含两部分：

1. 代码实现
2. 实现版说明文档

当前结论不再声称“和参考视频 100% 一致”，只说明：

- 当前工程真实基线参数来自场景 `Packages/cn.etetet.statesync/Scenes/Init.unity`
- 运行时代码不再额外硬改 `Distance`、`Pitch`
- 相机会按移动方向自动前视偏移
- 锁定目标时会叠加目标方向偏移
- 不再做旧的旋转镜头逻辑

---

## 2. 当前已落地实现

### 2.1 实现结果

已实现以下行为：

1. 本地玩家移动时，相机会按移动方向自动前视偏移
2. 本地玩家有明确锁定目标时，相机会再向目标方向叠加偏移
3. 偏移只影响 `Follow` 锚点位置，不改 `FOV`、不改 `CameraDistance`、不改基线朝向
4. 停止移动且无锁定目标时，相机会平滑回到基础跟随点
5. 旧的鼠标拖拽旋转镜头链路已删除

### 2.2 当前实现策略

本次采用的是“保基线、只偏移”的稳妥方案：

- 基础相机参数完全读取场景现有 `Virtual Camera`
- 移动时，先按移动方向给 `Follow` 一个前视偏移
- 锁定目标后，再把 `Follow` 向“玩家到目标的中点方向”继续推
- 最终偏移统一通过平滑收敛到目标值，避免换向跳变
- 偏移距离上限受基础 `CameraDistance` 约束

这版实现刻意没有再引入新的镜头旋转、缩放、插值参数，目的是先把镜头语义收敛干净。

## 3. 真实参数来源

### 3.1 场景基线

`Packages/cn.etetet.statesync/Scenes/Init.unity` 当前可确认的真实相机参数：

- `FieldOfView = 60.000004`
- `CameraDistance = 8.07`
- `ShoulderOffset = (0, 0, 0)`
- `VerticalArmLength = 0`
- `CameraSide = 0`
- `Damping = (1, 1, 1)`
- `CameraRadius = 0.2`

### 3.2 本次实现的参数策略

本次代码实现不再把运行时相机强行改成别的值，而是：

- `FOV`：沿用场景 `Virtual Camera` 的当前值
- `Distance`：沿用场景 `Cinemachine3rdPersonFollow.CameraDistance`
- `Pitch / Yaw`：沿用场景 `Virtual Camera.transform.rotation`

也就是说，这次实现的“参数还原”不是再猜一套 `12 / 60 / 60`，而是把运行时回归到场景真实基线。

### 3.3 关于 `distance=12`

此前工程里存在把 `CameraDistance` 运行时强改成 `12` 的旧逻辑。  
这次已经删除。

因此当前实际运行结果不再使用 `12`，而是使用场景里的 `8.07`。

如果后面你在 Unity 里对照视频后确认仍然需要更远的镜头，应该改场景或配置，而不是重新把数值写死回 System。

## 4. 偏移公式

### 4.1 目标来源

当前实现只认“明确锁定目标”：

- 来源：`TargetComponent.Unit`

没有采用 `TargetSelectorComponent.CurrentTargetId` 作为回退，因为它包含自动索敌语义，会导致“没手动锁定也偏镜头”。

### 4.2 有效目标判定

目标必须同时满足：

- 不为空
- 未销毁
- 不是自己
- 与玩家敌对
- 生命值大于 0

### 4.3 移动前视偏移

移动前视偏移直接使用客户端本地已有的移动预测数据：

- 优先 `UnitViewInterpolationComponent.PositionPredictionDirection / PositionPredictionSpeed`
- 回退 `UnitViewInterpolationComponent.PredictedDirection / PredictedSpeed`
- 最后才回退最近一次权威同步方向

当前实现公式为：

```csharp
speedRatio = Clamp01(moveSpeed / capabilityMoveSpeed);

maxMoveOffsetDistance = baseDistance > 0f
    ? baseDistance * 0.35f
    : moveSpeed;

moveOffset = moveDirection * (maxMoveOffsetDistance * speedRatio);
```

这个公式的语义是：

1. 速度越高，镜头朝移动方向让出的前方视野越大
2. 镜头前视偏移的上限仍然绑定在基础 `CameraDistance` 上

### 4.4 锁定目标偏移

设：

- `ownerPosition`：玩家世界位置
- `targetPosition`：目标世界位置
- `baseDistance`：当前 `Cinemachine3rdPersonFollow.CameraDistance`

当前实现公式为：

```csharp
midpointOffset = (ownerPosition + targetPosition) * 0.5f - ownerPosition;
midpointOffset.y = 0f;

maxOffsetDistance = baseDistance > 0f
    ? baseDistance * 0.5f
    : midpointOffset.magnitude;

lockOffset = Vector3.ClampMagnitude(midpointOffset, maxOffsetDistance);
```

这个公式的语义是：

1. 先把镜头跟随点往“玩家和目标的中点”方向推
2. 但最多不超过基础镜头能力的一半

因此它不是拍脑袋的调参值，而是一个按基线距离约束的比例算法。

### 4.5 最终偏移合成

当前实现不是二选一，而是“锁定优先下的合成”：

```csharp
if (hasLockTarget)
{
    moveOffset *= lockedMoveOffsetMultiplier;
}

desiredWorldOffset = moveOffset + lockOffset;
currentWorldOffset = Vector3.MoveTowards(currentWorldOffset, desiredWorldOffset, offsetFollowSpeed * Time.deltaTime);
```

也就是说：

1. 移动时，相机会朝移动方向前视
2. 有锁定目标时，移动前视偏移会先按倍率衰减，再叠加目标偏移
3. 停止和换向时，镜头不是瞬移，而是平滑收敛

## 7. 当前版本的边界

这次实现刻意没有做下面这些内容：

- 没做锁定时相机绕目标旋转
- 没单独做锁定态的额外旋转
- 没做锁定时 FOV 变化
- 没做自动索敌驱动镜头偏移
- 没把镜头参数抽成 Excel/配置表

原因很简单：先把镜头职责拆干净，先确认“移动前视偏移 + 锁定目标偏移”这条主链是不是你要的视频语义。

## 8. 后续校准建议

如果你跑起来后仍然觉得和视频不一致，建议按这个顺序校准：

1. 先看场景 `Virtual Camera` 的基础旋转是否需要调
2. 再看 `CombatCameraTuningView.MoveOffsetDistanceRatio` 是否需要增减
3. 再看 `CombatCameraTuningView.LockOffsetDistanceRatio` 是否需要增减
4. 再看 `CombatCameraTuningView.LockedMoveOffsetMultiplier` 是否需要落在 `0.3 ~ 0.5`
5. 再看 `CombatCameraTuningView.OffsetFollowSpeed` 是否需要更紧或更松
6. 最后才考虑 `CameraDistance` 是否需要从 `8.07` 调远

不建议回到旧做法重新在代码里写死：

- `Distance = 12`
- `Pitch = 60`

因为那会再次把场景真实参数和运行时参数拆成两套。
