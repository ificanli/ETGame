## 需求概述

当前局内武器系统已经具备双武器槽、点击切枪、弹药同步、自动开火的基础闭环，但距离参考图和目标体验仍有明显差距，主要集中在三类问题：

1. **战斗连续性不足**：当前枪械打空后只会原地换弹，不会自动切到另一把可用武器继续输出。
2. **交互完整性不足**：武器栏缺少长按丢弃、手动换弹等明确交互入口。
3. **HUD 表现不足**：当前只有两格武器槽，且每格仅展示图标和弹药文本，缺少选中强调、换弹进度、品质信息、空槽态和参考图风格的卡片化表现。

本专项的目标不是把这些问题归类为 BUG，而是统一按**需求优化项**处理，形成一个可分阶段推进的武器优化清单。

## 技术方案

### 整体思路

本专项不改变现有武器数据模型（双槽 WeaponComponent），而是在已有基础上**逐层补全缺口**：

1. **服务端补全自动切枪 + 后台换弹**：在 `BTWeaponCanFireHandler` 中检测空弹时自动切换到另一可用槽位，同时启动原槽后台换弹，使输出不中断。
2. **修正换弹协议**：当前 `C2M_Reload` 的字段是模板残留（Account/Password），需替换为正确的换弹语义字段，打通手动换弹入口。
3. **UI 分阶段强化**：先在现有 2 槽结构上补齐选中态、换弹进度条、空槽态等表现，再考虑扩展为参考图风格快捷栏。

选择此方案的原因：改动范围最小，不推翻已联调通过的双槽模型和自动开火流程，风险可控。

### Entity/Component 设计

#### WeaponComponent（修改，无需新增字段）

当前 `WeaponComponent` 已具备完整的双槽弹药、换弹状态、射击时间字段，足以支撑本专项所有子需求：

| 现有字段 | 用途 | 本专项使用场景 |
|----------|------|---------------|
| `Slot1WeaponId` / `Slot2WeaponId` | 槽位武器ID | 自动切枪时判断另一槽是否有武器 |
| `Slot1Ammo` / `Slot2Ammo` | 当前弹药 | 空弹判定、手动换弹可行性判定 |
| `Slot1Reloading` / `Slot2Reloading` | 换弹状态 | 后台换弹显示、重复请求拦截 |
| `Slot1ReloadFinishTime` / `Slot2ReloadFinishTime` | 换弹完成时间 | HUD 换弹进度条计算 |
| `Slot1EffectiveMagazineSize` / `Slot2EffectiveMagazineSize` | 生效弹匣容量 | 满弹判定、进度条分母 |
| `CurrentSlot` | 当前槽位 | 自动切枪写入目标 |

**结论**：本专项不需要给 `WeaponComponent` 新增字段。自动切枪逻辑仅需在 `WeaponComponentSystem` 中新增辅助方法（如 `TryGetAlternateFireableSlot`），通过组合现有字段完成判定。

#### WeaponConfig（无修改）

当前 `WeaponConfig` 包含 `Damage`、`AttackRange`、`AttackIntervalMs`、`MagazineSize`、`ReloadTimeMs`、`CanMoveWhileFire`、`FireLockTypeId`、`BulletCount`、`SpreadAngle` 等字段，足以满足所有子需求，无需新增配置列。

### 接口设计

#### 修正 `C2M_Reload` / `M2C_Reload`（Proto 修改）

当前定义存在严重问题——字段为 `Account` / `Password`，是模板复制残留，完全没有换弹语义。

**修正后定义：**

```protobuf
// ResponseType M2C_Reload
message C2M_Reload // ILocationRequest
{
    int32 RpcId = 1;
    int32 SlotIndex = 2; // 要换弹的槽位（0=当前槽, 1=槽1, 2=槽2）
}

message M2C_Reload // ILocationResponse
{
    int32 RpcId = 1;
    int32 Error = 2;
    string Message = 3;
}
```

**消息类型变更**：从 `ISessionRequest` 改为 `ILocationRequest`。  
原因：手动换弹需要把“槽位非法 / 无武器 / 满弹 / 正在换弹”等校验结果回给客户端，因此不能设计成 fire-and-forget 的 `ILocationMessage`。

#### 服务端 `C2M_ReloadHandler` 校验逻辑

| 校验项 | 拒绝条件 | ErrorCode |
|--------|----------|-----------|
| 槽位范围 | `SlotIndex` 不在 {0, 1, 2} | ERR_InvalidSlotIndex |
| 武器存在 | 目标槽无武器 | ERR_NoWeaponInSlot |
| 已满弹 | 当前弹药 == 生效弹匣容量 | ERR_AmmoFull |
| 正在换弹 | 目标槽 `Reloading == true` | ERR_AlreadyReloading |

校验通过后调用现有 `WeaponReloadHelper.TryStartReload()`，复用自动换弹全部流程。

以上 4 个错误码当前工程里**还不存在**，实现阶段需要新增到：

#### Proto 消息

变更汇总：

| Proto 文件 | 变更 | 说明 |
|------------|------|------|
| `StateSync_C_10700.proto` | 修改 | `C2M_Reload` 从 `ISessionRequest` 改为 `ILocationRequest`，字段替换为 `SlotIndex` |
| `StateSync_C_10700.proto` | 修改 | `M2C_WeaponAmmoState` 追加换弹进度条所需字段 |

建议把 `M2C_WeaponAmmoState` 扩展为：

```protobuf
message M2C_WeaponAmmoState // IMessage
{
    int64 UnitId = 1;
    int32 Slot1Ammo = 2;
    int32 Slot2Ammo = 3;
    bool Slot1Reloading = 4;
    bool Slot2Reloading = 5;
    int32 Slot1MagazineSize = 6;
    int32 Slot2MagazineSize = 7;
    float Slot1AttackRange = 8;
    float Slot2AttackRange = 9;
    int64 Slot1ReloadFinishTime = 10;
    int64 Slot2ReloadFinishTime = 11;
    int32 Slot1ReloadTimeMs = 12;
    int32 Slot2ReloadTimeMs = 13;
}
```

客户端用同步后的 `TimeInfo.Instance.ServerNow()` 计算：

- 剩余时间 = `ReloadFinishTime - ServerNow`
- 进度百分比 = `1 - 剩余时间 / ReloadTimeMs`

这样换弹进度条才能是**真实进度**，而不是无依据的本地假动画。

### 边界条件处理

#### FEAT-004 双武器均空弹场景

当两把武器均弹药为 0 时：

1. 当前槽空弹 → 检查另一槽：另一槽也空弹或正在换弹 → **不切枪**
2. 当前槽仍然触发自身换弹（现有逻辑不变）
3. 行为树在换弹期间 `CanFire` 返回 false，单位停火等待当前槽换弹完成
4. 换弹完成后恢复射击

#### FEAT-005 重复换弹 / 满弹请求

- 正在换弹中再次请求 → 返回 `ERR_AlreadyReloading`，客户端忽略
- 满弹时请求换弹 → 返回 `ERR_AmmoFull`，客户端可给予提示

### FEAT-004 空弹自动切副武器并让原武器后台换弹

#### 目标

当玩家当前武器打空时，如果另一槽位存在可用武器，则自动切换到另一把枪继续攻击，同时让原武器进入后台换弹，换弹完成后保留待切回状态。

#### 技术思路

- 服务端在自动开火判定阶段检查当前槽位弹药是否为 0。
- 若当前槽位可触发换弹，则先开启该槽位换弹。
- 若另一槽位存在武器、未换弹、且满足可射击条件，则自动切换 `CurrentSlot` 到另一槽位并广播。
- 客户端沿用现有 `M2C_SwitchWeapon` 和弹药刷新事件，补充“自动切枪”表现与后台换弹显示。

### FEAT-005 手动换弹入口

#### 技术思路

- 修正当前异常的 `C2M_Reload / M2C_Reload` 协议定义，使其承载 `SlotIndex` 或“当前武器换弹”语义。

  - 第二阶段：再根据操作习惯决定是否补键盘快捷键。
- 地图服接收后调用统一换弹逻辑，触发与自动换弹一致的状态同步和 UI 刷新。
