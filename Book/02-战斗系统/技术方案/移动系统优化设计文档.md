## 需求概述

当前移动系统采用服务器权威模式（客户端发方向→服务器算位置→62.5Hz广播），导致：
1. 自己角色有 50-100ms 网络延迟感
2. 服务器每 16ms 广播一次位置，带宽消耗大（10人场景约 366 KB/s）
3. 服务器 CPU 负担重（每 16ms 跑 NavMesh 计算）

目标：切换为**客户端权威移动 + 服务端校验**模式，实现零延迟手感和 78% 带宽降低。

## 技术方案

### 整体思路

```
当前：客户端发方向(30Hz) → 服务器算位置(62.5Hz) → 广播(62.5Hz) → 客户端校正
改后：客户端算位置(每帧) + NavMesh碰撞(本地) → 上报(20Hz) → 服务器校验 → 转发(20Hz)
```

**核心变化**：移动计算从服务器移到客户端。客户端有完整 NavMesh 数据，碰撞在本地即时完成。服务器只做合法性校验和转发，不再每 Tick 计算移动。

### 权威模型

| 模块 | 权威方 | 说明 |
|------|--------|------|
| 位置计算 | **客户端** | 本地每帧计算，零延迟 |
| 碰撞检测 | **客户端** | NavMesh TryMoveAlongSurface |
| 位置校验 | **服务器** | 速度上限 + NavMesh 范围检查 |
| 位置转发 | **服务器** | 校验通过后转发给其他玩家 |
| 非法纠正 | **服务器** | 拉回到最后合法位置 |
| 交互提示显示 | **客户端** | 本地读取预测位置即时判圈，服务端提示改为兜底 |
| 移动动画状态 | **客户端** | 本机读本地输入，远端读最近同步状态，不再等位置差 |

### 协议设计

#### C2M_MoveState（客户端 → 服务器，20Hz）
```
C2M_MoveState : ILocationMessage
    float PosX, PosY, PosZ         // 客户端当前位置
    float DirX, DirZ               // 移动方向
    float Speed                    // 当前速度
    uint Sequence                  // 客户端序列号
    long ClientTimeMs              // 客户端时间戳
```

#### M2C_MoveSync（服务器 → 其他客户端，20Hz 转发）
```
M2C_MoveSync : IMessage
    long UnitId
    float PosX, PosY, PosZ         // 服务器确认的位置
    float DirX, DirZ               // 方向（用于外推）
    float Speed                    // 速度（用于外推）
    uint Sequence                  // 序列号
```

#### M2C_MoveCorrection（服务器 → 违规客户端，仅非法时发）
```
M2C_MoveCorrection : IMessage
    float PosX, PosY, PosZ         // 纠正的合法位置
    uint AckSequence               // 纠正的序列号
```

**包体对比**：
- 旧 M2C_JoystickMove：~56 字节（含 Rotation 4 float）
- 新 M2C_MoveSync：~36 字节（去掉 Rotation，客户端从 Direction 推算）

### Entity/Component 设计

#### MoveValidationComponent（服务器端，新增）
```csharp
[ComponentOf(typeof(Unit))]
public class MoveValidationComponent : Entity, IAwake, IDestroy
{
    public float3 LastValidPosition;          // 上一次合法位置
    public long LastValidateTimeMs;           // 上一次校验时间
    public uint LastClientSequence;           // 上一次客户端序列号
    public int ViolationCount;               // 连续违规次数
    public float MaxSpeedTolerance = 1.5f;   // 速度容忍倍率（PvE 宽松）
    public float NavMeshSampleRadius = 1.0f; // NavMesh 采样半径
}
```

### 服务端校验规则（PvE 宽松策略）

```
收到 C2M_MoveState 时：
1. 序列号检查：seq <= lastSeq → 丢弃
2. 速度检查：
   - maxDistance = maxSpeed * deltaTime * 1.5倍容忍
   - actualDistance = distance(newPos, lastValidPos)
   - actualDistance > maxDistance → 非法
3. NavMesh 检查：
   - NavMesh.SamplePosition(newPos, 1.0m)
   - 采样失败 → 非法
4. 合法 → 更新位置 + 转发 M2C_MoveSync
5. 非法 → 发 M2C_MoveCorrection + ViolationCount++
6. 连续 10 次违规 → 日志告警（不踢人）
```

### 客户端上报策略

```
基础频率：20Hz（每 50ms 一次）

立即发送条件（不等 50ms）：
- 启动移动（从静止到移动）
- 停止移动（从移动到静止）
- 急转弯（方向变化 > 45°）

跳过发送条件：
- 静止状态且上一次已发送停止包
- 位置变化 < 0.01m 且方向未变
```

### 远程玩家外推（UnitViewInterpolationComponent 改造）

```
收到 M2C_MoveSync 时：
1. 更新权威位置 + 方向 + 速度

每帧 Update：
2. if speed > 0: 外推位置 += direction * speed * dt
3. 新权威包到达：平滑拉向权威位置
4. speed == 0：视觉位置平滑减速到权威位置（100-150ms）
```

### 停止特殊处理

停止是最敏感的时刻（容易出现滑行感）：
- 客户端松开摇杆 → 本地立即停止 + 立即发送 stop 包（不等 50ms）
- 服务器收到 speed=0 → 立即转发
- 其他客户端收到 speed=0 → 视觉平滑减速（不硬停）

### 交互提示与动画延迟回归修复（2026-04-17）

客户端权威切换后，交互提示和移动动画仍然存在额外延迟，根因拆成两层：

1. `ECA` 原先主要依赖服务端 `200ms` 定时扫描更新进圈状态，客户端虽然已经预测到目标位置，但提示层仍在等服务端圈检。
2. 移动动画原先主要依据可视位移/位置差推导，导致本机和远端单位都会额外叠加一层“等位置变化”的延迟。

修复策略：

1. 客户端本地加载当前地图的 `ECA` 导出配置，直接用本地预测位置每帧刷新 `InRangePointIds` 和 `FocusPointId`，交互按钮不再等待服务端提示。
2. 服务端在合法 `C2M_MoveState` 落地后，立即执行一次 `ECAHelper.CheckPlayerInRange(unit)` 作为兜底，保证服务端范围状态尽快追平。
3. 容器交互距离与 `ECA` 进圈检测统一为水平距离，消除地形高低差带来的口径不一致。
4. 本机角色移动动画直接读取 `LocalMoveSpeed/LocalMoveDirection`；远端玩家移动动画直接读取最近一次同步包里的 `Speed`，不再等待位置差阈值。
