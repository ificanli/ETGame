# 局内搜索与肉鸽需求文档（草案）

## 1. 文档目标
- 对齐"局内搜索容器 + 肉鸽成长"需求范围、流程、配置、协议与验收标准。
- 作为后续开发与联调基线，先确认需求一致，再进入编码阶段。

## 2. 当前基线（代码现状）

### 2.1 ECA / ECANode 现状
- `ECAPointMarker` 已支持 `Type + Params + FlowGraph` 配置导出。
- `ECAPointType` 已有 `Container`、`SpawnPoint`、`EvacuationPoint`。
- ECA 流程图已支持事件/条件/动作节点与 `OnTimerElapsed` 参数匹配。
- `ecanode` 已有 `ContainerComponent`，可记录容器状态和最近掉落请求。
- `ECAFlowActionKey` 里已有与搜索相关动作键：
  - `ShowInteractButton`
  - `HideInteractButton`
  - `StartSearchTimer`
  - `ShowSearchUI`
  - `OpenContainerUI`
  - `SpawnItemsToGround`
  - `PlayOpenAnim`

### 2.2 已存在但尚未串通的部分
- 交互入口当前主要是 `C2M_ClickUnitRequest`（现用于任务/NPC），尚未接入 ECA 容器交互链路。
- 搜索相关动作键中，服务端实际执行目前只覆盖了部分（例如 `StartSearchTimer`、`SetPointState`、`SpawnItemsToGround`）；UI类动作尚未形成客户端闭环。
- `ItemComponent/ItemHelper` 完整可用，可作为容器拾取入包基础能力。
- 肉鸽链路当前无专门组件、无专门协议、无专门UI。
- 怪物击杀事件源已存在：`DamageHelper` 在目标死亡时发布 `UnitDie` 事件。

## 3. 需求范围

## 3.1 功能A：局内搜索容器（ECA驱动）

### 3.1.1 玩家体验流程
1. 玩家进入容器交互范围。
2. 客户端显示"交互按钮提示UI"。
3. 玩家点击交互按钮。
4. 若容器首次开启：
   - 播放搜索进度UI与开启动画。
   - 计时结束后按配置生成产出并展示结果。
5. 若容器非首次开启：
   - 直接打开容器UI，展示剩余内容。
6. 玩家可执行：
   - 单个拾取
   - 一键拾取
   - 关闭容器
   - 搜索阶段可主动关闭UI中断搜索
7. 玩家离开范围时隐藏交互提示UI。

### 3.1.2 核心规则
- 容器掉落由服务端权威生成与保存，客户端只展示。
- 首次开启后容器内容应可被后续打开看到（直到被取空或容器失效）。
- 容器支持两种产出模式（由配置决定）：
  - 容器内产出：直接进入容器面板内物品列表。
  - 地面掉落：产出到地面再拾取。
- 搜索阶段允许中断（主动关闭UI、离开范围、死亡、切图等）。再次交互时重置计时，不保留进度。
- 容器允许多人同时打开查看；拾取冲突按"先到先得"处理。

### 3.1.3 ECA流程建议（容器模板）
- 事件：`OnPlayerEnterRange` -> 动作：`ShowInteractButton`
- 事件：`OnPlayerLeaveRange` -> 动作：`HideInteractButton`
- 事件：`OnPlayerInteract`
  - 条件：`PointStateEquals(state=Closed)` -> 动作链：
    - `ShowSearchUI`
    - `PlayOpenAnim`
    - `StartSearchTimer(seconds, timer_id=container_search)`
  - 事件：`OnTimerElapsed(timer_id=container_search)` -> 动作链：
    - `SetPointState(state=Opened)`
    - `GenerateContainerLoot(output_mode, loot_table, count, radius)`
    - `OpenContainerUI`
  - 条件：`PointStateEquals(state=Opened)` -> `OpenContainerUI`

说明：
- 新动作名：`GenerateContainerLoot`。
- `output_mode` 取值：
  - `ContainerPanel`：产出进入容器面板。
  - `GroundDrop`：产出到地面。

### 3.1.4 需要新增/补全的系统能力
- 服务端：
  - ECA交互请求处理（从玩家输入到 `ECAPointComponent.OnPlayerInteract`）。
  - 容器会话状态管理（谁在打开、是否被占用、是否可重复打开）。
  - 容器掉落生成与持久（按局内生命周期）。
  - 拾取逻辑（容器->背包）。
- 客户端：
  - 交互提示UI（靠近显示/离开隐藏）。
  - 搜索进度UI（首次开启可中断）。
  - 容器面板UI（列表、拾取、关闭）。

### 3.1.5 协议草案（命名待最终确认）
- `M2C_ECAInteractHint`：提示显示/隐藏（pointId、buttonText、inRange）
- `C2M_ECAInteract`：玩家交互请求（pointId）
- `M2C_ECASearchState`：搜索状态同步（pointId、state、remainMs）
- `C2M_ECASearchCancel`：主动关闭搜索UI并请求中断（pointId）
- `M2C_ContainerOpen`：打开容器返回内容（pointId、items、isFirstOpen、outputMode）
- `C2M_ContainerTakeItem`：拾取单个（pointId、itemId/slot）
- `C2M_ContainerTakeAll`：一键拾取（pointId）
- `C2M_ContainerClose`：关闭容器（pointId）
- `M2C_ContainerUpdate`：容器内容变更广播

## 3.2 功能B：肉鸽成长系统（击杀经验+升级+三选一Buff）

### 3.2.1 玩家体验流程
1. 玩家击杀怪物获得经验。
2. 经验累计达到阈值时升级。
3. 升级后立即获得属性成长。
4. 达到配置等级时触发"肉鸽三选一"弹窗（**当前实际：1、3、5、8 级**，旧设计草案写 2/4/6/9 已过时）。
5. 玩家选择1个选项后，立即获得对应Buff（接入现有Buff/BT体系）。

### 3.2.2 核心规则
- 经验与升级服务端权威。
- 升级数值全部走配置，不包含武器加成，仅处理基础成长决策（如生命/攻击/移速等基础属性）。
- 三选一先使用单池模型（一个选项池），复杂规则（去重、互斥、高阶权重）后续再扩展。
- 弹窗期间不暂停时间流逝，玩家与战斗照常进行。
- 若同一时刻连续升级触发多次选择，需队列化处理。

### 3.2.3 挂接点建议
- 击杀事件来源：`UnitDie`（已有）。
- 经验发放条件：`attacker` 为玩家且 `target` 为怪物。
- Buff生效方式：`BuffHelper.CreateBuff(...)`（已有体系）。

### 3.2.4 需要新增的模块能力
- 服务端组件（建议放 `statesync`，必要时拆子包）：
  - `RogueProgressComponent`：等级、经验、待选次数、已选记录。
  - `RogueChoiceComponent`：当前弹窗选项、超时策略、选择锁。
  - `RogueUpgradeHelper`：经验结算、升级判定、属性成长应用。
  - `RogueBuffApplyHelper`：选项->Buff映射并下发生效。
- 客户端UI：
  - 局内经验条/等级显示。
  - 三选一弹窗（展示描述、图标、效果预览）。

### 3.2.5 协议草案（命名待最终确认）
- `M2C_RogueExpSync`：经验、等级、下级阈值
- `M2C_RogueLevelUp`：升级通知、属性提升摘要
- `M2C_RogueChoicePopup`：三选一选项列表
- `C2M_RogueChooseOption`：提交选择
- `M2C_RogueChoiceResult`：选择结果与Buff应用回执

### 3.2.6 配置建议
- `RogueLevelConfig`：等级阈值、每级成长（HP/攻击/移速等）
- `RogueOptionConfig`：选项ID、权重、描述、BuffId、前置条件
- `RogueMonsterExpConfig`：怪物->经验值映射
- `RogueChoiceTriggerConfig`：按等级触发三选一（示例：2、4、6、9）

## 4. 关键数据与状态机

### 4.1 容器状态机（建议）
- `Closed`：未开启
- `Searching`：首次开启中（有进度）
- `Opened`：已开启可查看可拾取
- `Empty`：被取空（可选）
- `Locked/Occupied`：被其他玩家占用（可选）

### 4.2 肉鸽状态机（建议）
- `Normal`：正常战斗累计经验
- `ChoicePending`：待做三选一
- `Applying`：应用Buff中
- `Cooldown`：弹窗后短暂保护期（可选）

## 5. 日志与可观测性要求
- 容器链路关键日志：
  - 进入/离开范围
  - 交互请求
  - 搜索开始/中断/完成
  - 掉落生成、拾取结果
- 肉鸽链路关键日志：
  - 击杀来源、经验发放
  - 升级前后数据
  - 三选一下发与选择结果
  - Buff应用结果

## 6. 测试与验收标准

### 6.1 容器验收
- 玩家进入范围提示出现，离开消失。
- 首次交互出现搜索进度，结束后显示容器内容。
- 二次交互直接打开容器，不再走首次动画（除非重置规则另定）。
- 拾取后背包正确更新，容器内容同步减少。
- 两人并发操作同容器时行为符合并发规则。

### 6.2 肉鸽验收
- 击杀怪物稳定发经验。
- 升级阈值正确、属性增长正确。
- 指定等级触发三选一弹窗（当前按配置验证 2、4、6、9）。
- 选择后Buff正确挂载，效果可见且可验证。
- 连续升级触发多次选择时不丢失、不乱序。

## 7. 分期建议
- Phase 1：容器交互基础链路（范围提示、交互入口、首次搜索）
- Phase 2：容器物品展示与拾取（含并发）
- Phase 3：肉鸽经验与升级（无三选一）
- Phase 4：三选一与Buff接入（含UI）

2. 搜索允许人为关闭UI并中断；中断后再次交互重置计时。
3. 容器允许多人同时打开查看；拾取按先到先得。
4. 升级成长全部走配置，不包含武器，只做基础成长决策。
5. 三选一弹窗与搜索弹窗一致，不暂停时间。
6. 选项池先简单处理为单池，复杂规则后续详细设计。
7. 三选一触发改为"等级X触发"，由配置指定（**当前已落地：1、3、5、8 级**，旧草案 2/4/6/9 已过时）。
8. Buff复用现有 `BuffConfig`。
