## 决策记录

### 2026-04-16 - 主倒计时不复用 EvacuateTips
- **背景**：现有 `EvacuateTips` 只在玩家站上撤离点时显示，语义是局部撤离交互倒计时。
- **方案**：为整局主时限单独新增客户端运行时和顶部常驻 UI，继续保留 `EvacuateTips` 原职责。
- **原因**：整局主时限和撤离点局部倒计时生命周期不同、权威来源不同，混用会把后续维护搞乱。
- **替代方案**：直接复用 `M2C_ECAEvacuationState` 和 `EvacuateTips`。放弃原因是会把“整局主时限”伪装成“站点交互倒计时”，语义错误。

### 2026-04-16 - 首版继续复用现有失败结算链路
- **背景**：用户要求“倒计时结束撤离失败”，但当前工程只有撤离成功结算和失败/死亡结算两条主链。
- **方案**：保留 `RunTimeLimitComponent -> HP=0 -> UnitDie -> 失败结算` 现有链路，只补主倒计时显示和同步。
- **原因**：先满足产品目标，且不引入新的结算枚举、归档结果和 UI 分支，改动面最小。
- **替代方案**：新增独立“超时撤离失败”结算类型。放弃原因是会扩大到结算协议、归档统计、战绩展示和 UI 文案多处联动，不适合首版。

### 2026-04-16 - 主倒计时 UI 改为 MainPanel prefab 静态节点
- **背景**：用户明确要求“不要运行时创建，直接改 `MainPanel`”，并要求把 UI 任务的优先策略固化为 prefab 优先。
- **方案**：在 `MainPanel.prefab` 顶部中间补 `RunTimeLimitRoot` 和 `RunTimeLimitText` 静态节点；运行时仅负责文本赋值、显隐和警示色切换。
- **原因**：主倒计时属于稳定常驻 UI，资源层表达更清晰，也更符合 YIUI / prefab 优先的维护方式。
- **替代方案**：继续保留运行时创建节点。放弃原因是和当前明确约束冲突，且不利于后续资源维护。

### 2026-04-16 - 首次同步放在进图入口显式发送，不塞进 Component Awake
- **背景**：`RunTimeLimitComponent` 当前只在 `PlayerEnterMap_RunTimeLimit` 中集中创建。
- **方案**：组件创建后，由 `PlayerEnterMap_RunTimeLimit` 立即调用 `RunTimeLimitMessageHelper.SyncState` 发送首次剩余时间；后续加时继续在 `AdjustDuration` 里同步，销毁时统一清空。
- **原因**：这样“谁创建主时限、谁发首次同步”更直观，也避免把网络副作用直接塞进组件生命周期初始化。
- **替代方案**：在 `RunTimeLimitComponent.Awake` 中直接发消息。放弃原因是会把组件初始化和消息发送强耦合，不利于后续复用与排查。

## 问题日志

### 2026-04-16 - 仓库存在大量并行脏改动
- **现象**：`git status` 显示当前工作树中已有大量资源、第三方插件、Home、怪物、美术和测试相关改动。
- **原因**：仓库当前存在多条并行工作线。
- **解决**：本轮只修改本任务相关的计划、文档、消息、主时限和 `MainPanel` 相关文件，不清理、不回退其他改动。

### 2026-04-16 - 整仓编译被既有协议缺失阻塞
- **现象**：执行 `dotnet build ET.sln` 时，编译首先在已有 `M2C_WeaponDiscarded / C2M_DiscardWeapon / C2M_PickupGroundItem / M2C_PickupGroundItem` 类型缺失处失败，未先报到本轮新增主倒计时链路。
- **原因**：仓库当前存在并行中的“地面拾取/丢枪”协议与处理器改动，但对应 proto/生成代码尚未齐全，属于本轮任务外的既有阻塞。
- **解决**：记录为外部阻塞，当前不跨任务去补该协议线；本轮先完成主倒计时代码与文档回写，任务状态保持“开发中”。

### 2026-04-16 - Logs 目录存在 Unity 占用文件
- **现象**：按测试流程清理 `Logs/` 时，若干 `AssetImportWorker` / `shadercompiler` 日志文件被其他进程占用，目录无法整体删除。
- **原因**：本机当前有 Unity 相关后台进程持有部分日志文件句柄。
- **解决**：保留占用文件，直接执行非交互测试命令；`Test_RunTimeLimit_ClientSync_Test` 仍成功通过，不影响本轮功能验证。
