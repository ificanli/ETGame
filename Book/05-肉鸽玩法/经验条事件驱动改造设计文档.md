# 经验条事件驱动改造设计文档

**创建时间**：2026-04-11  
**最后更新**：2026-04-11  
**状态**：已完成  
**关联任务**：M0.2-W3 #2  
**涉及包**：cn.etetet.statesync

## 需求概述

当前肉鸽等级/经验 UI 已经能显示，但刷新方式仍是客户端轮询：

1. `MainPanelComponent.LateUpdate()` 每帧调用 `RefreshRogueLevelBar()`，读取 `RogueClientComponent`。
2. `HPViewComponent.LateUpdate()` 过去每帧调用 `UpdateDisplayLevelAndExp()`，同时处理显示等级和玩家自己的经验条。

这意味着客户端已经有明确的经验同步消息 `M2C_RogueExpSync`，但 UI 层没有直接订阅这次变化，而是每帧自己比对。

本次目标不是改经验和升级规则，而是把“等级/经验 UI 刷新”改为事件驱动：

- 收到肉鸽经验/等级变化时，立即发布客户端事件。
- `MainPanel` 和玩家 `HPView` 订阅事件并刷新。
- 去掉对应的每帧轮询入口。

## 技术方案

### 整体思路

保持现有服务端和协议不变，只调整客户端刷新链路：

1. 保留 `M2C_RogueExpSync` 作为经验/金币/等级同步主消息。
2. 新增客户端事件 `EventRogueProgressChanged`，作为“肉鸽等级/经验/金币状态有变化”的统一信号。
3. `M2C_RogueExpSyncHandler` 在更新 `RogueClientComponent` 后发布该事件。
4. `M2C_RogueLevelUpHandler` 在更新客户端等级后也发布该事件，保证等级文本能立即刷新。
5. `RogueClientHelper.ResetRuntime(root)` 在切图清理时发布该事件，避免 UI 继续保留旧经验值。
6. `MainPanel` 与玩家自己的 `HPView` 提供显式刷新方法，并由事件处理器调用。
7. `MainPanelComponent.LateUpdate()` 不再轮询肉鸽等级条；`HPViewComponent.LateUpdate()` 不再轮询玩家自己的肉鸽等级/经验，非玩家单位的显示等级轮询保持不变。

### 接口设计

不新增网络协议，不改现有消息体。

新增客户端事件：

```csharp
public struct EventRogueProgressChanged
{
}
```

事件触发入口：

1. `M2C_RogueExpSyncHandler`
2. `M2C_RogueLevelUpHandler`
3. `RogueClientHelper.ResetRuntime`

### 刷新范围

本次事件驱动只覆盖等级/经验相关 UI：

1. `MainPanel` 中的 `RogueLevelSlider`、`RogueLevelText`
2. 玩家自身 `HPView` 中的 `u_DataTxtLevel`、`u_DataCurExp`

不在本次改动范围内的内容：

1. 经验获取规则
2. 升级阈值
3. 选牌弹窗逻辑
4. 金币显示逻辑
5. 非玩家单位 `UnitDisplayLevelComponent` 的既有显示等级刷新机制
