# 肉鸽商人点位随机与血条隐藏设计文档

**创建时间**：2026-03-31
**最后更新**：2026-03-31
**状态**：已完成
**关联任务**：M0.2-W3 #10
**涉及包**：cn.etetet.statesync, cn.etetet.map

## 需求概述

修改现有肉鸽效果 `1001 金主驾到`，不新增新卡牌、不改主语义：

1. 选牌后仍然生成一个可交互商人。
2. 玩家交互后仍然获得金币。
3. 商人不再固定刷在玩家前方，而是从场景预摆的候选点中随机选择一个出生。
4. 商人客户端不显示头顶血条。

## 技术方案

### 整体思路

服务端继续沿用 `BTRogueSpawnMerchant -> RogueMerchantHelper` 这条现有触发链，只改“出生点解析”与“展示过滤”两段：

1. 地图中预摆 `SpawnPoint` 类型 ECA 点位。
2. 用自定义参数 `rogue_merchant_spawn=1` 标记哪些点可作为肉鸽商人候选点。
3. `SpawnPointManagerComponent` 在加载地图 ECA 时额外收集这批候选点。
4. `RogueMerchantHelper` 优先从候选点列表随机选择一个出生；如果地图未配置候选点，则回退到旧逻辑，继续在玩家前方生成，避免直接把已有地图跑坏。
5. 客户端血条创建不再对 `CampId <= 0` 的 NPC 创建 HPView。当前商人属于中立 NPC，服务端同步到客户端的 `CampId` 为 `0`，可直接复用已有同步字段，避免新增协议字段。

### 配置方式

场景内增加商人候选点时，按下面方式配置：

1. 在地图里放置 `ECAPointMarker`。
2. `PointType` 选择 `SpawnPoint`。
3. 在 `Params` 中增加一条：`rogue_merchant_spawn = 1`。
4. 需要多个候选点时，重复摆放多个点，运行时会随机选其中一个。

### Entity/Component 设计

不新增新的玩法 Entity。

运行时仅扩展已有 `SpawnPointManagerComponent` 的缓存数据，避免重复创建新的地图级组件。

### 数据结构

新增使用的 ECA 参数键：

- `rogue_merchant_spawn`
  - 值为 `1/true` 时，表示该 `SpawnPoint` 可作为肉鸽商人候选点。

不修改 Excel 卡牌表，不修改协议 `UnitInfo`。

## 实现步骤

1. 扩展 `SpawnPointManagerComponent`，支持缓存商人候选点并提供随机获取接口。
2. 改造 `RogueMerchantHelper`，优先使用候选点随机出生并保留旧逻辑回退。
3. 改造客户端血条创建条件，过滤中立 NPC。
4. 用 `dotnet build ET.sln` 做编译验证，并同步更新文档。

## 验收标准

- [ ] `1001 金主驾到` 触发后，商人优先出生在地图预摆候选点之一，而不是固定在玩家前方。
- [ ] 商人交互后仍然只给一次金币，并保持原有销毁逻辑。
- [ ] 商人客户端不显示头顶血条。
- [ ] 地图未配置候选点时，旧地图仍可通过回退逻辑正常生成商人。
