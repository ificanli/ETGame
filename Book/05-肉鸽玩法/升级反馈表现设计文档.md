**创建时间**：2026-04-21  
**最后更新**：2026-04-21

**涉及包**：cn.etetet.statesync

## 需求概述

当前肉鸽升级链路已经具备：

1. 服务端经验结算与升级判定。
2. 客户端 `M2C_RogueLevelUp` 升级通知。
3. 升级音效 `AudioHook_RogueEvents.cs -> AudioEventId.SfxLevelUp`。
4. 升级后继续弹出三选一选牌。

但视觉反馈仍然偏弱：

1. 角色升级瞬间没有明确的世界特效。
2. 主 HUD 上没有即时升级弹字，玩家很容易把“等级跳变”和“选牌弹窗”割裂看待。

用户本轮已经明确：

1. 范围先做“特效 + 弹字”，不额外扩到新的音效链路。
2. 只在**本地玩家自己升级**时播放，不给其他玩家/机器人做公共播报。
3. 特效位置取**角色中心略微上抬**。
4. 弹字使用 **YIUI** 体系承载，文案采用 `LEVEL UP`。

## 技术方案

### 整体思路

保持现有服务端协议与升级判定不变，只补客户端表现层：

1. 继续复用现有 `M2C_RogueLevelUp` 消息作为唯一升级触发入口。
2. 新增客户端视图侧并行 `MessageHandler`，专门处理升级表现，不污染现有数据同步 Handler。
3. 收到升级消息后，只对当前场景中的本地玩家 Unit 播放反馈：
   - 世界空间：播放现有 `LevelUp` 特效 prefab。
   - 屏幕空间：在 `MainPanel` 的 YIUI 根节点内创建局部升级弹字节点，按角色世界坐标投影到 HUD 上。
4. 弹字动画使用仓库已接入的 `DOTween`，执行“短暂放大 + 上浮 + 淡出”。

### 为什么这次不用新独立 Panel/Common prefab

本需求属于短时覆盖反馈，节点数量固定、结构简单，符合 `yiui-unity-mcp` 中“少量临时按钮或特效挂点可以运行时创建”的边界。

因此本轮不新增独立页面职责，而是：

1. 继续以 `MainPanel` 作为 YIUI 主承载面。
2. 在 `MainPanel` 内动态创建 `LevelUpToastRoot` / `LevelUpToastView`。
3. 让运行时代码只负责一次性节点初始化、文本赋值和动画播放。

这样能避免手改 `YIUIGen`，同时保持升级弹字依附于现有主 HUD，而不是再引入一套独立运行时 Canvas。

### DOTween 选型结论

本轮采用 `DOTween`，原因如下：

1. 仓库已正式接入 `DG.Tweening`，并已有 YIUI / Window tween 使用先例。
2. 升级弹字是纯 UI 动画，`DOTween` 对 `RectTransform` / `CanvasGroup` 的支持最直接。
3. 相比手写 `LateUpdate`，这类一次性放大、上浮、淡出序列用 `DOTween.Sequence()` 更短、更稳，也更容易在重复升级时中断并重播。

### 表现设计

#### 1. 升级特效

1. 使用现有资源 `Packages/cn.etetet.statesync/Assets/GameRes/Effect/LevelUp.prefab`。
2. 特效资源地址按当前 effect 短地址规则加载，location 使用 prefab 名 `LevelUp`。
3. 位置取本地玩家世界坐标 `+Y` 偏移，默认略高于角色中心。
4. 特效播放失败只记日志，不影响升级主流程。

#### 2. 升级弹字

1. 弹字文案默认固定为 `LEVEL UP`。
2. 弹字挂在 `MainPanel` 的局部全屏容器下，避免独立 Canvas 与层级漂移。
3. 弹出位置由角色世界坐标投影到 `MainPanel` 本地坐标得到。
4. 动画序列：
   - 初始缩放略小并透明度为 0。
   - 0.12s 内放大到主视觉尺寸并快速显现。
   - 同步上浮一小段距离。
   - 末段淡出并隐藏。
5. 如果短时间内连续升级，再次播放前会先 `Kill` 当前 tween，并从新位置重新开始。

### 接口设计

不新增网络协议，不改已有 `M2C_RogueLevelUp` 消息。

新增客户端视图侧消息处理器：

```csharp
[MessageHandler(SceneType.Client)]
public class M2C_RogueLevelUp_FeedbackHandler : MessageHandler<Scene, M2C_RogueLevelUp>
{
}
```

触发流程：

1. 消息到达客户端。
2. 现有 `M2C_RogueLevelUpHandler` 继续负责写入 `RogueClientComponent` 并发布进度事件。
3. 新增 `M2C_RogueLevelUp_FeedbackHandler` 负责：
   - 找到本地玩家 Unit
   - 播放 `LevelUp` 世界特效
   - 调用 `MainPanel` 播放升级弹字

### 不在本次范围内的内容

1. 不修改服务端升级判定与经验表。
2. 不改三选一弹窗逻辑。
3. 不扩到“别人升级我也能看到”的公共播报。
4. 不新增升级数值摘要面板。
5. 不重构现有音效系统，只复用已存在的升级音效 Hook。
