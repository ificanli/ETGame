**创建时间**：2026-04-16
**最后更新**：2026-04-16（主动退出服务端链调整为“响应先返回，结算与切图后台协程执行”）

**涉及包**：cn.etetet.statesync, cn.etetet.equipment, cn.etetet.proto, cn.etetet.test

## 需求概述

当前局内只有“靠近撤离点并等待倒计时完成”这条成功撤离入口，缺少一个随时可用的主动退出手段。用户本轮补充的明确要求如下：

- 在局内 `MainPanel` 常驻增加一个退出按钮。
- 不要二次确认，不弹窗。
- 点击后直接按“撤离成功”口径结束本局。
- 必须走现有成功撤离结算页，不能做旁路假结算。
- 结算页关闭后，正常回到大厅。
- 所有 UI 相关改动优先落 `prefab / Builder / YIUI` 资源层，不要运行时创建按钮。

## 技术方案

### 整体思路

本轮不把“主动退出”硬塞回撤离点 ECA 交互链，因为用户要的是“任意时刻立即成功撤离”，它不再依赖撤离点范围、撤离点倒计时或 `PlayerEvacuationComponent`。

正确收口方式是：

1. 在 `MainPanel.prefab` 静态补一个常驻 `ExitButton`。
2. 客户端点击后发送一条最小 `ILocationRequest`，语义为“当前局内玩家主动成功撤离”。
3. 服务端收到请求后，直接复用现有 `EvacuationSettlementHelper.Settle(player)`。
4. 结算消息仍走已有 `M2C_EvacuationSettlementHandler -> SettlementClientComponent -> SettlementPanel`。
5. 服务端在结算消息发出后，继续复用当前成功链的回大厅转图逻辑，让客户端看到完整成功结算页，关闭后再回大厅。

这样做的重点是“复用现有成功结算链”，而不是“伪造一个看起来像成功结算的新 UI 分支”。

### 为什么不直接复用 PlayerEvacuationComponent

现有成功撤离主链是：

1. 玩家站上撤离点。
2. `StartEvacCountdown` 创建 `PlayerEvacuationComponent`。
3. 服务端持续检查玩家是否在撤离点范围内。
4. 倒计时完成后执行 `EvacuationSettlementHelper.Settle(player)`。
5. 转图回 `Home`，客户端展示 `SettlementPanel`。

本次需求与这条链的前半段不一致：

- 没有撤离点范围前提。
- 没有局部撤离倒计时。
- 交互入口来自常驻按钮，而不是场景 ECA 点。

因此本轮只复用第 4、5 步，不复用第 1、2、3 步。

### 服务端实现

新增一条业务请求，例如：

```proto
// ResponseType M2C_QuickExitExtraction
message C2M_QuickExitExtraction // ILocationRequest
{
    int32 RpcId = 1;
}

message M2C_QuickExitExtraction // ILocationResponse
{
    int32 RpcId = 1;
    int32 Error = 2;
    string Message = 3;
}
```

服务端 `MessageLocationHandler<Unit, C2M_QuickExitExtraction, M2C_QuickExitExtraction>` 只做三件事：

1. 校验当前 `Unit` 是否处于有效局内场景，避免在 `Home / GateMap` 下误触。
2. 直接执行 `EvacuationSettlementHelper.Settle(unit)`。
3. 执行与当前成功撤离一致的回大厅转图逻辑。

注意点：

- 这条请求不新建 `PlayerEvacuationComponent`。
- 不下发新的成功结算协议，继续沿用 `M2C_EvacuationSettlement`。
- 不新开新的 `SettlementPanel` 分支，继续走 `SettlementClientComponent`。

### 客户端实现

客户端只负责：

1. 在 `MainPanel.prefab` 增加静态按钮节点。
2. 在 `MainPanelComponentSystem` 绑定点击。
3. 发送 `C2M_QuickExitExtraction` 请求。
4. 若请求返回失败，仅记日志并保持当前局内状态。

客户端不直接打开成功结算页，也不直接切场景。结算页和回大厅均继续由现有服务端权威消息与场景链驱动。

### UI 实现方式

本轮 UI 必须优先改 `prefab`：

- 在 `MainPanel.prefab` 的现有局内按钮区增加 `ExitButton` 静态节点。
- 按钮文案固定为“退出”。
- 该按钮局内常驻显示，不跟随撤离点/搜索点显隐。
- 不做运行时创建按钮。

为了尽量少侵入现有 YIUI 自动生成层，本轮允许采用“prefab 静态节点 + 手写层查找组件并绑定点击”的接法。只要按钮结构落在 prefab，且不在运行时动态造节点，就满足当前 UI 约束。

### 错误码

本轮新增一条最小业务错误码，用于表示“当前不在可主动退出的局内上下文”，例如：

- `ERR_QuickExitExtractionContextInvalid`

失败时客户端不弹确认框，也不弹额外失败窗，先保持日志与响应消息即可。

## Entity/Component 设计

本轮不新增新的运行时 Entity 或 Component。

复用现有：

- `SettlementClientComponent`
- `LoadoutComponent`
- `EvacuationSettlementHelper`

`MainPanelComponent` 只新增对退出按钮的 UI 引用缓存，不新增独立业务组件。

不新增成功结算下行协议，继续复用：

- `M2C_EvacuationSettlement`
