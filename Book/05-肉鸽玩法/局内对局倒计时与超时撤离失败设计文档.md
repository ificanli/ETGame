# 局内对局倒计时与超时撤离失败设计文档

**创建时间**：2026-04-16
**最后更新**：2026-04-16
**状态**：开发中
**关联任务**：M0.2-W3 #37
**涉及包**：cn.etetet.statesync, cn.etetet.map, cn.etetet.proto, cn.etetet.test

## 需求概述

当前搜打撤局内已经存在两条和时间相关的链路：

1. 服务端 `RunTimeLimitComponent` 会在玩家进入非 `Home/GateMap` 地图时启动整局主时限，默认 `8 分钟`。
2. 撤离点 `EvacuateTips` 只在玩家站上撤离点时显示局部撤离倒计时。

但玩家当前看不到“整局还剩多久”，也无法在 UI 层区分“整局主时限”和“撤离点局部倒计时”。用户本次要求补齐以下闭环：

- 局内主界面顶部常驻显示对局总倒计时。
- 倒计时使用服务端权威时间，不允许客户端本地硬编码启动。
- 继续兼容现有 `1044 时间延长` 对整局总时长的加成。
- 倒计时结束后，本局按“撤离失败”口径结束。

本轮首版进一步确认的约束：

- 不新开第三种结算结果类型。
- 到点后继续复用当前 `RunTimeLimitComponent -> HP=0 -> UnitDie -> 失败结算` 主链路。
- `SettlementPanel` 继续使用现有失败态展示；本轮重点是主倒计时 UI 和时间同步闭环。
- 现有 `EvacuateTips` 保持不动，继续只负责撤离点局部倒计时。

## 技术方案

### 整体思路

不去重写现有整局时限权威逻辑，而是在其上补一层“服务端剩余时间同步 + 客户端常驻显示”。

整体链路如下：

1. 玩家进入局内时，`PlayerEnterMap_RunTimeLimit` 仍由服务端在 `statesync` 内创建 `RunTimeLimitComponent`。
2. 新增一条 Map 下行消息，把当前主时限剩余毫秒同步给客户端。
3. 客户端新增一个轻量运行时组件，缓存“是否激活、结束时间戳、剩余毫秒”。
4. `MainPanel` 在 `LateUpdate` 中直接读取该运行时组件，每帧换算 `MM:SS` 并刷新顶部文本。
5. 当服务端因 `1044 时间延长` 调整总时长时，继续沿用现有 `AdjustDuration`，并在同一处补发新的剩余时间同步消息。
6. 当玩家离开局内地图、回到 `Home/GateMap` 或结算结束时，客户端主倒计时状态清空并隐藏 UI。

### 为什么不复用 EvacuateTips

`EvacuateTips` 当前语义是“站在撤离点上时，若持续停留 N 秒则成功撤离”，它依赖 `M2C_ECAEvacuationState` 和 `ECAInteractClientComponent`，属于局部交互倒计时。

本次新增的是“整局主时限”：

- 生命周期从玩家进局开始，到本局结束为止。
- 权威源来自 `RunTimeLimitComponent`，不是 `PlayerEvacuationComponent`。
- 显示位置要求是 `MainPanel` 顶部常驻，不是只在站点交互时弹出。

因此两者必须保持并行，不能复用同一套运行时数据。

### UI 实现方式

本轮改为“资源层静态节点 + 运行时数据刷新”方案，直接修改 `MainPanel.prefab`，不再在 `MainPanelComponentSystem` 中动态创建主倒计时骨架。

原因：

1. 主倒计时属于 `MainPanel` 的稳定常驻区块，应该落在 prefab，而不是运行时代码里拼出来。
2. 这样更符合 YIUI / prefab 优先的维护方式，后续美术和策划能直接在资源层看到布局。
3. 运行时逻辑只保留文本赋值、显隐和警示色切换，职责更清晰。

静态节点规则：

- 在 `MainPanel.prefab` 顶部中间增加 `RunTimeLimitRoot` 容器和 `RunTimeLimitText` 文本节点。
- 默认显示 `MM:SS`。
- 正常阶段使用浅色文本。
- 剩余 `60 秒` 内切换为警示色。
- 不显示毫秒，不做动画特效。

### 协议设计

新增一条 Map 下行消息，例如：

```proto
message M2C_RunTimeLimitState // IMessage
{
    int32 State = 1;      // None / Running
    int64 RemainMs = 2;   // 剩余毫秒
}
```

客户端不直接信任本地“开始时间 + 固定 8 分钟”，而是采用和撤离点倒计时相同的同步模式：

- 服务端下发 `RemainMs`
- 客户端收到消息时换算 `EndTimeMs = ClientNow + RemainMs`
- `MainPanel` 每帧读取并展示

这样可以兼容：

- 玩家刚进局时的首次同步
- `1044 时间延长` 导致的中途加时
- 回城/切图时的状态清空

### 服务端同步时机

需要在以下时机同步主时限状态：

1. 玩家进入非 `Home/GateMap` 地图、刚创建 `RunTimeLimitComponent` 后
2. `RunTimeLimitComponent.AdjustDuration()` 调整总时长后
3. 玩家离开局内、删除 `RunTimeLimitComponent` 时

其中第 3 点用于显式告诉客户端隐藏主倒计时，避免 UI 残留。

### 失败结算口径

本轮不新增 `TimeoutSettlement` 或 `ExtractionFailedSettlement`。

继续沿用当前链路：

1. `RunTimeLimitComponent.TriggerTimeoutDeath()`
2. 把玩家 `HP` 置 `0`
3. 触发 `UnitDie`
4. 走现有死亡/失败结算

这样可以保证：

- 不改已有掉落、回写、结算页和归档主链
- 不引入新的结果枚举、协议和 UI 分支
- 先满足“到点失败”的产品目标

## Entity/Component 设计

### RunTimeLimitClientComponent

挂在客户端根 `Scene` 上，字段规划：

- `bool IsActive`
- `long RemainMs`
- `long EndTimeMs`

它只存数据，不做逻辑。

### MainPanelComponent 扩展

继续保留以下显示状态缓存字段：

- `bool LastRunTimeLimitVisible`
- `long LastRunTimeLimitRemainSeconds`

主倒计时根节点和文本节点改为从 `MainPanel` 的 prefab / YIUI 绑定中直接取得，不再由手写层运行时创建。

## 接口设计

### 服务端 -> 客户端

新增：

```csharp
public partial class M2C_RunTimeLimitState : MessageObject, IMessage
{
    public int State { get; set; }
    public long RemainMs { get; set; }
}
```

### 客户端运行时约定

- `State == Running` 时写入 `RemainMs` 和 `EndTimeMs`
- `State == None` 时清空运行时并隐藏 UI
