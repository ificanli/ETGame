**创建时间**：2026-04-13

**关联任务**：M0.2-W3 #27
**涉及包**：cn.etetet.statesync, cn.etetet.eca, cn.etetet.ecanode, cn.etetet.map, cn.etetet.test

## 需求概述

在肉鸽局内增加一种配置驱动的任务点玩法。玩家靠近任务点时，局内显示交互按钮；点击交互按钮后先弹出“接受任务”UI；点击接受任务后才真正启动任务，刷出一波怪物；玩家清完这波任务怪后完成任务并获得固定金币奖励。

本次需求明确约束如下：

- 任务点由用户自行在场景中摆放，我方不处理场景摆点。
- 必须通过现有 ECA 点位配置实现，不新建单独 Excel。
- 同一局内同一个任务点只能完成一次。
- 完成奖励为固定金币，按当前肉鸽局内金币口径发放。

## 技术方案

### 整体思路

任务点继续复用现有 `ECAPointMarker + FlowGraph + Params` 体系，不接旧 `quest` 包。服务端在 `cn.etetet.statesync` 内扩展一个高层任务点闭环：

1. `OnPlayerEnterRange` 只显示交互提示。
2. 主界面点击交互按钮时，客户端先识别当前焦点点位是否为“任务点”。
3. 若是任务点，则先弹本地接受任务弹窗，不立即发起 `C2M_ECAInteract`。
4. 玩家点击“接受任务”后，再走现有 `C2M_ECAInteract -> ECA Flow -> StartTask`。
5. `StartTask` 动作由 `statesync` 注册到 `ECAFlowActionRegistry`，负责解析点位参数、创建任务运行时组件、刷怪并给怪挂任务归属标记。
6. 监听任务怪死亡事件，当剩余数量归零时发放固定金币、同步进度，并把点位标记为已完成/不可再次交互。

这样能保持显示层和业务层分离，符合 `statesync/AGENTS.md` 对 ECA 流程图的约定。

**注意**：按当前工程规范，靠近任务点显示交互提示 UI；点击交互后打开接受任务弹窗；点击接受任务后才真正开始刷怪任务。

### Entity/Component 设计

#### 服务端任务点状态

`RogueMissionTaskPointComponent`

- `PointId`
- `OwnerPlayerId`
- `RewardGold`
- `MonsterUnitConfigId`
- `SpawnCount`
- `RemainingMonsterCount`
- `Started`
- `Completed`

挂载在任务点 `Unit` 上，用于描述单局单点的任务状态。

#### 服务端任务怪标记

`RogueMissionTaskMonsterComponent`

- `TaskPointUnitId`
- `OwnerPlayerId`

挂在刷出来的任务怪身上，用来在死亡时回查所属任务点。

#### 客户端本地弹窗

`RogueMissionTaskPopupComponent`

- 动态创建的遮罩、窗口、标题、描述、奖励文案、接受/取消按钮引用
- `CurrentPointId`
- `Visible`

挂在当前场景，属于纯客户端显示层。

### 数据结构

不新增 Excel，直接使用 `ECAPointMarker.Params` 承载配置：

- `mission_task_title`
- `mission_task_desc`
- `mission_task_accept_text`
- `mission_task_monster_unit_config_id`
- `mission_task_monster_count`
- `mission_task_reward_gold`

任务点 FlowGraph 固定模板如下：

1. `OnPlayerEnterRange -> ShowInteractButton`
2. `OnPlayerLeaveRange -> HideInteractButton`
3. `OnPlayerInteract -> StartTask`

### 配置约定

用户摆点时使用 `RangeTrigger` 类型即可，任务点识别只依赖参数是否齐全，不依赖额外挂脚本。

当前编辑器约定补充如下：

- 当点位挂载的 `FlowGraph` 中包含 `StartTask` 动作时，`ECAPointMarker` 会自动把任务点需要的 6 个参数模板补到点位 `Params`
- `RogueMissionTaskFlow` 已内置这 6 个参数模板默认值；摆点时直接在 Inspector 中改值即可，不需要手敲 key

推荐参数填写示例：

| Key | Value 示例 | 说明 |
|------|------------|------|
| `mission_task_title` | 清理据点 | 接受任务弹窗标题 |
| `mission_task_desc` | 消灭附近出现的 6 只怪物 | 接受任务弹窗描述 |
| `mission_task_accept_text` | 接受任务 | 接受按钮文案 |
| `mission_task_monster_unit_config_id` | 1012 | 刷出的正式怪物 `UnitConfigId` |
| `mission_task_monster_count` | 6 | 本波刷怪数量 |
| `mission_task_reward_gold` | 300 | 完成奖励金币 |

当前任务点刷怪的随机散布范围直接沿用 `SpawnMonstersHelper` 的硬编码偏移，`X/Z` 两轴均为 `[-10,10]`。若后续需要按点位单独配置刷怪半径，再补参数 key 和运行时解析。

- [ ] 玩家靠近任务点时，局内出现交互按钮。

- [ ] 同一局内同一点位无法重复完成任务。
- [ ] 非任务点交互按钮行为不受本次修改影响。
