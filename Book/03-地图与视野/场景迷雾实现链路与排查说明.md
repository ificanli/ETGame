# 场景迷雾实现链路与排查说明

## 1. 文档目的

- 说明当前项目中场景迷雾的实际实现链路。
- 区分“迷雾数据”“场景迷雾投射”“小地图/大地图 UI 迷雾”三条链路。
- 提供最短排查路径，方便直接下断点确认问题点。

## 2. 总体链路

当前迷雾实现可以拆成四层：

1. 地图初始化层
2. 迷雾运行时数据层
3. 场景迷雾投射层
4. UI 迷雾显示层

核心流程如下：

1. 当前地图创建时，为 `Scene` 挂上 `MinimapRuntimeComponent`。
2. 自己的单位创建后，把 `MyUnitId` 绑定进 `MinimapRuntimeComponent`。
3. `SceneFogComponent` 每帧刷新迷雾贴图时，调用 `MinimapRuntimeComponent.RefreshLocalFog()`。
4. `RefreshLocalFog()` 根据友方单位位置和 `NumericType.AOI` 计算当前可见格子，并累计到已探索格子。
5. `SceneFogComponent` 把格子数据烘成 `FogTexture`。
6. `SceneFogComponent` 把 `FogTexture`、`FogBounds`、`OutsideFogColor` 等参数传给 `ET/SceneFogOverlay` shader。
7. shader 通过场景深度重建世界坐标，把当前屏幕像素映射到 fog uv，最终把迷雾盖到主相机画面上。
8. 折叠小地图和展开大地图也会读取同一份 `CurrentVisibleCells/ExploredCells`，各自绘制 UI 迷雾层。

## 3. 初始化链路

### 3.1 挂载小地图运行时

文件：

- `Packages/cn.etetet.statesync/Scripts/Hotfix/Client/Scene/AfterCreateCurrentScene_AddMinimapRuntime.cs`

作用：

- 当前地图 `Scene` 创建后，自动添加 `MinimapRuntimeComponent`。

### 3.2 绑定自己的单位

文件：

- `Packages/cn.etetet.statesync/Scripts/Hotfix/Client/Scene/AfterMyUnitCreate_BindMinimapRuntime.cs`

作用：

- 自己的单位创建后，把 `runtime.MyUnitId` 绑定成自己的单位 ID。

这个步骤如果没成功，后面 `GetMyUnit()`、`TryGetMyPosition()`、`RefreshLocalFog()` 都会失效。

### 3.3 挂载场景迷雾组件

文件：

- `Packages/cn.etetet.statesync/Scripts/HotfixView/Client/Scene/AfterCreateCurrentScene_AddSceneFogComponent.cs`

作用：

- 当前地图 `Scene` 创建后，自动添加 `SceneFogComponent`。

## 4. 迷雾运行时数据层

文件：

- `Packages/cn.etetet.statesync/Scripts/Model/Client/MinimapRuntimeComponent.cs`
- `Packages/cn.etetet.statesync/Scripts/Hotfix/Client/MinimapRuntimeComponentSystem.cs`

### 4.1 运行时数据结构

`MinimapRuntimeComponent` 中与迷雾直接相关的字段：

- `WorldMinX`
- `WorldMaxX`
- `WorldMinZ`
- `WorldMaxZ`
- `FogCellSize`
- `CurrentVisibleCells`
- `ExploredCells`

说明：

- `CurrentVisibleCells` 表示当前团队可见格子。
- `ExploredCells` 表示当前地图内已经探索过的格子。

### 4.2 地图参数装载

入口：

- `MinimapRuntimeComponentSystem.ResetRuntime()`

作用：

- 从 `MinimapConstConfig` 读取当前地图的边界和迷雾参数。

读取的关键配置有：

- `MapName.WorldMinX`
- `MapName.WorldMaxX`
- `MapName.WorldMinZ`
- `MapName.WorldMaxZ`
- `MapName.FogCellSize`

### 4.3 网格尺寸推导

入口：

- `MinimapRuntimeComponentSystem.TryGetFogGridSize()`

作用：

- 使用地图边界和 `FogCellSize` 推导网格宽高。

公式逻辑：

- `width = WorldMaxX - WorldMinX`
- `height = WorldMaxZ - WorldMinZ`
- `gridWidth = ceil(width / FogCellSize)`
- `gridHeight = ceil(height / FogCellSize)`

因此如果边界配置不对，后面的场景迷雾和 UI 迷雾都会一起错。

## 5. 当前可见区域计算链路

文件：

- `Packages/cn.etetet.statesync/Scripts/Hotfix/Client/MinimapRuntimeComponentSystem.cs`

### 5.1 计算入口

入口：

- `MinimapRuntimeComponentSystem.RefreshLocalFog()`

流程：

1. 清空 `CurrentVisibleCells`
2. 取 `Scene.UnitComponent`
3. 取 `MyUnit`
4. 遍历当前客户端存在的单位
5. 只保留与自己 `CampHelper.IsFriendly()` 为友方的单位
6. 读取每个友方单位 `NumericComponent` 里的 `NumericType.AOI`
7. 按圆形范围写入可见格子
8. 把当前可见格子累计到 `ExploredCells`

### 5.2 圆形写格实现

入口：

- `MinimapRuntimeComponentSystem.AppendFogCells()`

作用：

- 以某个友方单位位置为圆心
- 以其 `AOI` 为半径
- 逐格检查圆形覆盖
- 将命中的格子写入 `CurrentVisibleCells`

### 5.3 这一层的硬前提

要让迷雾正常打开，至少需要满足：

- `runtime.MyUnitId` 已正确绑定
- `runtime.GetMyUnit()` 能拿到自己
- 当前客户端 `UnitComponent` 里确实有友方单位
- 这些友方单位存在 `NumericComponent`
- `NumericType.AOI` 不是 0

只要其中一个条件不成立，`CurrentVisibleCells` 就可能始终为空。

## 6. 场景迷雾投射链路

文件：

- `Packages/cn.etetet.statesync/Scripts/ModelView/Client/SceneFogComponent.cs`
- `Packages/cn.etetet.statesync/Scripts/HotfixView/Client/SceneFogComponentSystem.cs`
- `Packages/cn.etetet.statesync/Assets/GameRes/Graphics/Shaders/SceneFogOverlay.shader`

### 6.1 每帧主入口

入口：

- `SceneFogComponentSystem.Update()`

流程：

1. 找当前地图上的 `MinimapRuntimeComponent`
2. 调 `RefreshRuntimeSettings()`
3. 调 `RefreshFogTexture()`
4. 找 `Camera.main`
5. 调 `EnsureOverlay()`
6. 调 `UpdateOverlayTransform()`
7. 调 `UpdateOverlayMaterial()`
8. 显示覆盖层

### 6.2 FogTexture 生成

入口：

- `SceneFogComponentSystem.RefreshFogTexture()`

作用：

- 根据 `CurrentVisibleCells/ExploredCells` 生成一张 `Texture2D`
- 当前可见格使用 `FogColorVisible`
- 已探索未可见格使用 `FogColorExplored`
- 未探索格使用 `FogColorUnexplored`

注意：

- `runtime.RefreshLocalFog()` 是在这里被调用的。
- 也就是说，场景迷雾刷新是当前迷雾数据更新的主驱动。

### 6.3 覆盖层对象

入口：

- `SceneFogComponentSystem.EnsureOverlay()`
- `SceneFogComponentSystem.CreateOverlay()`

作用：

- 在 `Camera.main` 下创建一个覆盖网格
- 给它挂上 `SceneFogProjectorView`
- 给 `MeshRenderer` 赋 `ET/SceneFogOverlay` 材质

### 6.4 传入 shader 的关键参数

入口：

- `SceneFogComponentSystem.UpdateOverlayMaterial()`

关键参数：

- `_FogTex`
- `_FogBounds = (WorldMinX, WorldMinZ, width, height)`
- `_OutsideFogColor`
- `_EdgeSoftness`

这里的 `width` 和 `height` 不是 `WorldMaxX/WorldMaxZ` 本身，而是：

- `width = WorldMaxX - WorldMinX`
- `height = WorldMaxZ - WorldMinZ`

## 7. Shader 工作方式

文件：

- `Packages/cn.etetet.statesync/Assets/GameRes/Graphics/Shaders/SceneFogOverlay.shader`

核心逻辑：

1. 从场景深度纹理采样当前屏幕像素深度
2. 用 `ComputeWorldSpacePosition` 把屏幕像素还原成世界坐标
3. 取世界坐标的 `xz`
4. 用 `(positionWS.xz - _FogBounds.xy) / _FogBounds.zw` 得到 fog uv
5. 如果 uv 不在 `[0, 1]`，直接返回 `_OutsideFogColor`
6. 如果 uv 在范围内，则去 `FogTexture` 采样颜色

这意味着：

- `FogBounds` 配错时，屏幕大量像素会直接走 `_OutsideFogColor`
- 视觉上会像“整片黑雾把场景压住”

## 8. UI 迷雾链路

### 8.1 折叠小地图

文件：

- `Packages/cn.etetet.statesync/Scripts/HotfixView/Client/YIUISystem/Main/MainPanelComponentSystem.cs`

关键入口：

- `RefreshMinimapTexture()`
- `RefreshMinimapFog()`

作用：

- `RefreshMinimapTexture()` 负责底图 uv 裁切
- `RefreshMinimapFog()` 负责把 `CurrentVisibleCells/ExploredCells` 画成一张 UI fog 贴图

### 8.2 展开大地图

文件：

- `Packages/cn.etetet.statesync/Scripts/HotfixView/Client/YIUISystem/Main/MapWorldPanelComponentSystem.cs`

关键入口：

- `RefreshWorldMapTexture()`
- `RefreshWorldMapFog()`

作用：

- 大地图复用同一份运行时数据
- 也是把 `CurrentVisibleCells/ExploredCells` 重新画成一张 UI fog 贴图

### 8.3 与场景迷雾的关系

UI 迷雾和场景迷雾共用同一份 fog 真相：

- `CurrentVisibleCells`
- `ExploredCells`

但 UI 本身不会主动触发 `RefreshLocalFog()`。

当前实现里，真正推动 fog 数据刷新的主要入口仍然是：

- `SceneFogComponentSystem.RefreshFogTexture()`

## 9. 黑屏/全黑的常见问题点

### 9.1 `CurrentVisibleCells.Count == 0`

优先检查：

- `runtime.MyUnitId` 是否绑定成功
- `runtime.GetMyUnit()` 是否为空
- 友方单位是否存在于客户端 `UnitComponent`
- 友方单位的 `NumericType.AOI` 是否为 0

结论：

- 这一类问题属于“迷雾数据真相没算出来”

### 9.2 `_FogBounds` 不覆盖真实地图

表现：

- 小地图 fog 可能还能看见局部变化
- 但场景画面大面积是 `_OutsideFogColor`

优先检查：

- `WorldMinX`
- `WorldMaxX`
- `WorldMinZ`
- `WorldMaxZ`
- shader inspector 里的 `_FogBounds`

结论：

- 这一类问题属于“场景投射坐标映射错了”

### 9.3 主相机深度链路有问题

当前 shader 依赖场景深度。

相关代码：

- `SceneFogComponentSystem.Update()` 里会设置 `camera.depthTextureMode |= DepthTextureMode.Depth`

如果深度不可用，世界坐标还原就会异常。

### 9.4 UI 黑但场景不黑

优先看：

- `RefreshMinimapFog()`
- `RefreshWorldMapFog()`
- 小地图/大地图底图纹理是否正常

结论：

- 这一类问题更接近 UI 迷雾层或底图链路，不一定是场景 fog 真相错误

## 10. 推荐断点顺序

建议按下面顺序查，最快：

1. `MinimapRuntimeComponentSystem.ResetRuntime()`
2. `AfterMyUnitCreate_BindMinimapRuntime.Run()`
3. `MinimapRuntimeComponentSystem.RefreshLocalFog()`
4. `MinimapRuntimeComponentSystem.AppendFogCells()`
5. `SceneFogComponentSystem.RefreshFogTexture()`
6. `SceneFogComponentSystem.UpdateOverlayMaterial()`
7. `MainPanelComponentSystem.RefreshMinimapFog()`
8. `MapWorldPanelComponentSystem.RefreshWorldMapFog()`

每一步建议重点看：

1. `MapName`
2. `WorldMinX/WorldMaxX/WorldMinZ/WorldMaxZ`
3. `FogCellSize`
4. `CurrentVisibleCells.Count`
5. `ExploredCells.Count`
6. `_FogBounds`

## 11. 一句话判断法

如果你只想快速判断问题在哪一层，可以直接用下面的规则：

- `CurrentVisibleCells.Count == 0`：优先查视野计算链路
- `CurrentVisibleCells.Count > 0` 但场景仍整片黑：优先查 `_FogBounds`
- 场景正常但小地图/大地图黑：优先查 UI fog 或底图链路

## 12. 补充说明

当前项目里“场景迷雾”和“小地图/大地图 UI 迷雾”不是同一个渲染对象，但它们共用同一份 fog 数据真相。

所以排查时不要混成一个问题，要先分清：

- 是 `CurrentVisibleCells/ExploredCells` 没算出来
- 还是 `_FogBounds` 映射错了
- 还是 UI 自己的底图/遮罩链路有问题
