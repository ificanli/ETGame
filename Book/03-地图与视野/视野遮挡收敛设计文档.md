# 视野遮挡收敛设计文档

**创建时间**：2026-04-16
**最后更新**：2026-04-17
**状态**：开发中
**关联任务**：M0.2-W3 #20
**涉及包**：cn.etetet.statesync, cn.etetet.map, cn.etetet.recast, cn.etetet.test

## 需求概述

当前视野系统仍存在与旧索敌问题同源的缺口：

1. 主画面迷雾当前按圆形/格子直接开图，没有墙体遮挡。
2. 服务端给客户端同步单位时，仍可能把墙后单位直接创建出来。
3. 小地图/大地图 marker 直接跟随客户端单位创建移除，因此也会继承穿墙可见问题。
4. `Ward` 提供的视野和 `Detector` 揭示敌方眼的逻辑，目前也只按距离，没有统一墙体遮挡。

本轮目标不是只修一处表现，而是把“单位本体 / 小地图标记 / 客户端可见性 / 主画面迷雾 / 大地图迷雾 / Ward / Detector”统一到同一套不可穿墙视野规则。

## 已确认口径

1. **团队共享视野保留**：如果自己被墙挡住，但队友或友方眼对目标无遮挡，则目标仍应进入团队共享视野。
2. **Ward 受墙体遮挡**：眼只能看到自己无遮挡的目标。
3. **Detector 受墙体遮挡**：侦查只揭示“自己到敌方眼无遮挡且在侦查半径内”的敌方眼。
4. **LoS 兼容兜底沿用索敌规则**：`PathfindingComponent` 缺失、起点投影失败或 `Raycast` 失败时，仍先按兼容策略放行，避免非标准场景直接整片全黑/全不可见。

## 技术方案

### 整体思路

本轮不改 AOI 核心包的可见性算法，原因是：

1. `cn.etetet.aoi` 当前未声明 `cn.etetet.recast` 依赖，不能合法直接接入 `PathfindingComponent.HasLineOfSight(...)`。
2. AOI 本身只在 `cell` 变化时增量更新，可用于“范围粗筛”，但不能单独解决“同一 AOI cell 内绕墙/出墙”的动态切换。

因此本轮采用“两层收敛”：

1. **AOI 继续负责粗范围**：
   - 仍由 AOI 决定“是否进入潜在观察范围”。
   - 不把墙体逻辑硬塞进 AOI 包。
   - 当玩家当前持有狙击枪时，AOI 最终结果会被武器运行时射程临时覆盖，确保粗范围和真实视野一致。
2. **地图/视野层负责最终可见性**：
   - 服务端在现有 `TacticalVisionComponent` 的定时刷新里，计算每个玩家“最终应该看到的单位集合”。
   - 该集合同时考虑：自己无遮挡直视、队友无遮挡共享、友方眼无遮挡共享、侦查无遮挡揭示敌方眼、草丛/遮蔽隐藏。
   - 通过 `ExtraUnitVisibilityComponent` 的“额外可见 + 额外隐藏”双向 diff，把客户端单位创建/移除收敛到最终口径。
3. **客户端迷雾复用同一套 Recast LoS**：
   - 客户端 `MinimapRuntimeComponent.RefreshLocalFog()` 不再直接按圆形开格子。
   - 改为对每个友方视野源（自己、队友、友方眼）逐格做 `HasLineOfSight(...)` 判定，只把无遮挡格子写入 `CurrentVisibleCells`。

### 统一 LoS 规则

底层统一复用现有索敌使用的 Recast 视线规则：

1. 调用 `PathfindingComponent.HasLineOfSight(float3 from, float3 to, float unitRadius, float maxVerticalDelta, out float hitT)`。
2. 只投影起点到 NavMesh，终点保持原始世界坐标。
3. `|from.y - to.y| > 4f` 直接视为被挡住。
4. `hit.t < 1` 视为中途撞墙，不可见。
5. `hit.t >= 1` 或 `hit.t == float.MaxValue` 视为无遮挡。
6. `PathfindingComponent` 缺失、起点投影失败/过远、`Raycast` 失败时按兼容策略放行。

这次统一的是“能不能看见”这一层，不复用索敌的评分、续锁缓存和战斗优先级。

### 服务端收敛方案

#### 1. `statesync` 增加共享 LoS 辅助

在 `cn.etetet.statesync/Scripts/Hotfix/Share` 增加通用辅助，用于：

1. 单位到单位无遮挡判断
2. 单位到世界点无遮挡判断
3. 从 `NumericType.AOI` 推导世界半径（供友方眼视野同步到客户端迷雾使用）

`map` 包只负责最终可见性过滤，不直接引用 `recast`。

#### 2. `ExtraUnitVisibilityComponent` 扩展“隐藏目标”能力

当前组件只维护：

1. `ViewerToTargets` / `TargetToViewers`：额外可见目标
2. `ViewerToConcealedTargets`：草丛等遮蔽导致的隐藏目标

本轮新增：

1. `ViewerToSuppressedTargets`：因墙体遮挡/敌方眼未被侦查等原因，当前应被额外隐藏的目标

并补一组 diff 接口：

1. `ResetViewerSuppressedTargets(Unit viewer, HashSet<long> targetIds)`
2. `IsTargetSuppressed(long viewerId, long targetId)`

效果：

1. 目标虽然还在 AOI 范围内，但若本轮应被视野规则隐藏，服务端会主动给该玩家发 `M2C_RemoveUnits`。
2. 目标后来重新满足可见条件时，再主动补发 `M2C_CreateUnits`。
3. `MapMessageHelper` 广播消息前也会统一检查 suppress/conceal 状态，避免“单位没创建但后续同步消息还在发”。

#### 3. `TacticalVisionHelper.Refresh()` 计算最终视野

在现有战术视野刷新流程中，统一收敛三类结果：

1. `extraTargetIds`
   - 队友始终共享的位置型目标：友方玩家、友方眼
   - 队友自身无遮挡直视到的敌对目标
   - 友方眼无遮挡看到的敌对目标
   - 侦查无遮挡揭示到的敌方眼
2. `suppressedTargetIds`
   - 玩家原生 AOI 中存在，但当前不应显示给该玩家的目标
   - 例如：墙后怪物、墙后敌方玩家、未被侦查揭示的敌方眼
3. `conceal` 结果继续沿用现有草丛逻辑

最终执行顺序：

1. 清理陈旧关系
2. 计算 `extraTargetIds`
3. 计算 `suppressedTargetIds`
4. `ResetViewerTargets(viewer, extraTargetIds)`
5. `ResetViewerSuppressedTargets(viewer, suppressedTargetIds)`
6. 清理非活跃观察者

### 客户端迷雾收敛方案

#### 1. 视野源统一

客户端迷雾不再只用“自己一个圆”或“友军 AOI 方块”，而是统一收敛为多个视野源：

1. 当前玩家
2. 同阵营友方玩家
3. 当前客户端可见的同阵营友方眼

#### 2. 视野半径来源

1. 玩家主视野半径：
   - 当前持有狙击枪时，优先使用当前武器生效射程
   - 其余情况优先使用 `Minimap.SceneFog.VisionRadius`
   - 只有 `SceneFog.VisionRadius <= 0` 或未配置时，才回退到服务端同步过来的 `NumericType.AOI`
2. 友方眼视野半径：
   - 本轮把眼的 `VisionRadius` 同步写入 `NumericType.AOI`
   - 客户端读取该数值转成世界半径，避免新增临时同步协议

#### 3. 格子可见判定

对每个视野源，遍历其半径内候选格子：

1. 格子中心在半径内
2. 视野源到格子中心通过 `HasLineOfSight(...)`
3. 满足时写入 `CurrentVisibleCells`

这样主画面迷雾、小地图迷雾和大地图迷雾都自然复用同一份无遮挡格子真相。

#### 4. 主画面迷雾移除 Shader 圆形兜底

当前 `SceneFogOverlay.shader` 还会根据 `_VisionRadius` 在 Shader 端额外画一个以玩家为圆心的实时可见圈。  
若只改 `CurrentVisibleCells`，主画面仍会沿这层旧逻辑穿墙。

因此本轮同时调整 `SceneFogComponentSystem`：

1. 场景迷雾贴图与小地图/大地图一致，直接把 `CurrentVisibleCells` 写成可见色。
2. 将 `_VisionRadius` 固定为 `0`，关闭 Shader 端圆形兜底。
3. 主画面迷雾由网格可见结果统一驱动，不再绕过墙体 LoS。

## 验收标准

- [ ] 玩家自己隔墙看不到墙后怪物/敌方玩家，客户端不再创建其单位本体。
- [ ] 小地图/大地图 marker 不再显示墙后目标。
- [ ] 主画面迷雾、小地图迷雾、大地图迷雾都不会直接穿墙开图。
- [ ] 若队友或友方眼对目标无遮挡，则团队共享视野仍然成立。
- [ ] `Ward` 的视野不能穿墙。
- [ ] `Detector` 只有在“半径内 + 无墙遮挡”时才揭示敌方眼。
- [ ] 当前持有狙击枪时，玩家主视野半径直接等于当前生效射程，并且 AOI 订阅会立即刷新。
- [ ] 保持现有 grass/concealment 逻辑不回退。
- [ ] `dotnet build ET.sln` 通过。
