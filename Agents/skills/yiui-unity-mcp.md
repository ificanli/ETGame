# yiui-unity-mcp - 使用 Unity MCP 以可维护方式构建 YIUI

这个 skill 只处理一类问题：

- 用 `Unity MCP + YIUI` 做**页面资源结构、生成衔接和手写 UI 逻辑接入**

它负责的是：

- 新增或修改 `Panel / Item / 子界面 / 弹窗`
- 调整 YIUI prefab 结构
- 重新生成 YIUI 绑定代码
- 处理 `YIUIGen` 自动生成代码与手写 `YIUIComponent`、`YIUISystem` 的衔接
- 判断一个页面是否应该拆分，而不是继续往现有 prefab 里堆

它不负责的是：

- 手机适配、按钮/字体/间距、`CanvasScaler`、Root 基线
- ET `EntityRef`、`await` 后访问 Entity、分析器问题
- `dotnet build ET.sln`、导表、发布、构建确认
- Unity MCP 的通用工具编排细节

遇到这些问题时，分别联动：

- `yiui-mobile-adaptation`
- `et-arch`
- `et-build`
- `unity-mcp-orchestrator`

## 使用场景

- 新增或修改 YIUI `Panel / Item / 子界面 / 弹窗`
- 调整现有 YIUI prefab 结构，并重新生成绑定代码
- 需要判断某个界面是否应该拆成多个页面或区块
- 需要使用 Unity MCP 定位、检查、修改 YIUI 相关 prefab、节点、菜单和生成结果
- 需要处理 `YIUIGen` 自动生成代码、手写 `YIUIComponent`、手写 `YIUISystem` 之间的衔接
- 需要把某个业务包接入 YIUI，并从现有入口打开 UI
- 需要重构已有 YIUI，使资源结构更容易理解、复用和维护

## 第一原则

- **先判断页面职责，再改 prefab**
- **一个 `Panel` 只表达一个页面职责**
- **列表项、子界面、弹窗、独立页面分开建模**
- **改页面结构时，`Builder / prefab / YIUIGen / 手写层 / 入口 helper` 必须视为一个变更单元**
- **页面空态必须保留页面身份，不能让流程层代替页面层**
- **不要手改 `YIUIGen` 自动生成文件**
- **不要用大面积显隐切换模拟多个独立页面**
- **不要把页面主体结构放到运行时代码里动态拼装**
- **退役旧页面或旧入口时，必须连带清理事件绑定、生成衔接、流程 helper 和请求 helper**
- **凡是能在 GUI / Builder / prefab 层确定的结构、字号、按钮尺寸、间距和静态节点位置，必须先落资源层**
- **任何 UI 调整都先做整页 / 整界面职责与布局分析，再进入局部节点修改**
- **用户指出的某个按钮、文本、卡片或详情框，只是问题入口，不代表改动范围只限该节点**
- **遇到重叠、遮挡、不可点、文本压按钮或滚动异常时，默认先检查整页分区、锚点、滚动区、摘要区和 CTA 安全区预算**
- **如果还没完成整页分析，禁止直接通过改单个 `Text / Button / RectTransform` 做止血式修复**
- **底部主操作按钮如果和摘要 / 状态 / 详情正文同屏，必须在 prefab 层显式拆出按钮安全区与文本区，不能让静态文本直接顶到按钮上**
- **运行时代码只允许做数据赋值、显隐、事件绑定，以及真正数量不固定数据项的模板实例化**
- **如果节点已经在 prefab 里存在，禁止在运行时再用 `fontSize / sizeDelta / offset / anchoredPosition` 回写它的静态布局**

## 不负责范围

下面这些不属于本 skill：

- 手机端偏小、按钮难点、字体偏小、页面过密
- `YIUIConstAsset`、`YIUIRoot.prefab`、`CanvasScaler`、设计分辨率
- ET async/await、`EntityRef`、分析器报错
- `dotnet build ET.sln`、导表、发布、最终构建验证
- Unity MCP 的权限、沙箱、授权策略

如果用户请求里同时出现这些内容，先保留本 skill 只负责 YIUI 资源结构与生成衔接，其他部分联动对应 skill。

## 页面职责与资源边界

开始拼 UI 前，先判断当前需求属于哪一类：

- 独立页面
- 页面内部的稳定区块
- 重复列表项
- 临时覆盖交互

默认建模方式：

- **能独立打开**：独立 `Panel`
- **会重复出现**：独立 `Item`
- **只属于当前页面但结构稳定**：子界面或公共区块
- **短时覆盖交互**：弹窗 / Window

错误做法：

- 把多个独立页面都塞进一个 Panel，靠按钮切页和显隐模拟
- 把页面空态直接跳到别的页面
- prefab 里只有一个通用骨架，真正页面结构全靠代码运行时生成
- 为了省绑定字段，把多个独立页面硬塞进同一个“大壳 prefab”

## YIUI 分层规则

### Panel

- 一个 `Panel` 只负责一个明确页面
- 打开 prefab 后应能直接看出它是什么页面
- Panel 名称必须和页面职责一致
- 页面内部可以有空态、锁定态、无数据态，但不能因此丢掉页面身份

### Item

- 重复结构优先抽成 `Item`
- `Item` 默认负责快速识别和快速选择
- `Item` 不承载整页职责

### 子界面 / 公共区块

- 只复用稳定区块，不复用整页职责
- 公共区块不带整条业务流程
- 如果一个区块已经开始承担完整页面语义，应优先拆成独立 `Panel`

### 弹窗

- 弹窗只处理临时交互
- 弹窗不吞并主页面职责

## 页面层与流程层

流程层只负责：

- 决定默认打开哪个页面
- 判断能否进入某个流程
- 在多个页面之间做明确路由

页面层只负责：

- 展示当前页面
- 响应当前页面交互
- 处理当前页面刷新
- 展示当前页面的空态、锁定态、错误态

硬规则：

- **流程路由不能代替页面空态**
- **页面空态必须保留页面身份**

## 运行时创建的边界

可以动态创建：

- 列表项或卡片项的模板实例
- 少量临时按钮或特效挂点
- 数量不固定但结构简单的局部节点

不应该动态创建：

- 页面主框架
- 大块布局骨架
- 整个详情页主体
- 整个配置页主体
- prefab 已存在的静态标题、正文、按钮、页签、容器
- 本应在 Builder 或 prefab 中固定的字体、按钮高度、边距和对齐关系
- 与底部 CTA 共存的静态摘要区、状态区、详情区边界
- 页面主流程已经收缩到单页后仍保留的旧多页兼容显隐壳

判断标准：

- 如果运行时代码已经在创建“整页内容区”，说明资源层拆分通常有问题
- 如果一个页面打开后大部分结构都不能在 prefab 里直观看到，后续维护成本会明显升高
- 如果运行时还在修正静态节点的 `fontSize / sizeDelta / offset / anchoredPosition`，说明资源层职责仍然没有收干净
- 如果静态文本是否压到按钮要靠运行时缩文案、缩字号、改高度来兜底，说明 prefab 的文本区和按钮区边界还没拆清

## 生成代码与手写代码

生成文件：

- 资源结构改完后，先重新生成 YIUI 绑定代码
- 不直接编辑 `*ComponentGen.cs`
- 不直接编辑 `*SystemGen.cs`

手写 `YIUIComponent`：

- 页面私有状态默认写回当前 `Panel` 自己的 `*Component.cs`
- 如果需要拆文件，只拆成当前 `Panel` 自己命名的局部 `partial`
- 只放页面状态数据、选中态、缓存、运行态引用
- 不放业务流程控制
- 不放大段渲染逻辑
- 不把页面私有状态同步继续下沉到跨 `Panel` 的共享 helper

手写 `YIUISystem`：

- 页面刷新、事件响应、列表重建默认写在当前 `Panel` 自己的 `*ComponentSystem.cs`
- 如果需要拆文件，只拆成当前 `Panel` 自己命名的局部 `partial`
- 只放初始化、打开、销毁、页面刷新、列表重建、当前页面交互响应
- Item 点击逻辑放在 Item System
- 列表绑定逻辑集中在拥有者 Panel System
- 不把页面私有渲染、页面私有交互继续下沉到跨 `Panel` 的 `ViewHelper`

共享 helper 的允许边界：

- 只保留真正跨界面的基础能力，例如统一入口路由、纯基础工具、纯共享请求封装
- 不再新增页面私有渲染、页面私有交互、页面私有状态同步到通用 helper
- 如果一个 helper 已经需要识别具体页面节点、具体页面状态或具体页面分支，默认应把逻辑移回对应 `Panel`

## 最小流程

### 1. 先做职责判断

先明确：

- 这次新增的是页面、区块、列表项还是弹窗
- 它的上游入口是什么
- 它的空态是什么
- 它和相邻页面的边界是什么

### 2. 再定义资源结构

先定义：

- `Panel` / `Item` 名称
- 根节点结构
- 需要暴露的绑定节点
- 列表根节点
- 空态节点
- 底部 CTA 安全区
- 与 CTA 分离的摘要区 / 详情区 / 滚动区边界

要求：

- 不要边想边拼
- 不要先堆节点再回头解释职责
- 不要把用户指出的单个问题直接等同于单个节点问题，先确认它是不是整页预算失衡
- 先把标题区、主内容区、摘要区、滚动承载区和 CTA 区的边界盘清楚，再决定是否需要改单个节点
- 只有确认问题确实是局部节点缺陷后，才进入单点修复
- 不要把“按钮下方肯定没事”当成默认前提，必须显式给长文案和按钮区做高度预算

### 3. 用 Unity MCP 或 Builder 改资源

优先：

- 用 Unity MCP 定位 prefab、节点、组件、菜单项
- 复用项目现有 Builder
- 把资源结构表达清楚后再继续下一步
- prefab 缺节点时优先补 Builder / prefab，不要回退成运行时 fallback 拼旧 UI

### 4. 重新生成 YIUI 绑定

检查：

- 生成目录是否更新
- 缺失字段是不是命名、路径或绑定名错误
- 不要拿手改生成文件代替重新生成

### 5. 补手写组件与系统衔接

只在手写层补：

- 页面状态数据
- 列表缓存
- 交互响应
- 页面刷新逻辑

如果手写层已经在替 prefab 补整页结构，说明资源层职责错位。

如果资源层、`YIUIGen`、手写层和 helper 开始互相兜底，通常说明已经偏离了 YIUI 自然生成分层；这类漂移最常见的结果就是编译错误、绑定断链或旧入口残留。

### 6. 收口入口 helper

如果这轮改动改变了页面职责、事件集合或当前有效页面集合，还要同步检查：

- 页面打开入口是否还指向旧页面
- 流程 helper 是否仍保留旧路由
- 请求 helper 是否仍保留只服务旧流程的方法
- 空态或锁定态是否被错误地回退成旧页面跳转

不要让“资源层已删、helper 仍认识旧流程”的状态继续存在。

## 编辑器不可用时的应急说明

- Unity Editor 不可用时，允许做最小静态修复来排查或止血
- 这类修复只能作为应急手段，不能替代正式的 `Builder / prefab / 生成链` 同步
- 编辑器恢复后，必须重新走一次资源同步与生成，确认静态修复没有留下隐性漂移

## 排查清单

遇到问题时，先按下面顺序排：

1. 当前 Panel 是否已经违反单职责
2. 当前内容是否本应拆成独立 `Panel / Item / 子界面 / 弹窗`
3. 当前 prefab 是否在伪装多个页面
4. 页面空态是否被错误地挪给了流程层
5. prefab 路径、节点命名、绑定名是否正确
6. YIUI 生成是否已经重新执行
7. 手写代码是否误改了 `YIUIGen`
8. 是否存在 prefab 节点已删，但 `Gen / System / Helper` 还保留旧事件
9. 是否错误地用手改生成文件代替重新生成
10. 页面私有方法是否被错误地下沉到了跨 `Panel` 的共享 helper

## 协作规则

当任务同时涉及多个方向时：

- 页面结构、生成衔接、手写 UI 逻辑接入：主问题归本 skill
- 手机适配、字号、按钮、`CanvasScaler`、Root 基线：联动 `yiui-mobile-adaptation`
- ET `EntityRef`、`await` 后访问 Entity、分析器问题：联动 `et-arch`
- 构建确认、导表、发布：联动 `et-build`
- Unity 编辑器/Prefab/Menu/Console 的通用 MCP 编排：联动 `unity-mcp-orchestrator`
