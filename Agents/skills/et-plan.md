# et-plan - 版本/周计划管理

这个 skill 负责项目的版本计划和周计划管理，是所有开发任务的唯一来源。

## 使用场景

- 创建或更新版本计划
- 创建或更新周计划
- 添加新任务到计划
- 推进任务状态
- 查看当前计划进度
- 评审任务优先级

## 核心原则

1. **计划是唯一任务来源**：不在计划里的任务，开始制作前必须先补充到计划文档中（自动执行）
2. **开工即入计划**：et-design 门禁检查时若发现任务不在计划中，自动补充到当前活跃周，无需额外确认
2. **状态驱动**：每个任务必须有明确状态，状态只能向前推进
3. **周粒度拆分**：版本计划按周拆分，每周聚焦可交付成果
4. **周日为每周截止日**：周计划周期为周一到周日，**周日必须完成本周总结 + 下周规划**

## 文件位置

- **版本计划**：`Book/08-版本计划/{版本号}版本计划.md`
- **周计划**：`Book/08-版本计划/{版本号}-W{周数}周计划.md`
- **当前活跃周**：通过版本计划中的标记确定

## 任务状态流水线

状态只能按以下顺序向前推进，不允许跳过（特殊情况需用户确认）：

```
未提需求 → 设计中 → 开发中 → 未回归 → 回归通过 → 未人工验收 → 已验收
```

### 状态定义

| 状态 | 含义 | 进入条件 |
|------|------|---------|
| 未提需求 | 任务已记录但需求尚未明确 | 刚加入计划 |
| 设计中 | 正在编写设计文档 | 需求明确，开始设计 |
| 开发中 | 正在编码实现（触发 et-design） | 设计文档已确认 |
| 未回归 | 开发完成，待回归测试 | 代码实现完成 |
| 回归通过 | 回归测试全部通过 | et-test-run 通过 |
| 未人工验收 | 等待用户人工验证 | 回归已通过 |
| 已验收 | 用户确认完成 | 用户确认 |

### 特殊状态

| 状态 | 含义 |
|------|------|
| 阻塞 | 有外部依赖无法推进 |
| 退回 | 验收不通过，需返工（退回到"开发中"） |

## 工作流程

### 创建版本计划

1. 与用户确认版本目标
2. 填写版本计划模板
3. 拆分周计划（每1-4周为一个迭代周期）
4. 创建第一周计划

### 添加任务

1. 用户提出新需求/新任务
2. **强制检查**：任务是否已在计划中
   - 已在 → 更新该任务
   - 不在 → 自动补充到当前活跃周的周计划文档中（填写任务描述、优先级、涉及包、备注），同步更新版本计划变更记录，无需用户额外确认
3. 确定任务优先级（P0/P1/P2）
4. 确定归属周（本周 or 后续周）
5. 更新周计划文档

### 推进任务状态

1. 用户或系统触发状态变更
2. 按流水线顺序推进，不允许跳过
3. 更新周计划文档中的状态列
4. 如果状态变更为"未回归"，提醒用户运行回归测试
5. 如果状态变更为"回归通过"，提醒用户人工验收
6. 状态变更为"已验收"时，在任务行标注完成日期

### 每周切换（周日执行）

**周日是每周截止日，必须完成以下流程**：

1. **本周总结**：
   - 统计本周任务完成情况（完成数/总数）
   - 记录未完成任务及原因
   - 更新上周计划底部的"周总结"区块
   - 更新版本计划中的周计划状态（进行中 → 已完成）
2. **下周规划**：
   - 将未完成任务评估是否带入下周（或降级/取消）
   - 与用户确认下周新任务和优先级
   - 创建下周计划文档
   - 更新版本计划索引表

## 与其他 Skill 的衔接

- **et-design**：任务状态变为"开发中"时，触发 et-design 开始文档驱动开发
- **et-test-run**：任务状态变为"未回归"时，触发回归测试
- **et-build**：开发完成后触发编译验证
