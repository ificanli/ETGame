# `yiui-mobile-adaptation` - 游戏手机 UI 适配硬规则

这个 skill 只做一件事：

- 给 `YIUI` 的手机 UI 适配提供硬规则

它负责：

- 判断手机 UI 为什么显得小
- 判断该改 Root、页面 prefab、Builder 默认值，还是运行时微调
- 约束按钮、字体、间距、卡片、底部操作区的手机基线
- 约束长文案在手机上的可见性

它不负责：

- 页面拆分、`Panel / Item / 子界面` 建模
- YIUI 生成代码、手写组件和手写 System 衔接
- 编译、构建、发布流程
- ET 架构分层、`EntityRef`、分析器问题

遇到这些问题时，分别联动：

- `yiui-unity-mcp`
- `et-build`
- `et-arch`

## 使用场景

- 用户反馈“UI 太小”“按钮太难点”“字体不适合手机”
- 需要做 `YIUI` 手机竖屏适配
- 需要调整 `CanvasScaler`、设计分辨率、Root 缩放基线
- 需要统一按钮、字体、间距、卡片尺寸的手机标准
- 需要判断“该改 Root，还是改页面 prefab / Builder / 运行时微调”

## 第一原则

- **先修正 Root 基线，再修局部按钮和字体**
- **先改 GUI 默认资源，再改业务 prefab / Builder**
- **最后才考虑运行时微调**
- **底部主操作区必须有独立安全高度，摘要 / 状态 / 详情文案不能侵入这个区域**
- **当详情文案和底部 CTA 同屏共存时，优先压缩信息层级或改成滚动承载，不允许继续把文字堆到按钮上方**
- **凡是 GUI 默认资源能解决的问题，严禁修改 `cn.etetet.yiuiframework` 运行时代码**
- **凡是页面 prefab / Builder 能解决的字号、按钮尺寸、间距、容器高度与静态节点位置，禁止在运行时代码里继续回写**
- **运行时代码不能再用 `fontSize / sizeDelta / offset / anchoredPosition` 去重设 prefab 已有静态节点**
- **缺静态节点时先补 Builder / prefab，不允许用运行时临时拼整页或补整块旧布局**

## 不负责范围

下面这些不属于本 skill：

- 页面应该拆成几个 `Panel` 或几个 `Item`
- YIUI prefab 结构设计与代码生成衔接
- `dotnet build ET.sln`、导表、发布
- ET async/await、`EntityRef`、分析器报错

如果请求同时包含这些内容，本 skill 只负责给出适配判断和手机基线，其他部分联动对应 skill。

## 处理顺序

### 1. Root 基线

先查：

- `Assets/GameRes/YIUI/YIUISettings/YIUIConstAsset.txt`
- 业务侧 `YIUIRoot.prefab`
- 模板 `YIUIRoot.prefab`

这层决定：

- 整体是不是都偏小
- 多个 Panel 是否同时偏小
- 为什么只改单页字号，肉眼变化仍然弱

### 2. 页面默认值

再查：

- `Panel.prefab`
- `Item.prefab`
- 包内 UI Builder 默认值

这层决定：

- 某个页面是不是仍然太紧
- 按钮、卡片、输入框是否适合拇指操作

### 3. 运行时微调

只允许用于：

- 真正数量不固定的数据项模板实例化
- 少量临时按钮
- 少量运行时文本
- 状态切换后的局部显隐

如果运行时代码已经在决定整页手机适配基线，说明职责错位。
如果运行时代码仍在给静态按钮、静态标题、静态正文、静态容器回写尺寸和位置，也属于职责错位。

## Root 基线硬规则

- 手机竖屏主场景默认基线优先使用 `1080 x 1920`
- `YIUIConstAsset`、业务侧 `YIUIRoot.prefab`、模板 `YIUIRoot.prefab` 必须同步检查，不能只改一处
- `CanvasScaler` 默认要求 `Scale With Screen Size`
- `referenceResolution` 必须和手机设计基线一致
- 竖屏手机默认不继续沿用横屏基线
- 如果整套 UI 在手机上都显得小，优先怀疑 `referenceResolution` 仍是横屏基线，或 `matchWidthOrHeight` 方向不对
- 底部主操作区必须让位安全区
- 顶部标题和关闭按钮不能压刘海
- 安全区外还要保留一层可见留白

## 尺寸硬规则

### 按钮

- 最小可点击体感不得低于 `44pt / 48dp`
- 在本项目的 `1080 x 1920` 设计基线上，主按钮推荐 `88 - 96`
- 次按钮推荐 `72 - 88`
- 页签按钮推荐 `72 - 84`
- 输入框推荐 `80 - 88`
- 小图标按钮点击区至少等效 `64 x 64`
- 底部主操作优先单独一排
- 两个按钮可以同排
- 三个以上操作优先拆两排或主次分层
- 不要把多个小按钮横向压缩到拇指难点的程度

### 字体

- 页面主标题：`44 - 56`
- 区块标题：`34 - 40`
- 卡片标题：`32 - 38`
- 主按钮文字：`28 - 32`
- 正文：`28 - 32`
- 次级说明：`24 - 28`
- 标签 / 状态字：`22 - 26`
- 占位文案：`24 - 28`
- 正文不要长期低于 `24`
- 可交互按钮文字不要低于 `24`
- 关键信息标题不要低于 `32`
- 如果必须低于这组值，优先反查是不是信息堆太多，而不是继续缩字

### 间距与卡片

- 页面左右边距：`32 - 48`
- 区块之间垂直间距：`24 - 32`
- 卡片内边距：`20 - 28`
- 按钮之间间距：`16 - 24`
- 列表项之间间距：`12 - 20`
- 底部主按钮距离安全区再额外留白：`16 - 24`
- 底部主按钮上方如果还有摘要 / 状态 / 二级说明，正文区和按钮区之间必须再预留一段固定安全高度，不能只靠文本高度“刚好塞下”
- 同一张卡里最多保留三层文本等级：标题、正文、状态
- 承担主操作入口的列表项不要做成薄条
- 如果页面已有独立详情区，列表卡只保留扫读信息
- 如果标题、正文、状态字号都上调，卡片高度和内部 padding 也必须一起上调

## 长文案与信息分层

- **列表区负责扫读，详情区负责细读**
- **列表卡默认只保留名称、分类、状态、单个关键数值**
- **详情区才承载完整说明、详细描述、玩法建议、长文案**
- **顶部说明区只保留流程提示，不重复列表卡和详情区内容**
- **底部按钮上方的摘要区只保留创建结果、当前选择、下一步这种短信息，不承载长说明**
- **文案清晰可见优先于单屏塞满**
- 详情文案较长时，默认优先使用纵向滚动区或等价滚动承载方式
- 详情区出现滚动是合理设计，不是失败信号
- 不要为了“刚好塞下”继续缩小正文字号或压缩行距
- 不要把长文案放在静态定高详情框里依赖 `Overflow` 硬顶
- 如果放大正文、标题、按钮字、卡片字，必须同步检查说明区、摘要区、详情区、列表区、底部按钮区的高度预算
- 不能只改单个 `Text` 的字号
- 创建页、职业选择页、结算确认页这类“长文案 + 主 CTA”同屏页面，默认要先检查是不是应该把正文缩成 3-5 行摘要，把完整说明留给独立详情区或滚动区

## 什么时候改 Root，什么时候改单页

优先改 Root 的信号：

- 多个 Panel 同时偏小
- 改单页字号，肉眼变化仍然弱
- 整体像桌面 UI 缩放后塞进手机

优先改单页 / Builder 的信号：

- 只有某一个页面偏小
- Root 已经正常，但卡片、页签、底部按钮仍然不适合手机
- 某个 Builder 生成出来的 prefab 默认过紧

## 验收标准

每次做完手机适配后，至少确认：

- 关键 CTA 在手机上确实可点，不存在文本或透明层遮挡
- 长文案不会压到列表、详情区或底部主按钮，必要时可以继续下拉查看
- 底部主按钮上方的摘要、状态字、说明字在最长正常文案下仍然不会和按钮重叠
- 列表卡仍然能快速扫读，详情区仍然负责细读
- 这次调整优先落在 GUI 默认资源、Root、页面 prefab 或 Builder，而不是误改 `yiuiframework`
- 进入 Play 后，静态节点的字号、按钮高度和相对位置必须与 prefab / Builder 一致，不能被运行时代码改回旧值

## 协作规则

当 `yiui-unity-mcp` 遇到下面这些任务时，必须联动本 skill：

- 手机 UI 适配
- 按钮太小
- 字体太小
- 页面过密
- `CanvasScaler` / 设计分辨率 / Root 缩放问题

联动后的分工：

- 本 skill 只负责判断问题属于 Root、页面、Builder 还是运行时微调
- 本 skill 只负责给出手机尺寸基线和验收标准
- YIUI 资源结构、生成代码、手写代码衔接仍由 `yiui-unity-mcp` 负责
