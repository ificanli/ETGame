# Equipment 起装商店购买测试设计

## 测试目标

验证起装界面的“商店购买”基础链路已经打通，并且不会破坏现有仓库起装逻辑：

1. 商店物品可以直接购买到固定槽位。
2. 商店物品可以直接购买到背包格子。
3. 财富不足时购买会被拒绝，且不会污染当前起装状态。
4. 购买成功后会正确扣除 `TotalWealth`，并保持“直达目标区域”而不是先进仓库。

## 测试用例清单

### Equipment_LoadoutShopBuyToFixedSlot_Test

验证商店购买到固定槽位：

1. 选择一个 `LoadoutShopVisible=true` 且可装备主/副武器槽的物品。
2. 给玩家足够财富。
3. 发起“购买到主武器槽”请求。
4. 断言购买成功。
5. 断言主武器槽写入目标配置。
6. 断言财富按 `LoadoutBuyPrice` 扣除。
7. 断言该物品没有被额外塞进仓库。

### Equipment_LoadoutShopBuyToBag_Test

验证商店购买到背包格子：

1. 准备一个有效背包尺寸。
2. 选择一个 `LoadoutShopVisible=true` 的商店物品。
3. 发起“购买到背包指定格子”请求。
4. 断言购买成功。
5. 断言背包格子列表新增对应物品。
6. 断言财富正确扣除。

### Equipment_LoadoutShopBuyWealthNotEnough_Test

验证财富不足时不会错误写入状态：

1. 选择一个价格大于 0 的商店物品。
2. 给玩家不足的财富。
3. 发起购买请求。
4. 断言返回“财富不足”错误。
5. 断言固定槽位/背包内容都未变化。
6. 断言财富保持原值。

## 实施顺序

1. 先写失败测试与测试设计文档。
2. 再补协议与服务端购买 Helper。
3. 再补客户端商店/仓库切换与购买交互。
4. 编译并执行目标测试。
5. 做一次现有起装流程回归检查。
